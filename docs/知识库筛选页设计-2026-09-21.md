# 知识库筛选页设计——左右布局 + 分类/标签组合路由（2026-09-21）

> 状态：**设计稿，待拍板后实施**。
> 需求（用户原话）：知识库页面左右布局，左边是分类和标签选择；分类单选、标签多选、可同时生效；**不同筛选组合 = 不同路由页面（SSR），不用单页 AJAX**，满足 SEO。

## 1. 交互模型

```
┌──────────────┬──────────────────────────────┐
│ 筛选面板(左)  │  文章列表(右)                  │
│              │                              │
│ 分类          │  当前筛选态面包屑：             │
│ ▸ SEO与关键词 │  SEO与关键词 × AI工具站 ✕      │
│ ▸ 变现模式    │                              │
│ ▸ …(10个)    │  [文章卡片 × N]                │
│              │  分页 »                       │
│ 标签          │                              │
│ □ 关键词研究  │                              │
│ □ 新词挖掘 ☑  │                              │
│ □ …(20个)    │                              │
└──────────────┴──────────────────────────────┘
```

- **分类=单选**（radio 语义）：选一个换一个；点已选中的取消（回到全部分类）；
- **标签=多选**（checkbox 语义）：**组合语义取 AND**（默认，见 §4 待确认）：选的标签越多，结果越窄；
- 面板上的每一处选择都是**普通 `<a href>` 服务端链接**（无 JS 依赖，爬虫可跟随、无 JS 用户可用）；移动端筛选面板折叠到列表顶部；
- 右侧顶部显示"当前筛选面包屑"（分类 × 标签），带 ✕ 移除项。

## 2. 路由设计（核心）

每个筛选状态一个独立 URL，全部 SSR：

| 筛选态 | URL | 现状 |
|---|---|---|
| 全部文章 | `/posts/` | 已有 |
| 仅分类（单选） | `/c/{cat}` | 已有（保留，不动） |
| **分类 + 标签组合** | `/c/{cat}/t/{t1}+{t2}+{t3}` | **新增** |
| 仅单标签 | `/tags/{key}` | 已有（保留） |
| **仅多标签** | `/tags/{k1}+{k2}` | **新增**（同一 handler 扩展解析 `+`） |

选择这套设计的理由：
- 与现有路由家族**零冲突**：`/c/{path...}` 本就是通配路由，`cat/t/t1+t2` 作为 path 解析即可；`/tags/{key}` 的 key 段天然可含 `+`；
- 分类是互斥维度 → 独占一个路径段；标签是可叠加维度 → 同段内用 `+` 连接，语义清晰且 URL 短；
- 相比查询参数（`?cat=x&tags=a,b`）路径式对 SEO 更友好（用户明确要求"不同路由页面"）。

**规范化规则（防同一组合多 URL 稀释权重）**：
1. 标签段按 key **字典序**排列；乱序访问（`/t/b+a`）→ **301** 到规范序（`/t/a+b`）；
2. 标签去重（重复写 `a+a` → 301 去重形）；
3. 组合上限（如 ≤4 个标签），超限 301 截断到前 4（防 URL 被恶意拼长）；
4. 未知分类/标签 key → 404；
5. canonical 指向**规范序自身**（不含分页 cursor 参数）。

**SEO 收录策略**：
- `/posts/`、`/c/{cat}`、`/tags/{key}`（单标签）→ 照常收录进 sitemap（现状不变）；
- **组合页（`/c/{cat}/t/…`、多标签 `/tags/a+b`）**：默认 **noindex, follow**——组合排列空间大、内容是子集易薄，不进 sitemap、不主动收录；但页面可被抓取（follow 传递权重给文章页），用户可分享。理由：Google 明确对"筛选组合参数页"建议 noindex 或 canonical 到主版本，路径式同理。
  （备选：若希望高价值组合可收录，可对"结果 ≥N 篇"的组合放开索引——待拍板，见 §4）
- 空结果组合 → 200 + noindex + 空态提示（保留筛选面板，用户可继续调整），不 404（404 会打断筛选流）。

## 3. 实现方案

**查询层（改动小）**：`PublicPostQuery.TagsAll` 已存在（AND 语义走 tagPredicates）；分类过滤复用 SameCategoryPosts 的双路径谓词（category_container_id OR container_assets）。新增一个组合读取：`PostsFiltered(categoryPath, tags)` = 现有 Posts 查询 + 分类谓词 + TagsAll。

**路由层**：
- `/c/{path...}` handler：解析 path 为 `cat[/t/tag1+tag2…]`，识别 `/t/` 段进入组合态；乱序/重复/超限 → 301 规范形；
- `/tags/{key}` handler：key 按 `+` split，多标签走 TagsAll；乱序 301。

**渲染层（模板）**：
- `list.tmpl` 重写为左右布局：左栏=FilterPanel（分类列表+计数+当前态、标签云+计数+当前态，全部 `<a>` 链接，href 由模板按"当前分类 × 目标标签集 / 目标分类 × 当前标签集"生成）；右栏=筛选面包屑+卡片列表+分页；
- 面板在 `/posts/`、`/c/…`、`/tags/…` 列表族统一出现（同一个 partial）；
- CSS：桌面双栏（左 220px + 右自适应），<720px 单栏（面板置顶）。

**工作量**：路由解析+读取 ~0.5 天，模板+CSS ~0.5 天，合计约 1 天。
