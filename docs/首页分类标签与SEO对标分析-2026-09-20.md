# 首页 / 分类 / 标签与 SEO 对标分析（2026-09-20）

> 背景：固定阅读样式已定稿。本文回答"同类内容站的首页/分类/标签是怎么设计的、我们的差距在哪、怎么补"。
> 全部现状数据为 2026-09-20 线上实测（itd-site-b095af，792 篇公开文章）。

## 0. 结论摘要

**一句话现状：站点是"792 篇文章的平铺堆"**——无分类、无标签、零内链；首页一排卡片（第 100 篇之后浏览不可达）；SEO 面 JSON-LD 与 OG 全站缺失（主题化重构时丢了旧交付层的结构化数据）。

**对标结论（Ahrefs / Backlinko / 行业惯例三方一致）：**内容站的标准形态是**主题簇（Topic Cluster）**：
1. **分类 = 主题枢纽页**（hub/pillar），可索引、带描述、聚合簇文章，是承接搜索流量的主要落地页；
2. **首页 = 精选 + 分类区块 + 最新**，分类进顶部导航；
3. **标签弱化为辅助**——低质标签页（薄内容/重复）业界普遍 noindex 或并入主题簇，不作为主要组织维度；
4. **内链是核心策略**：枢纽页 ↔ 簇文章双向链接 + 正文上下文链接。

**补齐路径三件事：①建分类数据（源目录零 LLM 映射 + 归档 AI 归类）；②模板升级（首页分类区块/分页/相关文章/JSON-LD/OG）；③内链批量（related 渲染 + AI 正文引用）**。详见 §4-5。

## 2. 对标研究

### 2.1 Ahrefs Blog（SEO 内容站标杆）

- **导航即分类**：博客导航是分类下拉（SEO：关键词研究/页面 SEO/外链/技术/本地/企业级；Marketing：内容/联盟/付费/视频），**分类名=关键词**（搜索词本身）。
- **首页结构**：hero（定位语+信任数据：28.4 万订阅/32.2 万月搜索流量）→ 最新文章流（每卡带 作者/日期/**分类标签**）→ **逐分类区块**（Data & Studies、Marketing 各配 3-6 篇 + "View all"）→ 订阅模块。
- **分类 URL**：`/blog/category/{slug}/` 扁平关键词化；文章可挂多个分类（多对多）。
- 页脚镜像全部分类（全站分类入口 ≥3 处）。

### 2.2 Backlinko（hub/支柱页模式）

- **首页**：1 篇精选 hero + 3 篇重点位 → 邮件订阅 → **逐分类区块**（SEO/外链/内容/联盟，各带 View all）。
- **顶部导航 = 5 大 hub**（AI Search/SEO 基础/内容营销/外链/营销），hub 下挂主题指南；hub 页 URL `/hub/{topic}/`。
- **支柱页-簇（pillar-cluster）**是其明示策略：分类页即枢纽页，聚合同主题文章并**双向内链**；站内有专门讲 Internal Linking 的指南并称之为"任何想提升排名的站的关键"。

### 2.3 分类 vs 标签的行业惯例（2025 共识）

- **分类页：保持索引**——高价值主题落地页，电商语境下分类页自然流量产出可达文章页 3-5 倍；做好分类页自身的内容（描述、子类、排序）即可规避薄内容。
- **标签页：普遍 noindex 或并入主题簇**——标签页天然薄内容/高重复（同样的文章列表换 个词），主流建议是只把标签当文章内交叉链接，不当索引页运营；<3 篇的标签页必 noindex。

**对我们最贴合的形态**：Backlinko 式——分类做枢纽页（我们只有单层需求，`/c/{path}` 即 hub 页），首页做"精选+分类区块+最新"，标签做文章内交叉链接 + 标签聚合页对薄标签 noindex。

## 4. 方案设计

### 4.1 分类体系（核心，数据先行）

**重大便利条件：agentblog 源目录本身就是主题分类**（`D:\code\agentblog\md` 20 个主题文件夹），导入时没带过来。

| 源文件夹 | 篇数 | 建议目标分类 |
|---|---|---|
| 实战战报 | 139 | 实战战报 |
| SEO与关键词 + seo | 77+5 | SEO 与关键词 |
| 变现模式 | 33 | 变现模式 |
| 内容创作 | 30 | 内容创作 |
| 需求挖掘与选品 | 26 | 需求挖掘与选品 |
| 免费推广渠道 + 外链建设 + 付费广告 | 19+18+9 | 推广与外链 |
| 网站建设 | 13 | 网站建设 |
| 案例拆解 | 13 | 案例拆解 |
| 工具与资源 | 13 | 工具与资源 |
| 认知与心理建设+税务合规与风险+收款与跨境财务+数据分析与运营迭代+进阶教程+概念科普 | 9+9+5+4+4+4 | 经营与合规（或拆两个） |
| **merged-archive（扁平混合堆）** | **357** | **AI 按标题归类进上述分类**（标题区分度足够，低成本）；归不进的单列"综合归档" |

落地方式：
1. 建文件夹树（doc-containers，单层 10-11 个）+ 开公开标记（C5 的 category-publication，API 已有）；
2. **435 篇按源目录 1:1 零 LLM 挂载**（脚本：标题→文件夹映射，走 PATCH container_ids 或 category_container_id）；
3. 357 篇归档：标题级 LLM 分类（react runs 批量或离线脚本一次跑完——**只产"标题→分类"映射表人工抽检后再写库**，不让 agent 直接写）；
4. 分类页开 SEO 元数据（slug/公开标题/描述——分类是关键词落地页，slug 用拼音或英文关键词）。

### 4.2 首页与模板升级（固定阅读主题的一部分，不做可编辑）

- **首页**：hero（站名+一句话+搜索）→ **分类区块**（每类 4-6 篇 + 查看全部）→ 精选位（site_featured 表已有）→ 最新 20 + 标签云（ShowTagCloud 开关已有）。纯模板改动（home.tmpl + 数据喂给）。
- **导航**：NavV2 纳入分类（顶导或第二行分类条，Ahrefs 式）。
- **分页**：posts/archive/tag/category 列表加分页（`?page=N` + rel prev/next），sitemap 全量化。
- **`/c/` 根路径**：分类总览页（全部分类的卡片入口，替代空 404）。
- **相关文章**：detail.tmpl 加 related 渲染块（四层降链代码已有）。
- **空态**：tags 空页/搜索无结果给引导文案；tag chips 空容器不渲染。

### 4.3 标签策略

- 数据补齐：AI 从每篇提 2-4 个标签（与 §4.1 的归档分类同一批 LLM 跑，边际成本低）；
- 运营策略：标签只做文章页交叉链接 + 标签聚合页；**<3 篇的标签页 noindex,follow**（模板加判定）；
- 首页标签云放尾部（不抢分类的导航主位）。

### 4.4 内链体系（四层）

1. **分类枢纽 ↔ 文章**：挂分类后自动成立（面包屑 + 列表）；
2. **相关文章**：模板渲染 related（层 2 兜底=同分类，数据就绪即生效）；
3. **正文上下文内链**：AI 批量给每篇插 2-3 个 `chunzhi-asset://` 相关引用（协议/解析/失效链路已上线；走"AI 产映射→人工抽检→批量 PATCH 草稿→重发布"管线，与 F4 同款纪律）；
4. **上下篇**：已有。

### 4.5 SEO 修复清单

1. JSON-LD：详情 Article+BreadcrumbList；列表/分类 ItemList；hub 分类页 WebPage+描述（模板层恢复）；
2. OG/Twitter 卡全站（og:title/description/type/url，og:image 待品牌图）；
3. posts/tags/分类页 meta description 生成规则（分类用其公开描述——分类页自身的关键词落地价值就在这里）;
4. sitemap：lastmod 改用 published_at 语义（不受可见性等运维操作污染）；纳入分类页与标签页；列表页条目补 lastmod；
5. robots：只聚合正式站（按 scope 或显式开关过滤测试站）；
6. canonical：随 DNS-01 证书落地自动生效（无代码）。

## 6. 明确不做

- 可编辑样式/样式编辑（方向已冻结，9-19 拍板）；
- 多级分类树（单层 10-11 类够用，category.tmpl 虽支持层级但不滥用）；
- 标签页做主要组织维度（对标结论：分类为主、标签为辅）；
- 语义嵌入/蒸馏卡上站（不在本轮）。
