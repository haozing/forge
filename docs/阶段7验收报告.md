## 2. E2E-CHAIN 核心链路（C1-C11）

创建团队工作区 → Markdown 笔记（builtin_shot 结构化内容，public 可见）→ 工作区标签（admin 建）→ **真实 DeepSeek** Agent 整理（json_object 端点，202 run）→ 建议落库（summary+tag，词表约束生效）→ 编辑确认（batch accept+单条 reject）→ `ai_assisted` 版本发布（审计六要素齐全）→ **公开站点同 URL 可读**（绑定+渲染投影）→ **检索命中**（真实 embedding 投影）→ **开放 API 消费**（`/api/open/v2/query` 200 hits=1）。

## 3. 本轮发现并修复的缺陷

| 级别 | 缺陷 | 修复 |
| --- | --- | --- |
| P2 | `allowedAgentCapability` 白名单缺 `query.execute`，而 `ForOpenAPI` 强制该能力 → 开放 API 查询**永远 403**（产品闭环断裂） | 白名单补 `query.execute`（internal/admin/agent.go） |
| P2 | 工作区 Agent 应用注册 201 响应**丢失一次性 raw api_key**（handler 用重查结果覆盖 RegisterAgentResult）→ 凭据永远拿不到 | 响应合并 `api_key/api_key_prefix`（frontend_agent_final.go） |
| 环境适配 | 生产 CSRF 门要求写请求带白名单 Origin；测试驱动适配（itd_run.py 自动 Origin 头） | 驱动层 |

## 5. 生产模式行为差异（相对开发模式，均按预期）

- cookie 变 `__Host-agent_session`（脚本手动携带不受 Secure 影响）；
- 写请求 CSRF Origin 门：必须携带白名单 Origin；
- 登录/邀请/公开站点/开放凭据限流全开；
- 配置 fail-fast：补齐前 api/worker 拒绝启动（负例已观测）。

## 6. 结论

**核心验收链路全部打通**（阶段 0-6 的全部产品能力在真实配置下协同工作），性能余量大。上线放行条件：回修 C11-OPEN-ASSET（P2）、接入真实 SMTP 复验邮件投递、部署方确认两个占位配置值。其余检查单项全绿。
