# 公开站点与权限统一 · 浏览器验收测试文档

日期：2026-09-13
依据：《公开站点与权限统一实施规划》《公开站点简化方案 v7（D1–D20）》《成员与 Agent 权限统一方案（A–K）》
测试方式：**真实浏览器黑盒操作**（Playwright 手工脚本化或人工执行），每条用例给出「账号角色 → 浏览器路径 → 操作步骤 → 期望结果 → 底层断言」。
执行原则：按用例编号顺序执行；任何一条失败先修复再继续；所有 403/422 断言用浏览器 DevTools Network 面板核对响应码。

> **v2 审计修订（2026-09-13）**：自审发现 8 类缺口并已补齐——① 存量数据迁移专项（原只测空库，漏掉上线最大风险）；② 角色×功能全组合矩阵；③ 并发与乐观锁（If-Match/会话 apply 冲突）；④ 安全与净化端到端（XSS/防探测/白名单外零泄露）；⑤ 边界值与上限（K4 上限、D8 后缀冲突、D18 幂等与回收）；⑥ 差异面板与 K 系列 UI（K6/K9/K10）；⑦ 多语言补 NULL locale/详情不回退/rss；⑧ 响应式与可访问性抽查。新增 §13–§16，原章节用例扩充约 45 条。

### 1.3 迁移后环境断言（执行迁移后立即核对）

| # | 断言 | 方式 |
|---|------|------|
| E-1 | `system.schema_migrations` 含 0031–0039 全部记录 | `SELECT version FROM system.schema_migrations ORDER BY version` |
| E-2 | `site.site_content_bindings` 是**视图**（pg_class relkind='v'） | `\dv site.site_content_bindings` |
| E-3 | `site_slugs/site_exclusions/site_featured/design_sessions` 四表存在 | `\dt site.*` |
| E-4 | `public_sites` 无 template、model_views 列；有 pages_config、default_locale、enabled_locales、fallback_to_default | `\d site.public_sites` |
| E-5 | `asset_publications` 表存在且触发器 `asset_versions_immutable_update` 仍在 | `\d asset.asset_versions` |

### 1.4 存量数据迁移专项（上线前必做——空库通过 ≠ 存量库通过）

**先在 0030 状态的旧库上构造旧结构数据，再执行 0031–0039，逐项核对回填。**

旧数据准备：同工作区 2 个站点（一旧一新，旧的带绑定/发布/评论/重定向）；旧绑定 3 条（含 display_path 带斜杠的 `posts/a/b`、含 about、含 featured）；model_views 配 2 个模型的白名单；path_redirects 存 1 条历史。

| # | 断言 | 方式 |
|---|------|------|
| M-1 | 多站点清理：每工作区仅剩最早创建的 1 个站点，新站点及依赖（bindings/releases/comments/redirects）级联删除 | `SELECT workspace_id, count(*) FROM site.public_sites GROUP BY workspace_id` |
| M-2 | slug 回填：旧绑定全部迁为 site_slugs 行；`posts/a/b` 取末段 `b`；about 不迁；末段冲突后者跳过（缺口名单人工补 slug） | `SELECT asset_id, slug FROM site.site_slugs` |
| M-3 | path_redirects FK 已解绑且历史行保留 | FK 查询为空；redirects 行数不减少 |
| M-4 | 白名单回填：verify_doc9 当前版本 public_view = 原 model_views 对应条目 | 查 public_view 列 |
| M-5 | `public_sites` 无 template / model_views 列 | `\d site.public_sites` |
| M-6 | 迁移重跑幂等：二次 migrate 输出已应用/no-op，不产生半状态 | 重跑后 E-1 复核 |
| M-7 | **失败回滚验证**：临时改坏 0033 → migrate 报错退出 → 该文件内全部语句回滚、记账未推进 → 还原后重跑成功 | 两次 migrate 输出对比 |

> 教训（真实踩坑）：migrate 镜像**打包迁移文件**——修改宿主 SQL 后必须 `docker compose build migrate` 重建，否则容器内仍是旧文件；FK 约束名不可猜测，用动态 DO 块删除。

## 3. 建站与设计中心（用户旅程 A）

### A-1 建站向导（admin）

1. 设置 → 公开站点 → 「创建站点」；
2. 填名称「测试站」、slug `test-site`；
3. 外观起点：依次点击五张预设卡片（冷静/杂志/极简/暖调/档案），**期望**选中卡片高亮切换；
4. 内容可见性保持「公开」→ 创建；
5. **期望**：创建成功并跳转站点详情；顶部 Tab 为 **概览 / 设计 / 内容清单 / 评论**（四 Tab，无「外观」「首页与导航」「字段展示」「内容绑定」）；
6. 底层：站点行 `pages_config` 为 v2 默认文档（hero+latest）；**无** template 列值。

### A-2 设计 Tab · 语言面板

1. 设计 Tab 顶部「语言」面板：默认语言 `zh`、启用语言 `zh`、回退开关勾选；
2. 改启用语言为 `zh, en` → 保存页面配置；
3. **期望**：保存成功提示；
4. 底层：`enabled_locales = {zh,en}`。

### A-3 设计 Tab · 首页模块编辑器

1. 「首页模块」面板点「选择模块类型」→ 文本块 → 添加模块；
2. 新块标题填「公告」、正文填 Markdown「欢迎阅读」；
3. 再添加「排行/榜单」块：模型 key 填 `verify_doc9`、排序字段 `rating`、方向降序、条数 5；
4. 上下移把「公告」移到最后 → 保存页面配置；
5. **期望**：保存成功；刷新页面后模块顺序与参数保留；
6. **异常路径**：ranked 的 sort_field 改为不存在字段 `nope` → 保存 → **422**，错误信息含「不是该模型已公开的数值字段」；
7. 底层：站点行 pages_config 与界面一致。

### A-3b 差异面板与发布前可见性（K9）

1. A-3 保存页面配置后（**未发布**）→ 打开「版本与发布」页 → 发布差异面板出现变更行；
2. 核对差异行包含「首页栏目/页面配置」，**不含**字段白名单（K9：已下沉模型）；
3. 放弃发布 → 公开站仍为上一 release；重新保存 → 差异仍在（工作配置与线上 release 独立）。

### A-3c about 内置页与上限

1. 自定义页面板中 `about` 行**无删除按钮**（内置保护）；
2. 添加页面至第 20 个后再添加 → **422/前端拦截**（K4 上限 20，服务端权威）；
3. text 块正文填 5001 字 → 保存 **422**；
4. links 块添加第 21 条链接 → **422**。

### A-3d 模块渲染真值（style 类名与块类型）

1. 配置 hero+latest+ranked+categories+links 各一块 → 保存 → 发布；
2. 无痕窗口看首页 DOM：`section.home-block` 按 blocks 顺序出现；块类名含 `block--hero block--width-full` 等（D10 封闭枚举）；
3. categories 块渲染公开分类名与收录计数；links 块渲染外链列表；
4. ranked 块内容顺序 = sort_field 数值降序（构造 rating 9/8/7 三条断言顺序）。

### A-3b2 引用资产选择器（C6 前端）

1. 打开笔记编辑器 → 状态行点「引用资产」；
2. 对话框按标题搜索「沙丘」→ 选择「沙丘2 影评」；
3. **期望**：编辑器光标处插入 `chunzhi-asset://{id}` token；
4. 该笔记发布后（公开站收录），公开详情页正文出现**站内链接**指向被引内容（D13 渲染）；
5. 选择器重复选择同一资产 → 由调用方去重（不重复插入）。

### A-4 设计 Tab · 自定义页

1. 「自定义页」面板 slug 填 `tags` → 添加 → **期望**提示「与保留路由或语言码冲突」；
2. slug 填 `EN`（语言码）→ **期望**同上；
3. slug 填 `guide` → 添加成功，出现 `/p/guide`；
4. 在 guide 页的模块列表添加「文本块」，标题「使用指南」→ 保存；
5. 浏览器访问 `/sites/{site-slug}/p/guide` → **期望**渲染自定义页，标题「使用指南」，含文本内容，`<html lang="zh">`；
6. 访问 `/p/about` → 渲染内置 about；自定义页面板中 about **无删除按钮**；
7. 同工作区第二个编辑者同时在设计 Tab 修改 → 后保存者以**站点行最新 ETag** 为准，先保存者收到 412/冲突提示（If-Match 乐观锁，不允许静默覆盖）。

### A-5 设计 Tab · 导航

1. 导航面板确认自动条目（home、各模型、自定义页）；
2. 隐藏某条目 → 保存 → 访问站点首页 → **期望**该条目从导航消失；
3. 恢复显示 → 保存 → 导航恢复。

### A-6 访客端验证（无痕窗口，不登录）

1. 访问 `/sites/test-site` → 首页按 A-3 配置渲染（文本块「公告」+ 榜单块）；
2. header 出现语言切换条（ZH / EN，A-2 已启用两语言）；
3. 点 EN → URL 变 `/sites/test-site/en`，`<html lang="en">`，head 含 `<link rel="alternate" hreflang="zh|en|x-default">`；
4. DevTools 断言：canonical 自引用、无 template 残留文本。

## 4. 内容收录与发布（用户旅程 B）

### B-1 自动收录（editor）

1. 编辑器新建内容「测试文章 B1」（模型 verify_doc9）→ 确认 → **发布**；
2. 打开站点详情 → 内容清单 Tab → **期望**「测试文章 B1」出现在收录列表，路径自动生成（如 `ce-shi-wen-zhang-b1`）；
3. **期望全程无任何「绑定」操作**。

### B-2 排除与恢复

1. B1 行点「排除」→ 内容从公开站消失（无痕窗口验证 404）；
2. 重新编辑 B1 并发布 → **期望仍不出现**（排除是持久意愿）；
3. 「已排除」区找到 B1 → 恢复 → 公开站重新可见。

### B-3 精选

1. 收录清单对 B1 点「精选」；
2. 首页若配置 featured 模块 → B1 出现精选区。

### B-4 改标题 → slug 切换 + 301（核心回归）

1. 编辑 B1 标题改为「测试文章 B1 修订版」→ 确认 → 发布；
2. **期望**：发布成功；内容清单中 B1 当前路径变为新 slug；
3. 无痕窗口访问**旧 slug** URL → **301** 到新 URL，无 404 窗口；
4. 底层：`site_slugs` 该资产两行（旧 is_current=false、新 true）；`path_redirects` 有 old→new 行；
5. **再次**发布同标题（无变更）→ slug **不变**（D18 幂等守卫）。

### B-5 更新记录块（D16）

1. B1 至此有 ≥2 次发布 → 打开公开详情页 → 底部出现「更新记录」折叠块；
2. 展开可见版本号/日期/版本说明「更新标题」；**无**自动 diff 内容；
3. 详情 head 含 `<html lang="zh">`；仅 1 个 h1。

### B-6b slug 规则真值断言（D4/D7/D8）

构造四条同模型内容发布，核对自动 slug：

| 标题 | 期望 slug |
|------|-----------|
| `Dune Part Two` | `dune-part-two`（英文原词） |
| `沙丘2` | `shaqiu2`（拼音） |
| 第二条 `沙丘2`（同日发布） | `shaqiu2-0913`（时间后缀） |
| `Hello, World! (2026)` | `hello-world-2026`（标点转连字符） |

### B-6b2 幂等与回收（D18）

1. 同标题**再次发布**（无内容变更）→ slug 不变（幂等守卫）；
2. 把标题改回旧值 `沙丘2 影评` → 发布 → **回收历史 slug**（不加新后缀），旧 301 行仍保留；
3. 底层：`site_slugs` 该资产两行（各 is_current 一次），无多余后缀行。

### B-6b3 收录清单分页

1. 该模型批量发布 55 条内容；
2. 收录清单默认 50 条/页，出现翻页；翻到第二页可见后续内容；
3. 公开集合页 `/sections/{model_key}` 按 page_size 分页正常。

### B-6b4 状态机完整性

| 操作 | 公开站表现 |
|------|-----------|
| 发布 → 归档 | 详情 404、收录列表消失、缓存失效（非登录窗口核对） |
| 归档 → 恢复草稿 → 重新发布 | 收录恢复、新 slug/旧 slug 语义正确 |
| 可见性 public→workspace | 立即从公开视图消失（G 步已验） |

### B-6 发布历史边界

1. 新内容首次发布（仅 1 个版本）→ 详情页**无**更新记录块；
2. 尝试在版本表直改 change_note → 被不可变触发器拦截（防线生效）。

## 13. 端到端串联场景（真实用户一天的操作流，按序执行）

**场景 J1「内容运营的一天」（editor 视角，全部 GUI 操作）**：
1. 上午：写一篇新内容「秋季摄影指南」→ 确认 → 发布（截图记录发布时间）；
2. 打开公开站首页 → 新内容出现在最新块（自动收录，无需绑定）；
3. 打开知识库分类树 → 给「摄影教程」分类挂上这篇内容 → 公开分类页出现该内容；
4. 需求变更：改标题为「秋季摄影完全指南」→ 发布 → 收到旧链接访问 → 301 到新地址；
5. 公开详情页底部「更新记录」出现第二条（v2 · 更新标题说明）；
6. 发现一篇低质内容 → 收录清单排除 → 公开集合页消失；
7. 邀请设计师改版：设计师从设计 Tab 选预设「杂志」并微调主色 → 保存 → 发布 → 公开站换肤；
8. 对暗色效果不满意 → 放弃（或回滚上一 release）→ 公开站恢复。

**场景 J2「站长双语上线」（admin 视角）**：
1. 语言面板启用 `zh,en` → 保存 → 发布；
2. 每篇主内容「添加翻译」产出 en 版 → en 版发布；
3. 无痕访问 `/sites/{slug}/en` → 语言切换器出现，内容为英文集合；
4. 详情页切换器点 ZH → 跳回中文 slug；
5. head 核对 hreflang 与 lang 属性。

**场景 J3「Agent 协作」（admin + agent key）**：
1. 给 agent 发 editor 成员行；
2. agent 起 AI 设计会话 → apply_patch 改暗色 → observe 返回截图/结构化观察；
3. admin 审阅设计面板 diff → 应用 → 发布；
4. agent 尝试直接发布内容 → **403**（J：发布必须人做）；
5. 移除 agent 成员行 → agent 全部操作 403。

每个串联场景执行完在 §15 记录表登记，任何一步与期望不符即登记缺陷并阻断后续步骤。
