# 开发实施契约

## 1. 文档定位

本文件将《产品文档.md》和《技术架构.md》转换为可执行的开发约束。产品文档负责用户可见行为，技术架构负责系统边界；本文件负责第一版的命名、接口顺序和验收口径。

如果三份文档出现冲突，以本文件明确的 Agent 授权规则和数据安全规则为准，并必须回写产品文档与技术架构，不能在代码中自行解释。

## 2. 第一版目标

第一版只交付一条完整闭环：

`普通用户登录 → 校验 agent.use → Eino 按 ModelEndpoint 执行 RAG/ReAct → 查询已发布资产 → 返回引用 → 用户点击链接时再次鉴权`

同时支持通用 Markdown 文档、FAQ、经典镜头资源模型、三态发布、附件、CSV 导入、统一查询 API 和 Agent 整理版本。

第一版暂不实现：多企业、多租户、字段级权限、复杂会签、独立消息中间件，以及未确定的高级媒体解析。

社群、论坛、帖子、评论和其他互动内容不属于本系统第一版或后续核心域建设范围。本系统不维护社群实体、互动页面、社群侧审核或互动权限；后续由外部系统独立建设，并通过单独定义的开放 API 契约接入本系统资产。外部系统调用时使用绑定 Agent 用户的 API Key，数据范围仍由该 Agent 用户的实时权限决定。

## 3. 不可改变的授权规则

### 3.1 成员角色与 Agent 技术身份

| 身份 | 作用 | 认证 | 数据权限来源 |
| --- | --- | --- | --- |
| `admin` 管理员 | 管理成员、模型、Agent 应用和全部资产 | 账号密码 + 会话 Cookie | 工作区管理员权限 |
| `editor` 编辑 | 创建、编辑、处理、发布和归档资产 | 账号密码 + 会话 Cookie | 工作区编辑权限 |
| Agent 用户 | 内置 Eino 或受控外部系统使用的技术身份 | 命名 API Key | 独立 `AgentAccessPolicy` 白名单 |

普通成员的 `agent.use` 只决定能否启动某个 `AgentApplication`。Eino Tool 调用不读取成员的资源读取权限，不把成员权限与 Agent 用户权限取交集。

### 3.2 Eino Tool 调用顺序

每次 Eino Tool 调用必须按以下顺序执行：

1. 从 API Key 解析并验证绑定的 Agent 用户。
2. 检查 Agent 用户启用状态、API Key 是否过期或吊销。
3. 使用 `AgentAccessPolicy` 和 `ScopeResolver` 检查 Agent 用户对资源模型及动作的权限。
4. 只查询当前发布指针指向的版本。
5. 检查模型 `agent_tool` 出口是否启用。
6. 返回结果前做对象状态、版本和引用复核，并写入审计。

用户发起问答时只额外执行一次 `agent.use` 校验。答案中的详情、附件和下载链接由用户后续请求重新执行用户自己的权限检查。

## 4. 统一命名

产品界面可以继续使用“资源表”等中文名称，代码和数据库使用以下规范名称：

| 产品概念 | 代码/数据库名称 | 说明 |
| --- | --- | --- |
| 资源表/数据模型 | `ResourceModel` | 定义字段、表单、发布和出口策略 |
| 资源模型版本 | `ResourceModelVersion` | 定义某一时点的字段和策略快照 |
| 资产 | `Asset` | 逻辑资产身份 |
| 资产版本 | `AssetVersion` | 不可变内容快照 |
| 原始输入 | `RawInput` | 永不被高质量版本覆盖的原始数据 |
| 检索投影 | `RetrievalProjection` | 可删除、可重建的索引副本 |
| Agent 应用 | `AgentApplication` | 普通成员可使用的外部 Agent 能力 |
| Agent 会话 | `AgentSession` | 成员选择应用后的短期绑定与审计，不承载数据授权 |
| Agent 任务 | `AgentTask` / `automation.Run` | 后台自动化请求和统一运行 |

`TableVersion`、`RetrievalIndex` 等旧称不得出现在新 API、迁移和代码中；兼容旧文档时只作为术语映射，不建立重复实体。

## 5. 核心状态

`Asset.publication_status`：

`internal | published | archived`

`AssetVersion` 是不可变快照；解析和 Agent 加工状态属于 `ProcessingJob`。编辑已发布资产只创建新的 `internal` 版本；`current_published_version_id` 在新版本显式发布前保持不变。首期不建立独立人工审核任务，质量和处理状态由版本及处理任务记录管理。

模型出口策略在 `ResourceModelVersion.policy` 中使用固定结构：`{"outlets":{"agent_tool":{"enabled":true}}}`。查询必须先检查 `enabled` 和当前发布指针；缺少配置按关闭处理。

## 6. 首个开发迭代顺序

### A. 安全与身份底座

- Go API/Worker 项目骨架和 PostgreSQL 迁移。
- `User`、工作区成员角色、`Session`、`ApiKey`、`AgentApplication`、`AgentAccessPolicy`。
- 简单角色授权、`ScopeResolver`、`policy_revision` 缓存失效和审计。
- 普通成员登录、Agent API Key 认证、`agent.use` 判定。
- 前台启动 Agent 应用：成员会话只校验 `agent.use` 并创建短期 `AgentSession`，不得把成员资源权限作为 Eino Tool 授权输入。

### B. 资产与发布闭环

- `ResourceModel`、`ResourceModelVersion`、字段定义和模型出口策略。
- Markdown 文档、FAQ、经典镜头模型的 CRUD。
- `RawInput`、`Asset`、`AssetVersion`、发布指针和版本历史。
- Agent 资产创建、编辑、处理、发布/归档接口：写入必须使用 `Idempotency-Key`；编辑使用当前工作版本 `If-Match`，编辑永远创建新的不可变 `AssetVersion`。
- 资产普通 `fields` 必须按绑定 `ResourceModelVersion.field_schema` 校验；至少支持 `properties/required` JSON Schema 结构和字段数组结构，未知字段、必填缺失或基础类型不匹配必须拒绝。模型字段声明 `type=content` 时，该字段不作为普通 JSON 值写入 `fields`，必须在同一事务创建/复制 `AssetVersionContentField` 与 `ContentContainerVersion`，并按允许块类型、最大深度、顺序和必填角色校验；未声明 `content` 的字段不得自动块化。
- 附件上传至阿里云 OSS 私有 Bucket，完成大小、类型和 SHA-256 校验后提供受控下载；不得向浏览器或 Eino 返回可绕过实时权限的 OSS 地址。
- Worker 读取不可变源版本，执行前重新校验绑定 Agent 用户的 `read` + `edit` 模型白名单；Eino Graph 结果按 `field_schema` 和内容限制校验后创建新的 `internal` 版本，源版本不被覆盖。
- 新编辑版本和 Agent 候选通过 `parent_version_id` 继承源版本附件；不复制 OSS 对象，状态查询和受控下载沿版本父链检查附件。
- Agent 资产发布/归档使用绑定 Agent 用户自己的 `publish` / `archive` 白名单动作，不读取发起问答成员的资源范围；发布原子切换当前发布指针，并在同一事务投递全文投影重建/删除事件。
- CSV 导入、行级错误、`Idempotency-Key` 和导入审计。

### C. 统一查询 API

- 结构化查询和 PGroonga 全文查询。
- 列表范围过滤、发布指针检查、出口策略检查和对象点校验。
- 详情、引用、附件下载和查询审计。
- OpenAPI 文档及 Eino Tool 请求/响应 schema。

### D. Eino 与 Agent 整理

- Eino Tool 只使用绑定 Agent 用户的授权上下文。
- 结构化查询、全文搜索、详情引用三个最小工具。
- Agent 整理任务生成 `internal` `AssetVersion`，不直接覆盖原始输入；只有显式发布流程才能成为当前发布版本。
- River、Outbox、EventDispatcher、失败重试和幂等回写。

## 7. 最小 API 集合

外部 Agent 接口的机器可读事实来源是 [openapi-open-v1.yaml](D:/code2/agentchunzhi/openapi-open-v1.yaml)，成员会话保护的管理接口事实来源是 [openapi-admin-v1.yaml](D:/code2/agentchunzhi/openapi-admin-v1.yaml)，前台 AgentSession 接口事实来源是 [openapi-frontend-v1.yaml](D:/code2/agentchunzhi/openapi-frontend-v1.yaml)。本节用于说明实现边界；接口路径、参数和响应发生变化时，必须先更新对应 OpenAPI，再同步本节和技术架构。

| API | 用途 | 首版要求 |
| --- | --- | --- |
| `POST /api/sessions` | 普通成员登录 | 创建安全会话 |
| `POST /api/open/assets` | 创建原始资产/internal 版本 | 支持幂等键 |
| `PATCH /api/open/assets/{id}` | 编辑工作版本 | 使用乐观锁 |
| `POST /api/open/assets/{id}/process` | 请求 Agent/解析处理 | 创建 ProcessingJob 和 internal 版本 |
| `POST /api/open/assets/{id}/publish` | 发布 internal 版本 | 原子切换发布指针 |
| `POST /api/open/assets/{id}/archive` | 归档资产 | 从默认查询出口移除 |
| `POST /api/open/query` | 统一 lexical/semantic/hybrid 查询 | 按调用主体过滤，使用签名 search-session cursor |
| `POST /api/open/query` | lexical/semantic/hybrid 查询 | 只返回当前发布版本，并同时检查 AgentAccessPolicy 的 `read`、出口策略和 search-session cursor |
| `GET /api/open/assets/{assetId}/references` | Agent 引用详情 | 按 Agent 用户实时权限、发布状态和 `agent_tool` 出口再次检查 |
| `GET /api/open/attachments/{id}/download` | 受控下载 | 每次请求重新鉴权 |
| `POST /api/open/agent-tasks` / `GET /api/open/agent-tasks/{taskId}` | 创建和查询单资产 `prepare_asset` 整理任务 | Agent API Key + `read` + `edit` 白名单；任务状态、运行尝试和完成错误由 Worker 回写，创建和查询均按 Agent 用户隔离 |
| `POST /api/admin/agent-users` | 创建 Agent 用户、绑定 AgentApplication 并生成一次性 API Key | 成员会话 + `agent.manage`；Key 只在创建响应中返回 |
| `POST /api/admin/agent-users/{agentUserId}/api-keys/rotate` | 撤销 Agent 用户当前有效 Key 并生成替代 Key | 成员会话 + `agent.manage`；旧 Key 立即失效，新 Key 只在轮换响应中返回 |
| `PUT /api/admin/agent-users/{agentUserId}/access-policy` | 替换 Agent 用户对指定资源模型的动作白名单 | 管理员会话；策略变更递增 `policy_revision` 并审计，不继承成员角色 |
| `GET /api/admin/agent-applications` / `GET /api/admin/agent-applications/{applicationId}` | 查看 Agent 应用绑定和密钥状态 | 成员会话 + `agent.manage` + `system:agent-users`；只读返回应用、Agent、ModelEndpoint、能力和 Key 是否有效，不返回密钥 |
| `PATCH /api/admin/agent-applications/{applicationId}/status` | 启用或停用 Agent 应用 | 成员会话 + `agent.manage` + `system:agent-users` + `Idempotency-Key`；停用阻止新会话并使后续会话解析失败，写入审计 |
| `POST /api/agent-applications/{id}/sessions` | 启动 Agent 应用 | 成员会话 + `agent.use`，创建短期会话引用 |
| `POST /api/agent-sessions/{sessionId}/references/validate` | 校验 Agent 答案引用 | 成员会话只定位 AgentSession；引用按绑定 Agent 用户实时 `read` 白名单、发布状态和 `agent_tool` 再次检查 |
| `POST /api/agent-sessions/{sessionId}/chat` | 执行 Agent 问答 | 成员会话只定位 AgentSession；使用应用绑定的 ModelEndpoint 执行 Eino RAG，引用仍按绑定 Agent 用户实时 `read` 白名单再次检查 |
| `POST /api/agent-sessions/{sessionId}/chat/stream` | 流式执行 Agent 问答 | 成员会话只定位 AgentSession；SSE 增量返回，`complete` 事件中的引用按绑定 Agent 用户实时 `read` 白名单再次检查 |

所有外部写入接口都必须支持 `Idempotency-Key`；所有查询和 Agent 调用都必须记录调用主体、发起用户、Agent 应用、结果数量、版本和耗时。

首版 OpenAPI 只覆盖资产、附件、检索、任务和审计相关能力，不提供社群实体或互动接口。外部社群系统的接入需另行提交 API 路径、数据模型、权限映射、幂等和审计契约，不能通过未登记接口或直接访问数据库实现。

## 8. 首版验收场景

1. 成员拥有 `agent.use` 时可以启动 Agent 应用；没有该权限时不能启动。
2. Agent 用户能读取某资源模型，而发起成员不能读取该资源模型时，Eino Tool 仍可返回 Agent 用户权限内的数据；成员点击详情链接时被再次拒绝。
3. Agent 用户被停用、API Key 被吊销或资源权限收紧后，下一次 Eino Tool 调用立即失败或收紧。
4. 已发布资产编辑时，旧发布版本继续可见；新 `internal` 版本显式发布后才切换指针。
5. 同一个导入请求、Agent 回写请求或网络重试不能产生重复资产。
6. 资产下线、权限收紧和过期事件不能让查询 API 返回旧数据或越权数据。
7. 结构化和全文查询在数据库可用时正常服务；不存在未实现的语义查询接口。
8. 外部社群系统只能通过单独定义的开放 API 契约访问本系统资产；调用结果按绑定 Agent 用户实时权限过滤，系统不出现社群实体、互动页面或社群侧审核状态。

## 9. 开工前必须补齐的参数

1. 经典镜头模型字段、枚举、唯一键和质量检查规则。
2. OpenAPI 分页、排序、过滤表达式和 Eino Tool schema。
3. 附件允许类型、单文件大小、总容量和保留期。
4. 日均输入量、并发查询量、审计保存周期和 RPO/RTO。
5. 第一版只验收结构化和全文查询，后续语义能力需另立技术方案和契约。
