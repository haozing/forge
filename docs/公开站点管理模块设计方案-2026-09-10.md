# 公开站点管理模块设计方案

日期：2026-09-10
后端基线：`4bfc335`（2026-09-09）
前端基线：`ac21109`（2026-09-09，`zck-web`）
范围：管理后台的公开站点管理界面（建站、绑内容、预览、发布版本、管评论）

---

## 0. 为什么是现在

后端的公开站点能力是**完整的**：站点 CRUD、内容绑定（改路径自动记 301）、预览、发布版本快照、评论审核、组织级样式预设，加上一整面 SSR HTML 渲染（`/sites/{slug}` + RSS/Sitemap/robots/媒体）。但前端**零实现**——`src/lib/permissions/matrix.ts` 里预留的 `site.read` / `site.manage` 是仅有的痕迹，全仓没有任何站点 API 调用、页面或导航项。

结果：产品主线"灵感 → 整理 → 审核发布 → 检索问答"的最后一跳，内容是发布进知识库了，但**没有一个界面能把它变成一个真实的公开网站**。这份方案把这一跳补上。

| 字段 | 取值 | 校验 |
| --- | --- | --- |
| `slug` | — | `^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$`，全局唯一，**创建后不可改** |
| `display_path` | — | `^[a-z0-9][a-z0-9/-]{0,120}[a-z0-9]$`，站点内唯一 |

| `status` | `active` \| `disabled` | DELETE = 置 disabled |
| `content_type`（绑定槽位） | `article` \| `featured` \| `about` | 描述展示位置，非内容形态 |
| `comments_mode` | `off` \| `moderated` \| `open` | 仅 PATCH 可设，POST 建站不支持 |
| 评论 `status` | `pending` \| `visible` \| `rejected` | 列表筛选另有 `all` |

### 1.4 关键业务规则

- **绑定绑的是 asset，不是 version**。公开读每次都 live 解析 `current_published_version_id`，所以资产重新发布新版本，站点自动跟随，无需改绑定（`internal/site/public.go:635-674`）。
- **写时绑定门**（`internal/site/validate.go:133-144`）：资产须已发布且存在 published 版本、资源模型 active、模型版本 `channels.public_site.enabled=true`、资产可见性在站点 scope 天花板内。任一不满足 → 422 `binding_target_invalid`。
- **改 `display_path` 自动记 301**，并压平重定向链保证一跳（`internal/site/binding.go:436-444,606-624`）；SSR 详情页 404 时命中则 301（`delivery_routes.go:52-61`）。
- **Release 是不可变配置快照**，不是指针。发布 = 把当前工作配置（或历史快照）序列化进新 release，再把 `published_release_id` 拨过去（`release.go:183-206`）。`published_release_id` 为 NULL 时公开渲染回退到工作列（bootstrap 模式）。
- **回滚** = 以历史快照为 base 重发一个新 release（`base_release_id` 非空 → action=`rolled_back`），不破坏历史。
- **站点停用与不存在合并成同一个 404**（防探测，`public_sites.go:61-94`）。
- **缓存失效**：域事件 → `delivery.cache_invalidations` → api 进程 2 秒轮询清进程内 PageCache；TTL 300 秒兜底。失效粒度实际是整站（`internal/delivery/invalidator.go`，`route_prefix` 列无写入方）。

### 1.5 公开面（前端不需要做，但要能在界面里给出链接）

SSR HTML：`/sites/{slug}`、`/posts`、`/posts/{path}`、`/sections/{slug}`、`/tags`、`/tags/{key}`、`/search`、`/rss.xml`、`/sitemap.xml`、`/robots.txt`、`/about/`、`/archive/`、`/media/{attachmentId}`。
JSON API：`/api/public/sites/{slug}` 及其子路径。

## 2. 模块定位与信息架构

**放在工作区上下文**，不是组织级——因为站点是 `workspace_id` 维度的（`public_sites.workspace_id`），样式预设才是组织级。

导航落点：在 `src/config/navigation.ts` 的"团队资产"分组下加一项「公开站点」，路径 `/workspaces/[workspaceId]/sites`，权限 `site.read`。

```
/workspaces/[workspaceId]/sites              站点列表（一个工作区可以有多个站点）
/workspaces/[workspaceId]/sites/[siteId]     站点详情，内部用 Tabs 分四页：
  ├─ 概览      基本信息、状态、公开地址、发布状态

  └─ 评论      审核队列
/workspaces/[workspaceId]/sites/[siteId]/releases   版本历史与发布/回滚
```

预览不单独占一页，作为详情页右侧抽屉或全屏对话框（见 §5.3）。

约定（照抄既有）：
- 路径参数一律 `encodeURIComponent`；
- body 用 snake_case；

## 4. 各页面设计

### 4.1 站点列表

- `GET /sites?limit=50`（cursor 分页，`has_more` + `next_cursor`）。
- 卡片或表格列出：名称、`slug`、状态徽章（`active` 用 `success`、`disabled` 用 `neutral`）、公开地址、内容绑定数量（需额外请求或后端补字段，见 §6.4）、更新时间。
- 主操作「新建站点」→ `CreateSiteDialog`；行内操作「停用/启用」（PATCH `status`）、「复制公开地址」、「打开预览」。
- 空态：`EmptyState` + 新建引导。
- 权限：无 `site.manage`（editor/reviewer/viewer）时隐藏新建/停用按钮，只读。

### 4.2 概览 Tab

- 基本信息表单：`name`、`domain`（带格式校验提示，并明确标注"域名仅登记，暂不参与路由"，见 §6.1）、`default_content_scope`。
- `slug` 只读展示（不可改）。
- 状态区：`active`/`disabled` 徽章 + 停用/启用按钮（停用要二次确认，文案说明"站点将立即对外 404，内容与绑定保留"）。
- 发布状态区：当前 `published_release_id` 指向的版本号 + 发布时间；未发布时提示"站点使用工作配置渲染，尚未发布版本"。
- 公开地址：`/sites/{slug}` 的完整 URL（生产域名 + 路径），可复制、可在新窗口打开。

### 4.3 内容绑定 Tab

这是模块的核心工作量。

- 列表：`display_path`、资产标题、`content_type` 槽位、`section_slug`、`sort_order`、首页/导航开关、`display_published_at`。
- 新增：`BindContentDialog` —— 搜索并选择**已发布**资产（`GET /workspaces/{ws}/assets?publication_status=published`），填 `display_path`、槽位、栏目、排序、首页/导航开关、`display_config`。
  - 前端应提前做与后端一致的前置校验（资产已发布、模型启用），把 422 `binding_target_invalid` 的成因在提交前就挡掉，减少无效请求。
- 编辑：**`asset_id` 不可改**（后端设计：换绑 = 删除后重建以重跑写时门，`binding.go:56-58`）。前端编辑对话框里资产选择器应置灰并提示"更换内容请删除后重新绑定"。
- 改 `display_path`：提示"旧地址会自动 301 到新地址"。
- 删除：二次确认，说明"仅解除站点展示，不影响知识库中的资产"。
- **权限注意**：绑定列表的 GET 也要求 `site.manage`（`sites.go:270`）。所以只有工作区 admin 能进这个 Tab；editor/reviewer/viewer 进来会 403。前端应对：`workspaceCan(role, "site.manage")` 为 false 时**隐藏该 Tab**，而不是渲染后报错。

### 4.4 外观 Tab

- `template`：`blog`/`pro` 下拉。**必须在 UI 里注明"模板当前不影响渲染结果，视觉差异由样式参数决定"**，否则用户会困惑（见 §6.2）。
- `default_content_scope`：下拉，附可见性说明（public 对所有人 / organization 仅组织成员 / workspace 仅本工作区成员）。
- `style_config`：后端是 L1 参数空间 + L2 自定义 CSS（`internal/site/style.go`，内置 preset：`calm|magazine|minimal|warm|archive`）。
  - 首版做法：提供"从预设开始"（读 `GET /api/organization/style-presets`，套用其 `style_config`）+ 若干基础控件（主色、字体、圆角、密度等，具体键以后端 `ParseStyleConfig` 接受的范围为准，落地前需逐键核对 `internal/site/style.go`）。
  - `custom_css`：文本域，提交前提示会被白名单清洗（`SanitizeCSS`）；若整体被清空且原文非空，后端返回 422，前端需给出"CSS 未通过安全校验"的明确提示。
- `comments_mode`：`off`/`moderated`/`open` 单选，附说明。
- 「保存」走 PATCH + `If-Match`；冲突（409）时提示"配置已被他人修改，请刷新后重试"，并自动 refetch。

### 4.5 评论 Tab

- `GET /sites/{siteId}/comments?status=pending|visible|rejected|all`，**无分页，后端硬编码 LIMIT 100**（`comments.go:231`）。前端如实呈现"最多显示 100 条"，不要假装能翻页。
- 列表项：`author_name`、`body`、`display_path`（指向被评论的文章）、时间、状态。
- 操作：通过（PATCH `status=visible`）、拒绝（`status=rejected`）、退回待审（`status=pending`）、删除。
- 默认筛选 `pending`，切 Tab 触发不同 `status` 查询。

### 4.6 版本历史页

- `GET /sites/{siteId}/releases`（cursor 是**纯十进制 revision**，与站点列表的 base64 游标不同，前端不要复用同一套游标解析）。
- 列表：`revision`、`published_by`、`created_at`，可展开看 `config` 摘要（模板/评论模式/是否有自定义 CSS）。
- 操作：「发布当前配置」→ POST 空 body（`base_release_id` 为空，action=`released`）；「回滚到此版本」→ POST `{base_release_id: <该版本 id>}`（action=`rolled_back`）。
- 每次发布/回滚后，站点 `revision` 递增，概览页的发布状态要失效重取。

## 5. 关键技术点

### 5.1 预览：HTML 不是 JSON

`POST /sites/{siteId}/preview` 返回 `text/html`，带 `Cache-Control: no-store` 和 `X-Robots-Tag: noindex, nofollow`（`sites.go:424-428`）。

`apiRequest` 会设置 `Accept: application/json`，虽然它对非 JSON 响应会退化成返回文本（`client.ts:41-50,124-128`），但语义上不干净。**单独写一个 `fetchSitePreview()`**：

```ts
// api/preview.ts
export async function fetchSitePreview(
  workspaceId: string, siteId: string,
  input: { style_config?: unknown; custom_css?: string; page?: "home"|"posts"|"detail"; display_path?: string },
): Promise<string> {
  const response = await fetch(
    buildUrl(`/workspaces/${encodeURIComponent(workspaceId)}/sites/${encodeURIComponent(siteId)}/preview`),
    {
      method: "POST",
      credentials: "include",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(input),
    },
  );
  if (!response.ok) throw new ApiError(response.status, await asErrorPayload(...));
  return response.text();
}
```

### 5.2 预览渲染

用 `iframe` + `srcDoc={html}`，`sandbox="allow-same-origin"`（**不要给 `allow-scripts`**，预览页含搜索壳等 JS island，但不执行更安全），`className` 固定高度 + 设备宽度切换（桌面/移动）。

注意：`srcDoc` 里的相对路径资源（`/static/delivery-*.js`、`/sites/{slug}/media/...`）在 iframe 里会按**当前页面 origin** 解析，而不是站点 origin。首版接受样式/图片可能不完整；若要完整预览，需后端补一个"预览用绝对 URL"模式（列为后端待办，见 §6.3）。

### 5.3 乐观锁

PATCH 站点必须带 `If-Match`。`etag` 就在 Site 响应里（`etag` 字段 = `revision`）。参照组织成员 PATCH 的既有写法（`src/features/organization/api/mutations.ts:17,36`）：带 `If-Match`、**不带** `Idempotency-Key`。但站点 PATCH 的 handler 对幂等键是可选（仅中间件），所以这里按"只带 If-Match"处理，与组织成员一致。

409 处理：提示冲突并 refetch，不自动重试（配置类编辑不该静默覆盖）。

### 5.4 缓存与失效

- 查询默认 `staleTime: 30_000`、`refetchOnWindowFocus: false`（全局默认）。
- 写操作后按既有做法失效：`invalidateQueries({ queryKey: siteKeys.all })` 粗粒度，或精确到 `siteKeys.detail(siteId)`。
- 发布/回滚后同时失效 `siteKeys.detail` 与 `siteKeys.releases(siteId)`。
- 绑定增删改后失效 `siteKeys.bindings(siteId)` 与 `siteKeys.detail(siteId)`。

### 5.5 Mock

`src/features/site/mocks/handlers.ts` 覆盖全部站点端点，并在 `src/mocks/handlers.ts:49-55` 追加 `...siteHandlers`。
- 预览 POST 要返回 `HttpResponse.html("<html>...</html>")`。
- 可选：照抄 workspaces 的 `getScenario/respondToScenario` 支持 `x-msw-scenario`，用于 e2e 的 empty/forbidden 场景。

## 6. 后端缺口与前端应对

这些是设计时**必须知道**的限制，前端要如实处理，不要做无法兑现的 UI。

### 6.1 自定义域名只存不路由

`public_sites.domain` 有列、有格式校验、有全局唯一约束，但**没有任何按 Host 分流的代码**（`0010_site.sql:15-16` 注释："stored for deployment-layer routing only; phase 5 routes by slug"）。所以填了域名，访问仍要走 `/sites/{slug}`。

**前端应对**：字段保留但加显著说明"域名登记用于后续接入，当前公开地址仍是 `/sites/{slug}`"。不要做"域名已生效"的暗示。

### 6.2 模板 `blog`/`pro` 渲染无差异

HTML 模板里没有任何 `Site.Template` 分支（`internal/delivery/templates/` 无命中），该值只出现在 `Chrome.Template` 和首页描述文本里。**前端应对**：要么暂时隐藏模板选择器，要么保留并注明"预留项，当前不影响渲染"。推荐后者 + 明确文案，避免用户反复切换找差异。

### 6.3 预览的相对路径资源

见 §5.2。**后端待办**：`delivery.PreviewInput` 增加"绝对化 base URL"选项，或预览响应内联静态资源。这是让预览真正可用的前提，建议与前端同步立项。

### 6.4 缺少站点级统计与绑定计数

Site 响应没有"绑定数量""评论待审数"等聚合字段。**前端应对**：概览页需要时单独请求 bindings/comments 计数（列表接口的 `has_more` + `items.length` 可近似），或列入后端待办（`GET /sites/{id}/summary`）。

### 6.5 评论列表无分页

见 §4.5。后端硬编码 LIMIT 100，无 cursor。**前端应对**：文案如实说明上限；量大时引导用户按状态筛选。

### 6.6 openapi 契约漂移（不影响对接，影响文档与类型生成）

已确认的漂移（`openapi.yaml` vs 实现）：

| 位置 | 漂移 |
| --- | --- |
| `SiteCreate`（`:5885`） | 缺 `style_config` |
| `SitePatch`（`:5896`） | 缺 `style_config`、`custom_css`、`comments_mode` |
| `PublicSite` schema | 缺 `organization_id`、`custom_css`、`comments_mode`、`published_release_id`、`etag` |
| `SitePreview` | 缺 `generated_at`；POST 请求体缺 `custom_css` |
| `PublicPostContent` | 契约写 `asset_id`，实现是 `id`；缺 `section`、`cover_attachment_id`、`cover_alt` |
| `PublicTagFacets` | 契约 `{key,display_name,count}` vs 实现 `{tag:{...},asset_count}` |
| 列表响应 | 只声明 `items`，实际含 `page:{next_cursor,has_more}` |
| sites PATCH | 契约声明 `Idempotency-Key`，handler 未强制 |

**前端应对**：类型以**真实响应**为准（用 `normalize*` 兜底），不要用 openapi 生成类型。同时建议给后端提一条：契约门目前只比对路径+方法（`openapi_contract_test.go:307`），字段级漂移不会被 CI 捕获。

### 6.7 公开评论的错误映射缺口

`writePublicSiteError` 未覆盖 `ErrInvalidInput`/`ErrForbidden`（`public_sites.go:61-94`），空 body 或超长 body 会落 500 `internal_error` 而非 422。这个面前端不做（公开访客行为），但会影响后续站内评论入口，记录备查。

## 7. 权限矩阵（前端显隐）

| 能力 | admin | editor | reviewer | viewer |
| --- | --- | --- | --- | --- |
| 查看站点列表/详情/预览 | ✅ `site.read` | ✅ | ✅ | ✅ |
| 新建/编辑/停用站点 | ✅ `site.manage` | ❌ | ❌ | ❌ |
| 查看/管理内容绑定 | ✅ | ❌（GET 也需 manage） | ❌ | ❌ |
| 发布/回滚版本 | ✅ | ❌ | ❌ | ❌ |
| 查看评论队列 | ✅ `site.read` | ✅ | ✅ | ✅ |
| 审核/删除评论 | ✅ `site.manage` | ❌ | ❌ | ❌ |

判定方式：`const role = workspaceRoleOf(workspace.data); const canManage = workspaceCan(role, "site.manage")`（`src/lib/permissions/matrix.ts:79-90`）。
注意：`/api/me` 的 `allowed_actions` **只含组织级动作**，工作区动作必须走 `workspaceCan`（`knowledge-base-page.tsx:417-423` 有明确注释）。

## 9. 验收口径

一句话：**在工作区里建一个站点，绑上两篇已发布的知识库文档，预览能打开看到内容，发布一个版本，公开地址 `/sites/{slug}` 能访问；把某篇文档的绑定路径改掉，旧地址 301 到新地址；停用站点后公开地址 404。**

前端门禁按 README 顺序：`typecheck → lint → format:check → test → test:e2e → build`。
