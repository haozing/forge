## 1. 背景与问题

公开站点管理现有六个 Tab（概览 / 内容绑定 / 外观 / 首页与导航 / 字段展示 / 评论），用户反馈内容绑定、首页与导航、字段展示三者认知负担重。根因是架构假设错位：站点按"通用 CMS"设计（1 工作区可开 N 站、内容逐条手工绑定、逐站覆盖配置），而产品现实是**一个知识库一张对外的脸**。本方案将根假设改为 **1 工作区 ↔ 1 站点**，并按"干净重做"原则重构收录、URL、页面配置与展示层。

站点模块尚未面向真实用户发布，现网仅测试数据（经典镜头库 lens-demo-0910 测试站等）——**无兼容包袱**。

## 3. 简化后的总模型

**什么内容上站** —— 三道闸即收录：已发布、可见性 ∈ 站点 scope、模型 active 且开 public_site 通道。站点级只留排除清单与精选标记。

**内容怎么展示** —— 下沉到数据模型高级设置：公开通道开关 + 字段公开白名单（开启向导）+ 集合页参数 + 公开分类挂载规则。

**站点长什么样** —— 站点设置收敛为"设计"：品牌 + 主题版式 + 首页模块 + 自定义页面 + 分类与导航。建站即生成完整可用的默认首页与导航。

**谁来改** —— 用户在"设计"Tab 手工改，或对内部 AI 说一句话；两边改同一份配置，改动停留在工作配置，人审差异后发布（AI 永远不直接发布 release）。

## 4. 内容收录与排除（干净重做）

### 4.1 数据模型：绑定表退役

现 `site.site_content_bindings`（0010 迁移：display_path、content_type、section_slug、sort_order、on_homepage、on_navigation）整表废弃，语义去向：

| 旧语义 | 去向 |
|--------|------|
| display_path（手工填） | `site_slugs` 自动生成（§5） |
| content_type='featured' | `site_featured` 表 |
| content_type='about' | 内置自定义页（slug 固定 `about`） |
| section_slug | 删除（栏目归属跟模型/分类走） |
| sort_order / on_homepage / on_navigation | 删除（模块参数与导航枚举取代） |

新表：

```sql
site.site_slugs   (id, organization_id, site_id, asset_id, slug, is_current, created_at,
                   UNIQUE(site_id, slug), 部分唯一索引(site_id, asset_id) WHERE is_current)
site.site_exclusions (site_id, asset_id, excluded_by, excluded_at, PK(site_id, asset_id))
site.site_featured   (site_id, asset_id, marked_by, marked_at,  PK(site_id, asset_id))
```

- **收录是派生态，不是账本**：收录 = 三道闸查询 LEFT JOIN exclusions / slugs / featured。发布钩子唯一职责 = 分配 slug。
- 交付层读路径 `JOIN site_content_bindings` → `JOIN site_slugs(当前行) + anti-join exclusions`。
- 下线时 slug 行保留（301 语义），三道闸不再命中，页面与媒体自然 404。

### 4.2 收录清单 Tab

已收录（标题 / 模型 / 当前 slug / 精选 / 所属分类，行操作 = 精选、排除、改挂分类）；已排除（恢复）；按模型与分类过滤。

## 5. URL 与 slug

### 5.1 路由规划

| 页面 | 路由 | 说明 |
|------|------|------|
| 首页 | `/sites/{slug}` | 固定 |
| 内容详情 | `/sites/{slug}/posts/{slug}` | 标题自动生成 |
| 集合页（每通道模型） | `/sites/{slug}/sections/{model_key}` | 通道开启自动生成 |
| **分类页（层级）** | `/sites/{slug}/c/{path…}` | 分类树公开化（§8.2），path 为各级分类 slug |
| 自定义页 | `/sites/{slug}/p/{pageSlug}` | `about` 为内置保留页 |
| tags / search / archive / media / rss / sitemap / robots | 不变 | 固定 |
| 多语言前缀 | `/sites/{slug}/{locale}/…` | 非默认语言统一加（§6） |

### 5.2 标题 → slug 规则

1. trim + NFKC + 转小写；
2. **纯 ASCII 标题保持原词**：空格与标点转连字符、压缩、去首尾；超长按词边界截断；
3. 含中文：连续汉字段转无声调拼音（go-pinyin，多音字取常用首音），段内连写、单段截 24；段间连字符；
4. 标题部分截 48（时间后缀不占预算）；
5. 查重 = 当前 slug + 全部历史 slug。冲突：`-MMdd` → 同日 `-MMdd-HHmm` → 序号 `-2`；**例外**：若生成结果等于**本资产自己的**历史 slug，直接回收（该 slug 从历史转回当前），不追加后缀。
6. 空结果回退 `post-{短 id}`。

示例：「Dune Part Two」→ `dune-part-two`；「沙丘2」→ `shaqiu2`；同站第二篇「沙丘2」→ `shaqiu2-0912`。

### 5.3 slug 切换时机与 301（D18）

**问题背景**：若在"标题 PATCH"（草稿阶段）就重算 slug，而线上仍在渲染上一已发布版本，则线上 URL 会立刻 404 或 301 到尚未发布的内容。因此 slug 只跟**已发布标题**走。

**发布事务内原子切换**（资产发布本身就是一个事务里的单条 UPDATE，见 `internal/asset/lifecycle.go:84-85`；写 301 的 `recordPathRedirectTx` 本就接收事务、带 `ON CONFLICT`，`internal/site/binding.go:606-613`）：

1. 以**刚发布的版本**的标题重算 slug；结果与当前 slug 同基（仅时间后缀不同）则**不动**（幂等，防每次发布换 URL）；
2. 不同则同一事务内：旧行 `is_current=false` → 新行 `is_current=true` → 写 `old→new` 301；
3. 提交即生效：新 URL 上线与旧 URL 301 **同时发生，零 404 窗口**。发布事件已触发既有 invalidator（`internal/delivery/invalidator.go`），新页即时渲染；301 逐请求服务、不进页面缓存。

**修复说明**：这不是"复用"现有 `PathRedirect`，而是**重建 301 链路**——现有 `site.path_redirects` 的行由 binding 的 display_path 变更写入、且有外键指向 `site_content_bindings`；绑定表退役后写入源与承载表都要换（详见 `方案审计报告-2026-09-12.md` §1.2/§1.3）。历史 slug 永久保留（SEO 权重 + 防第三方复用）。

**分类 slug 同规则，且允许手工修改**（关键词落地页的核心抓手，改后同样 301；草稿/待生效阶段同样不动线上路径）。

## 6. 多语言：内容到展示的统一模型

### 6.1 内容层

- `asset.assets` 增 `locale text NULL`（BCP-47 主子标签；NULL = 语言无关，数据表记录类默认 NULL 全语言可见）+ `translation_group_id uuid NULL`（组键）。
- 录入端：编辑器"语言"字段 + "添加翻译"（复制为新语言草稿入同组，此后各自独立编辑发布）。
- **创建时 locale 默认值（D20）**：人工新建文档/FAQ 与 AI 起草（react runs / MCP）= **工作区默认语言**（新增工作区设置，默认 `zh`）；数据表记录 = **NULL**（语言无关，全语言可见）；"添加翻译" = 显式目标语言（必填）；表记录派生文档 = 继承记录的 locale。

### 6.2 站点层

`default_locale`（默认 zh）+ `enabled_locales`（默认仅默认语言 = 今天的行为）+ `fallback_to_default`（默认开）。enabled_locales > 1 时 header 自动出现语言切换器。

### 6.3 完整 URL 矩阵（D12）

| 页面 | 默认语言 | 其他语言（以 en 为例） |
|------|----------|------------------------|
| 首页 | `/sites/{slug}` | `/sites/{slug}/en` |
| 详情 | `/sites/{slug}/posts/{slug}` | `/sites/{slug}/en/posts/{译文自己的 slug}` |
| 集合页 | `/sites/{slug}/sections/{model_key}` | `…/en/sections/{model_key}`（按 locale 过滤） |
| 分类页 | `/sites/{slug}/c/{path…}` | `…/en/c/{path…}`（分类名按 locale 渲染，路径段共用默认语言 slug） |
| 自定义页 | `/sites/{slug}/p/{pageSlug}` | `…/en/p/{pageSlug}`；页面 locale=NULL 全语言可见，设了 locale 只在该前缀出现（翻译自定义页 = 再建一页设 locale，P3 组内互链） |
| tags / search / archive / rss | 原样 | 同前缀，内容按 locale 过滤；rss、sitemap 每语言一份 |
| media | `/sites/{slug}/media/{id}` | 无语言概念，不加前缀 |

- locale 取主子标签（zh-CN 归一 zh）。
- **切换器语义**：详情页切换 = 沿 translation_group 跳译文 URL（两语言 slug 不同，禁止简单前缀替换造成 404）；无译文的语言置灰；非详情页 = 替换 locale 前缀。
- 每页输出自引用 canonical + `hreflang` alternates（enabled_locales ∪ `x-default`=默认语言）；列表回退显示的内容标注语言角标；详情不回退（半截外语体验差），只列组内已有语言。
- 评论挂资产，各语言版本独立。

### 6.4 不做的事

字段级翻译；自动机翻（AI"翻译此页"P3，产出草稿走人的发布）；cookie/GeoIP 自动跳转。

## 7. 页面体系、模块目录与布局

### 7.1 页面类型

| 页面 | 配置 | 说明 |
|------|------|------|
| 首页 | 模块列表 | 默认生成：hero → 最新内容 → 每通道模型聚合块 → 顶级分类导航块 |
| 自定义页 | slug + 标题 + 模块列表 | `about` 内置保留 |

| 详情页 | 模型字段白名单驱动 | §9 |

### 7.2 布局与样式三层（对齐现有 StyleEngine 代码）

| 层 | 内容 | 现状 |
|----|------|------|
| ① 站点版式 | 主题预设 + Token（色彩/明暗派生/密度/圆角/阴影/字体/字号/阅读宽）+ `HomeStyle` hero\|plain\|grid\|carousel、`ListStyle` list\|grid\|masonry\|timeline、`CardRatio`、`Sidebar` none\|toc\|tags | **已有**（styleengine.go `LayoutClasses`，模板消费） |
| ② 页面级覆盖 | 每页 `content_width: narrow\|normal\|full`；集合/分类页可覆盖 ListStyle 与条数 | 新增 |
| ③ 模块级样式 | `style` 子对象封闭枚举：`width: contained\|full`、`variant: plain\|card\|emphasis`、`columns: 1..4`、`background: default\|muted` | 新增 |

渲染约定：`block--{type} block--width-{..} block--cols-{..}` 等纯枚举类名（与 LayoutClasses 同思路）；**模块不携带自由 CSS**。位置 = blocks 数组顺序 + width + columns。不做拖拽画布、任意样式覆盖——发布差异可 diff、AI 写入可校验、回滚可信的前提。

### 7.4 "模板（blog/pro）"死字段处置与预设重定位（D15）

**代码事实**：建站向导的"模板"字段（`SITE_TEMPLATE_OPTIONS`: blog/专业 pro）是预留死字段——前端 options.ts 自注"**模板为预留项：切换模板不会改变页面外观**"。真正决定外观的是内置样式预设（`style.go`：calm / magazine / minimal / warm / archive，每个 = 色彩 Token + 衬线/无衬线 + 密度/圆角/阴影 + HomeStyle/ListStyle/CardRatio/Sidebar 组合）与逐键 Token 微调。两者之间**没有任何结构或功能差异**。

处置：

1. **删除 SiteTemplate 死字段**（干净重做，不留预留位）；
2. 预设重定位为**起点而非模板系统**：建站向导展示 5 张内置预设卡片（缩略图即五组版式开关的真实取值），选完即完成全部"外观配置"；
3. **AI 直出**：向导并列"让 AI 搭建"入口——Token + 版式开关全是封闭枚举，正是 AI 的选型题；AI 产出的满意配置可**保存为组织预设**（`site.style_presets` 表 + COPY 语义现成，应用时展开为自包含文档，渲染不依赖预设存活）；
4. 不做"模板市场"概念。

## 8. SEO：内链、分类与权重金字塔（D13/D14）

目标打法（用户表述）：**"分门别类、罗列"**——内容权重聚到小分类，小分类聚到大分类，大分类聚到主关键词（域名/首页）。

### 8.1 现状盘点（已核实的代码事实）

| 能力 | 现状 | 缺口 |
|------|------|------|
| 层级骨架 | `content.containers` 多级目录树已存在（doc_folder 挂文档，parent_id，16 层护栏，container_assets 挂载） | 未上公开面 |
| 罗列页形态 | sections（模型维度）、tags、archive 均为 SSR 列表 | 无分类维度公开页 |
| 内链 | related 详情推荐（fulltext → 同首标签 → 最新 三级降链，fail-open）；图片引用 `chunzhi-media://` 冻结转 `/media/` | **文档间引用无协议、无站内链接转换**（全库仅 chunzhi-media:// 一种协议） |
| 结构化数据 | 详情页 Article + BreadcrumbList（home→section→post 一层）+ og 标记 | 缺 CollectionPage/ItemList；面包屑未接层级分类 |
| SEO 卫生 | canonical、robots.txt 聚合、单 h1、description 三级兜底、rss/sitemap | 分类级标题/描述不可配 |

结论：**骨架约六成现成**（目录树、罗列形态、结构化数据底子、面包屑），缺的是"分类维度上公开面 + 引用内链 + 分类级 SEO 元数据"三件事。

### 8.2 分类树公开化（金字塔骨架）

- folder 子树开**公开标记** → 生成公开分类页 `/c/{path…}`，嵌套路径段 = 各级分类 slug（拼音规则同 §5.2，**可手工改为关键词**，改后 301）；
- 分类页 = 罗列页：子分类区 + 内容卡片分页 + 可编辑 SEO 标题/描述（分类元数据 `public_title/public_description`，默认取标题）+ CollectionPage/ItemList JSON-LD + 多级 BreadcrumbList；
- **资产挂分类**：文档继承其所在 doc_folder（天然现成）；数据表记录/FAQ 通过资产级 `category_container_id`（container 外键）挂载——所有内容类型统一"选分类"交互；
- 三维度各司其职：**模型 = 内容类型**（sections 集合页）、**分类 = 主题层级**（/c/ 金字塔）、**标签 = 自由横切**（tags）；
- **收录分工（D19）**：分类页为主（canonical 指向自身、可索引）；**当某模型存在公开分类挂载时，其集合页自动 `noindex, follow`**（同批内容不留两个可索引入口），站点可在设计里手动强制某集合页索引；无公开分类挂载的模型，集合页正常索引；
- **面包屑（D19）**：分类是面包屑的中间层（`首页 → 分类各级 → 当前页`）；**集合页不进面包屑**（它是类型索引不是层级），消除"两条父子链"；无分类挂载时 `首页 → 当前页`；集合页/标签页/归档页各自为 `首页 → 该页`；
- **保留字（D19）**：自定义页/分类 slug 与 `model_key` 不得取**固定路由段**（`posts`/`sections`/`c`/`p`/`tags`/`search`/`archive`/`about`/`media`/`static`/`rss.xml`/`sitemap.xml`/`robots.txt`）或**全部 ISO 639-1 两字母语言码**（对未来开启的语言同样安全），保存时 422；
- 导航自动枚举追加顶级分类 `category:{id}`；公开子树建议 ≤ 3 层（爬取预算）。

### 8.3 引用协议与站内链接转换（权重流动的管道）

- 新增内容协议 `chunzhi-asset://{asset_id}`（镜像 chunzhi-media 的冻结模式）：编辑器"引用资产"选择器写入，@提及文档/记录；
- 交付端页面构建期转换，**fail-closed 三分支**：
  1. 目标已发布 + current slug + 未排除（同站）→ 内部 `<a href="{公开 URL}">{目标标题}</a>`（dofollow，权重随内链流动）；
  2. 目标在本站但不满足公开条件 → 纯文本标题（无死链、不泄露存在性）；
  3. 跨站/不存在 → 纯文本；
- 转换结果随页面缓存；目标发布态变化经既有 invalidator 失效引用方页面（需建 `chunzhi-asset` 引用反向索引）。

### 8.4 金字塔内链闭环

- **自下而上**：详情页多级面包屑逐级可点；详情底部"所属分类"入口；related 分层调整为 **fulltext → 同分类 → 同首标签 → 最新**（优先把权重导向同主题聚类）；
- **自上而下**：首页 `categories` 模块 → 大分类页罗列子分类 + 内容 → 小分类页罗列内容；分页 canonical 规范化；
- **关键词落地**：分类 slug 手工可改（关键词化）、分类级 SEO 标题/描述、站点主标题/描述（已有）——"用关键词建站 + 站内分门别类罗列"打法在产品内全部有抓手。

### 8.5 内容更新记录：版本链的可信度呈现（D16）

**价值判断**：有用，但价值点要说准——不在于"版本历史页"本身引流，而在于三件事：① **新鲜度信号**（Article 的 `dateModified`——审计确认**已输出**，见 `internal/delivery/service.go:681-686`；D16 真正缺的是版本轨迹块本身）；② **E-E-A-T 可信度**（展示内容在被持续维护，像软件的更新说明）；③ **溯源差异化**（`asset_versions` 已有 `origin` = human/imported/ai_generated/ai_assisted 与 `confirmation_status` = human_confirmed——"AI 起草 · 人工确认"的透明标签是内容 AI 时代稀缺的信任资产）。对文档/知识类内容价值高；对数据表记录价值弱（版本语义是数据修正）。

> **前提依赖（决策 J）**：该叙事成立的前提是 **AI 不能自行发布内容**（见《成员与 Agent 权限统一方案》J：`asset.publish` 为 human_only，agent 只能起草 + 确认）。若 AI 可绕过人直接发布，"人工确认"标签即失真。

**呈现设计（全部在详情页内，不另开索引页）**：

1. **标题区元信息行**：`v3 · 发布于 2026-09-12 · 更新于 2026-09-20`（v = `version_no`，更新时间 = 当前已发布版本 `published_at`）；
2. **详情底部"更新记录"折叠块**（`<details>`/`<summary>` 原生折叠，维持站点 JS-free）：时间倒序列出**已发布版本**（限最近 10 条），每条 = 版本号 + 日期 + **版本说明**（发布时可选填写，像 commit message）+ 溯源标签（origin × confirmation_status 映射为"AI 起草 · 人工确认"等，human 不标）；
3. **JSON-LD**：Article 增加 `dateModified`（当前版本 published_at）；
4. **只有 ≥ 2 个已发布版本才渲染该块**——零配置原则，无开关可关（记录类模型若嫌干扰，未来在模型高级设置加开关，v1 不做）。

**明确不做的（边界）**：

- **不做旧版本内容查看**：每版本的图片授权、canonical、外链都是一套新复杂度；旧内容还可能包含作者已删除的敏感信息；
- **不做自动 diff 展示**：diff 会暴露被删掉的内容，泄密面不可控；**版本说明是作者主动写的公开信息，可控**；
- **不做 /history 独立索引页**：薄页面，SEO 负资产。

**数据与流程改动**：`asset_versions` 加 `change_note text NULL`；发布确认对话框 / `publish_asset`（MCP 工具）增加可选"版本说明"参数（**UI 标注"此说明将公开可见"**）；公开查询仅取 `published_at IS NOT NULL` 的版本元数据（title/slug 取当前版本，历史版本不暴露 URL）。

## 9. 字段展示名（label）与公开白名单（D17/D5）

### 9.1 字段展示名：全链只有机器键的缺口

代码事实：字段定义（`resourcemodel/schema.go` `validateFieldAt`）只有 `key / type / options / default / unique / required`，**没有 label**；key 强制 `^[a-z][a-z0-9_]{1,63}$` 纯机器格式；前端字段编辑器（fields-editor-section.tsx）每行仅"标识/类型/选项/必填"；公开详情页字段表模板直接 `<dt>{{.Key}}</dt>`——访客看到的就是 `shot_size`。内部数据表列表头、记录表单、模型设置、站点字段白名单 chips 同样全是键名。

设计（D17）：

- 字段定义增加 **`label`（展示名）**：1–40 字符的人读名称（如 `shot_size` → `景别`），随 field_schema 走模型版本快照，公开面自然冻结；
- **使用点全链替换**：内部表格列头 / 记录动态表单字段标签 / 模型详情字段列表 / 公开详情字段表 `<dt>` / 公开卡片字段名 / 字段白名单编辑器 chips（展示 `label`，副文本 `key`）/ 公开 JSON `fields` 元素增加 `label` 键：`[{key, label, type, value}]`（契约变更，公开 JSON 消费方同步）；
- **回退规则**：`label` 缺省渲染回退为 key——存量模型不编辑不劣化，编辑器保存时引导补全（label 为空给提示而非阻断）；
- **AI 建模同步**：AI 起草数据表 / agent 建模工具（create_resource_model）的系统提示与工具校验要求每个字段同时产出 `key + label`（中文产品 label 用中文）；
- 枚举选项（options）本身就是人读文本，维持现状不动。

### 9.2 公开白名单下沉到模型（D5）

- `site.model_views` 改名 `public_view` 存到资源模型，随模型 publish 快照进 `resource_model_versions`（与 field_schema 同机制），站点 release 引用模型版本天然冻结；"发布时剪枝 + model_views_pruned 审计"逻辑删除。
- 类型准入表、数量上限（卡 4 / 详 12）不变；白名单存 key、渲染用 label（§9.1）。
- 通道开启向导：打开 public_site → 字段勾选（默认全关 + 按 label 列出可选项）→ 提示剩余两步（改可见性、重发布）。

## 10. AI 改站：设计会话（agent 带眼睛的视觉迭代）

### 10.1 交互形态

用户在设计页点"让 AI 调整站点"，给一句意图（如"换成暗色极简风，首页把数据表放前面"）。agent 进入**设计会话**多轮迭代：`get_config → apply_patch → observe（真实渲染+截图+校验报告）→ 自评（对比度/层级/留白/图文比）→ 再改`，轮数上限 6。**人类全程旁观**：预览面板 iframe 指向会话预览 URL 实时刷新（既有 SSE 通知流推轮次/截图/agent 点评事件）；结束后 agent 给总结与最终 diff，**人一键"应用"**（写回工作配置）→ 发布差异面板 → **人发布**。这就是"agent 在改、人类能看、agent 也能看实时页面"的完整闭环。

### 10.2 三个机制

1. **沙盒会话配置**：会话开始把工作配置 fork 为 `session_config`（design_sessions 表，含 fork 文档/状态/发起 run）；agent 的 `apply_patch` **只写沙盒，全程不写站点行**。"应用"= 人把沙盒一次性写回工作配置。收益：多轮迭代零残留、并发人工编辑不被践踏、diff 干净（一次写回）。
2. **渲染**：`RenderPreview`（已有：member 鉴权、真实 Renderer+StyleEngine、永不缓存、BaseURL 重写支持跨域 iframe）扩展为接受候选 pages_config 整文档——v2 配置即文档，直接换。
3. **观察（眼睛，唯一要新建的重设施）**：无头浏览器截图池（chromedp，forge 容器装 chromium，并发 1–2、超时、`RENDERER_ENABLED` 门控）——渲染 HTML → 桌面 1280 / 移动 390 两档截图（1024px JPEG，每轮 ≤3 张）→ **图像 + 校验报告**（对比度/空块/缺图/文本超长）返回给多模态模型（模型端点配置需标记 vision 能力）。无浏览器环境降级为纯结构化观察（validator + resolved VM），agent 仍可用但没有审美判断。安全面小：只渲染本站 SSR 输出，图片走自家 media 路由，无外部抓取。

### 10.3 工具集与权限

| 工具/动作 | 语义 | 权限 |
|------|------|------|
| `site.get_config` | 读设计配置 + 模块目录 + 公开模型/字段 + 分类树 | site.read（editor 即有） |
| `site.design_session_start` | fork 沙盒会话 | agent 应用成员即可 |
| `site.apply_patch` | 写**沙盒**配置（过模块目录校验） | 同上，不写站点行 |
| `site.observe` | 渲染 + 截图 + 校验报告 | 同上 |
| `site.design_session_finish` | 总结与最终 diff | 同上 |
| （人的动作）应用会话结果 | 沙盒 → 工作配置 | site.design（editor 即可） |
| （人的动作）发布 | 工作配置 → release | site.design（editor 即可） |

**权限说明（D18 关联，与《成员与 Agent 权限统一方案》G 对齐）**：`site.manage` 拆为 `site.design`（站点外观/页面/导航/发布 release，授予 editor）与 `site.lifecycle`（建站/停用/域名/删除，留在 admin）。设计 Tab 与"发布"因此对内容主力 editor 可用；站点生命周期仍 admin 专属。

**agent 全程不写站点行、无 site.manage、无 site.publish**——与《成员与 Agent 权限统一方案》C（agent ≤ editor）天然一致；"直改"若将来要做，走 site.design 细粒度拆权限，不走 admin。此模式是既有 `site.style.suggest`（只读建议、人应用）的泛化升级：从"一次出 2–3 个静态候选"升级为"多轮看页面迭代"。

### 10.4 通道与出口

- **内部 agent（第 1 类）为默认体验**：react runs 通道；模型端点必须多模态。
- **MCP（第 2 类）**：同组工具，截图经 MCP 图像内容返回外部多模态客户端（Claude Desktop 等）；"应用"仍由人。
- 内容写入类 agent 工具（建文章/改记录）维持现有治理与审批语义，与本节设计会话互不影响；**agent 永不发布内容**（`asset.publish` 为 human_only，见成员方案 J）；分类元数据（公开标记/slug/SEO）与精选标记等非视觉操作不走设计会话，仍是人工直接操作。
- 模块目录内嵌工具描述并由 `get_config` 返回；未知类型/非法参数 422 附可用列表（自纠正闭环）。

## 15. 风险

1. **安全语义变化**（发布即上站）：建站向导明示；收录清单全程可见；排除零成本；发布 release 前不对外。
2. **引用失效放大**：一个资产发布需失效所有引用它的页面——反向索引必须建，否则内链要么 stale 要么全站失效；实现时评估 invalidator 粒度。
3. **分类树深度与爬取预算**：公开子树建议 ≤ 3 层；更深层级仍在站内可达（面包屑）但不进导航。
4. **多语言回退的重复内容**：hreflang + 自引用 canonical 消解；单语言（默认态）整条链路不激活。
5. **时间兜底碰撞窗口**：同日同分钟仍撞走序号；可读性收益大于概率损失。
6. **分类 slug 重名边界**：同站全局唯一含历史（同 §5.2），与内容 slug 的保留字/唯一性共用一套规则。

**开放问题已全部落定（D19/D20）**：自定义页上限 20/站点、`ranked` 维持限已公开字段、分类页与集合页收录分工（分类页为主 + 集合页自动 noindex）、面包屑层级、locale 保留字——详见《公开站点与权限统一实施规划-2026-09-12.md》§8。剩余仅观察项（无需现在决策）。
