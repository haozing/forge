## 2. 与方案的实现偏差（及原因）

1. **默认值应用点从两处扩为六处**。方案假设 agent `assets.Create` 走 draft 管道；实际它直建首版本，且 member 创建、人工确认派生、webhook、导入各有独立校验点。按"所有创建版本的入口同一规则"原则全部接入，纯校验路径（AI 候选、建议采纳）不接入。
2. **P2c 未按方案直调 `resourcemodel.Service`**。实施时发现 `Service.validate` 要求 member principal，且 `authz.agentAllowedActions` 白名单明确注释 "never manage models"（`model.manage` 不在 agent 可授动作）。按样式工具先例改走窄服务：`AgentDraftService` 复用包内纯校验与落库 SQL，授权为 agent_access_policies 工作区行显式含 `model.manage`；authz Require 路径与白名单**不变**（member 面守门原样）。产品文档 §8.3 已同步这一边界。
3. **字段字典只进 suggest 系统提示**，不改 `get_schema` 工具描述（避免既有工具描述膨胀）。
