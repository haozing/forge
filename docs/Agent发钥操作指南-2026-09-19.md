# Agent 发钥操作指南（管理员版）

> 2026-09-19。外部 agent 接入（MCP / OpenAPI）的身份、凭证与授权后端 API 已全部就绪；
> 管理台发钥界面列入后续（差距分析 B1 正式面板）。本文是当前的唯一操作路径，全部走真实 API。

## 0. 前置条件

- **组织管理员**会话（`POST /api/public/sessions`，body `{"email","password"}`，请求头必须带
  `Origin: https://101.35.49.253`；响应 Set-Cookie 里的 `agent_session` 即凭证）。
- MCP 端点：`https://forgeapi.qidu.site/mcp`（证书 DNS-01 签发完成前，可用
  `https://101.35.49.253/mcp` 并让客户端忽略自签证书）。

## 1. 创建 Agent 用户并签发 Key（一步完成）

```bash
curl -s -X POST 'https://101.35.49.253/api/admin/agent-users' \
  -H 'Cookie: agent_session=<管理员会话>' \
  -H 'Origin: https://101.35.49.253' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: issue-key-<任意不重复串>' \
  --data-binary @- <<'JSON'
{
  "display_name": "外部检索助手",
  "api_key_name": "默认密钥",
  "application_name": "外部检索助手",
  "model_endpoint_id": "<模型端点 ID，/admin/model-endpoints 列表里取>",
  "runtime_mode": "react",
  "capabilities": ["query.execute", "asset.read", "asset.write", "schema.read", "asset.confirm"]
}
JSON
```

响应 `201`：

```json
{
  "agent_user_id": "…", "agent_application_id": "…",
  "api_key": "ak_…（仅此一次明文返回，立即保存）",
  "api_key_prefix": "ak_…", "capabilities": […]
}
```

要点：
- `capabilities` 白名单 = 工具注册表能力（`asset.read/asset.write/schema.read/…`）+
  `query.execute / reference.read / publication.submit / agent.run / asset.confirm`。
  检索必带 `query.execute`，建稿写链必带 `asset.write`，确认必带 `asset.confirm`。
- `runtime_mode`：`rag` / `react`（不带 workflow_key）或 `workflow`（必带 workflow_key）。
- **发布不在 agent 能力面**（统一方案 J：`asset.publish` human_only，MCP 无发布工具）。
  agent 链路 = 建稿 → 确认，发布由人做。
- `expires_at`（ISO 时间）可选。

## 2. 授予模型级权限（access-policy）

```bash
curl -s -X PUT 'https://101.35.49.253/api/admin/agent-users/<agent_user_id>/access-policy' \
  -H 'Cookie: agent_session=<管理员会话>' -H 'Origin: https://101.35.49.253' \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{ "resource_model_id": "<builtin_document 的模型 ID>", "actions": ["read", "create", "edit", "confirm", "query.execute"], "data_scope": "organization" }
JSON
```

- actions 合法值：`read / create / edit / archive / confirm / query.execute`（`publish` 已按 J 移除）。
- data_scope：`public / organization / workspace`。
- **每个目标模型一条**；漏配的模型对该 agent 不可见（fail-closed）。

## 3. 取接入引导包（自检 + 给接入方）

```bash
curl -s 'https://101.35.49.253/api/admin/agent-users/<agent_user_id>/onboarding' \
  -H 'Cookie: agent_session=<管理员会话>' -H 'Origin: https://101.35.49.253'
```

返回：`base_url`、鉴权格式、`openapi_url`、能力清单、逐模型允许的操作表、`sample_curl`。
key 尚未签发或策略未配时结构仍返回，但操作全为 denied——用它自检授权是否配齐。

## 4. MCP 客户端配置（给接入方）

```json
{
  "mcpServers": {
    "forge": {
      "url": "https://forgeapi.qidu.site/mcp",
      "headers": { "Authorization": "Bearer ak_…" }
    }
  }
}
```

- Cursor 等：`Settings → MCP → Add Server`，类型 Streamable HTTP。
- 证书未就绪期间：用 `https://101.35.49.253/mcp` 并开启"忽略 TLS/自签证书"选项。
- 现有 8 工具：`search_assets / get_asset / list_tables / create_document / insert_record /
  update_document / confirm_asset_version / archive_asset`（无发布工具，by design）。

## 5. 数据面四道闸（检索/建稿不通时按此排查）

1. key `capabilities`（含 `query.execute`、写链 `asset.write`、确认 `asset.confirm`）；
2. access-policy 行（逐模型，actions 短名数组）；
3. 目标模型当前已发布版本 policy 的通道：open_api 检索要开 `channels.open_api`（组织级内置模型默认关），
   agent 通道按需；检索还要 `retrieval.fulltext.enabled=true`；
4. 内容可见性：外部 open 通道只含 `organization/public`（workspace 私有对外部 agent 不可见）。

## 6. 轮换 / 吊销

```bash
POST /api/admin/agent-users/<id>/api-keys/rotate     # body {"name","expires_at"?} → 新 key 明文一次性返回
POST /api/admin/agent-users/<id>/api-keys/revoke-all # 吊销全部 key
```

注意事项（差距分析 B2）：**key 的 capabilities 在签发时冻结**，之后改应用配置不回写已发 key——
调整能力后需 rotate 一次。参考现存测试 key：`ak_mcp_test_0a1b2c3d4e`（agent 用户 dc5ea7f2）。
