### 1.2 唯一的断点

**资源模型的管理界面不存在**，导致：

1. 内置模型（`builtin_document/note/faq/shot`）的 `public_site` 通道默认关闭，而 published 版本**不允许直接 PATCH policy**（实测 409 `resource_model_conflict`），必须"新建版本 → 改策略 → validate → publish"；
2. 这条路径后端 API 齐全，前端无入口 → 只能手搓 SQL/curl；
3. 连带影响：**结构化字段展示白名单（本周刚做）拿不到可用模型**——因为开不了通道 → 绑不了带字段的内容 → 白名单没东西可展示。

> **审计勘误（2026-09-10 当日修复）**：初稿称"这条路径后端 API 齐全"——审计发现对**内置模型**不成立：`Versions`/`CreateVersion`/`ValidateVersion`/`PublishVersion`/`RetireVersion` 原先直接以空 workspace 调工作区策略，对组织管理员也 403；且 publish 的收尾 UPDATE 有空串转 uuid 的 500。两处均已修复（`requireModelAction` 统一授权：工作区模型走工作区策略，内置模型读=组织成员、写=组织管理员；publish UPDATE 改 `workspace_id IS NOT DISTINCT FROM NULLIF($4,'')::uuid`），回归测试 `TestVersionLifecycleRoutesThroughOrgAwareAuth` 锁定。**本地已实测内置模型全生命周期走通。**

> 一句话：**"建模型 → 录记录 → 开通道 → 绑站点 → 配白名单 → 渲染结构化字段"这条链，缺的是第一环的前端。**

## 三、后端接口契约（已实现，前端直接对接）

> 以下全部取自 `internal/httpapi/resource_models.go` 与 `internal/resourcemodel/service.go`。

### 3.1 路由清单

| 方法 | 路径 | 说明 | 前置 |
| --- | --- | --- | --- |
| GET | `/api/workspaces/{workspaceId}/resource-models` | 列表（含内置模型） | `model.read` |
| POST | `/api/workspaces/{workspaceId}/resource-models` | 新建（含初始版本） | `model.manage` + Idempotency-Key |
| GET | `/api/resource-models/{id}` | 单模型（含 current_version） | `model.read` |
| PATCH | `/api/resource-models/{id}` | 改 name/description/status | `model.manage` + Idempotency |
| GET | `/api/resource-models/{id}/versions` | 版本列表 | `model.read` |
| POST | `/api/resource-models/{id}/versions` | 新建 draft 版本 | `model.manage` + Idempotency |
| GET | `/api/resource-model-versions/{versionId}` | 单版本 | `model.read` |
| PATCH | `/api/resource-model-versions/{versionId}` | 改 schema/policy（**仅 draft**） | `model.manage` + Idempotency + If-Match(schema_checksum) |
| POST | `/api/resource-model-versions/{versionId}/validate` | 校验 | `model.manage` + Idempotency |
| POST | `/api/resource-model-versions/{versionId}/publish` | 发布（成为 current） | `model.manage` + Idempotency |
| POST | `/api/resource-model-versions/{versionId}/retire` | 退役 | `model.manage` + Idempotency |

**内置模型注意**：`workspace_id` 为 NULL（组织级共享，全员可读）。授权矩阵（经 `requireModelAction`，2026-09-10 修复）：读（列表/单查/版本读）= 组织成员；写（元数据 PATCH/版本创建/校验/发布/退役）= **组织管理员**（`organization_role='admin'`）。前端按 `/api/me` 的 `organization_role` 显隐写入口。

### 3.2 请求体

**POST /resource-models**
```jsonc
{
  "model_key": "equipment_catalog",     // 组织内唯一
  "name": "设备资料库",
  "description": "",
  "content_kind": "record",             // record | document | faq | note
  "initial_version": {
    "field_schema": { "additional_properties": false, "fields": [ /* 见 3.3 */ ] },
    "form_schema":  { "sections": [ /* 表单布局，可为空数组 */ ] },
    "list_schema":  { "columns": ["..."], "filters": ["..."] },
    "policy":       { /* 见 3.4 */ }
  }
}
```

**PATCH /resource-model-versions/{id}**（指针语义，只传要改的段）
```jsonc
{ "field_schema": {...}, "form_schema": {...}, "list_schema": {...}, "policy": {...} }
```

### 3.3 field_schema（字段定义）

```jsonc
{
  "additional_properties": false,
  "fields": [
    { "key": "shot_size", "type": "enum",
      "options": [{ "value": "远景" }, { "value": "特写" }] },
    { "key": "lens_mm",   "type": "integer" },
    { "key": "shoot_date","type": "date" },
    { "key": "spec",      "type": "object", "properties": { /* 嵌套 */ } }
  ]
}
```

- **key 规则**：`^[a-z][a-z0-9_]{1,63}$`（2–64 位，小写字母开头）；保留字不可用（完整清单见上，**写侧** schema 校验拒绝）
- **允许的 type（13 种，2026-09-02 收敛后）**：
  `string` `text` `markdown` `integer` `number` `boolean` `date` `datetime` `enum` `multiselect` `object` `array` `asset_reference`
- `options` 仅 `enum`/`multiselect` 允许；`properties` 仅 `object` 允许；`default`/`unique` 可选
- **站点字段展示白名单的准入**（`internal/site/modelview.go`）：详情页允许 8 种标量（string/integer/number/boolean/date/datetime/enum/multiselect）；**卡片只允许 6 种（同时排除 multiselect 和 datetime）**——前端字段设计器应据此给出提示
- 保留字共 **14 个**（写侧 schema 校验拒绝，`schema.go:20-24`）：id/title/markdown/summary/tags/source/attachments/created_at/updated_at/created_by/updated_by/visibility/publication_status
- **array 类型必须有 `items` 定义**（`schema.go:364-371`）；object 必须有 `properties`（但不拒绝其他类型携带）

### 3.4 policy（出口策略）——本阶段核心

```jsonc
{
  "visibility": { "default": "workspace", "allowed": ["workspace", "organization", "public"] },
  "channels": {
    "workspace":   { "enabled": true },
    "public_site": { "enabled": false },              // ← 开这个，结构化数据才能进站点
    "agent":       { "enabled": true, "content_scope": "published" },
    "open_api":    { "enabled": false, "content_scope": "published" }
  },
  "retrieval": { "structured": { "enabled": true }, "fulltext": { "enabled": true }, "semantic": { "enabled": true } },
  "publishing": {
    "mode": "direct",                  // direct | approval
    "required_fields": ["title"],
    "require_clean_attachments": false,
    "require_human_confirmation": false
  }
}
```

校验规则（`PolicyFromJSON`，不符合即 422 `model_schema_invalid`；**field_schema 的 issue 逐条列出，policy 只产生一条聚合 issue** `policy/invalid_policy`）：
- 顶层键白名单：只允许 `visibility`/`channels`/`retrieval`/`publishing`，**多传任何键即 422**（legacy 形状显式拒绝，`schema.go:109-115`）
- `channels` 键只允许 `workspace`/`public_site`/`agent`/`open_api`
- `content_scope` 只允许 `published`/`all`，且**仅** `agent`/`open_api` 可带（**`public_site` 带 `content_scope` 会被拒**）
- `retrieval` 键只允许 `structured`/`fulltext`/`semantic`
- `visibility.default` 为空时跳过 default∈allowed 检查；非空时必须 ∈ `allowed`，值域 `workspace`/`organization`/`public`
- `publishing.mode` ∈ `direct`/`approval`

### 3.5 版本状态机

```
draft ──validate──→ (仍 draft，写 validated_at)
  │  ▲                 │
  │  └── PATCH ────────┘（PATCH 会清空 validated_at，必须重新 validate）
  │
  └──publish（仅要求 validated_at 非空）──→ published（成为 current_version_id，
                                            并自动退役旧的 published 版本）
                                              │
                                              └──retire（仅 published 可退役）──→ retired
                                                    （模型 current_version_id 置 NULL、
                                                     模型 status 打回 'draft'——模型失活，
                                                     站点白名单与绑定门立即失效）
```

- **PATCH 只对 draft 版本生效**（published 版本改任何东西都 409）
- **publish 只检查 `validated_at` 非空**（`service.go:467-473`）——不查 status、不重校 schema；因此**必须先 validate**，而 PATCH 会清空 validated_at
- validate 只对 draft 生效（`service.go:444`）
- 改配置的标准动作（顺序不可变）：`POST versions`（复制当前版本内容为新 draft）→ `PATCH` → **`validate`** → `publish`

### 4.2 关键交互

**字段设计器**（A2/A3）
- 行式编辑：`key` + `type` 下拉 + `options`（enum/multiselect 时展开）+ `default` + 删除；支持拖拽排序
- 前端预校验（对齐后端）：key 正则、保留字、options 非空、object 的 properties
- 实时提示与站点白名单的关系（哪些类型能进站点卡片/详情）
- 编辑既有模型时，**删除字段要显著警告**（影响已录入记录；后端会拒绝仍被引用的字段吗？→ 实测：不做引用检查，仅 schema 层校验，前端要提示"删除字段会导致已有记录该字段不可见"）

**出口策略编辑器**（A4，本阶段核心）
- 四个通道开关 + 各通道说明（workspace=工作区内可见，public_site=可绑定到公开站点，agent=Agent 可检索，open_api=开放 API 可读）
- `agent`/`open_api` 开启时露出 `content_scope`（published / all）
- 可见性默认值 + 允许集合（多选，default 必须在 allowed 内）
- 发布规则：mode 单选（direct/approval，附差异说明）+ required_fields + 两个开关
- **保存即"新建版本→PATCH→validate→publish"一键串行**（因为 published 不可改；漏 validate 会 409），并在 UI 上明确告知"此次修改会生成新版本 vN、旧版本自动退役"

**版本页**（A3）
- 版本列表（version_no / status / checksum / validated_at / published_at）
- 操作：以当前版本为基底新建 draft、validate（展示逐条 issue）、publish（二次确认）、retire

### 4.3 与既有页面的联动

- **数据表**（tables）：模型列表新建后自动出现在侧栏「数据表」分组（该分组已按"有字段的模型"过滤）；模型字段变更后需失效 `tablesKeys.all`
- **站点字段展示**（site fields tab）：模型发布后，白名单候选自动更新（该 Tab 已从 `resource-models` 取 field_schema）；模型版本升级后需失效 `siteKeys` 相关查询

## 七、验收标准

### 7.1 本阶段（P1-A）

1. 在工作区新建一个模型（如 `equipment`，含 enum/integer/date 字段），能通过动态表单录入记录（复用 tables 页）
2. 打开该模型的 `public_site` 通道（走"新建版本→改策略→发布"），站点绑定该记录时**不再 422**（此前通道关闭会被绑定门拒绝）
3. 站点「字段展示」Tab 能为该模型勾选字段，发布版本后**站点详情页渲染出结构化字段表、卡片渲染出字段 meta**
4. 改模型字段（增/删）→ 新建版本 → 发布 → 白名单自动剪枝（`model_views_pruned` 审计非零）
5. 全部前端门禁 + 后端 `go test ./...` 绿

**端到端一句话**：新建"设备资料库"模型 → 录入一条设备记录 → 开 public_site 通道 → 绑定到站点 → 勾选字段白名单 → 站点页面看到设备的结构化参数。

### 7.2 对照产品文档的验收（§18）

本阶段补齐 §18.4（专业资源模型可动态录入）的模型定义侧；§18.11/12/13（同一资产多出口、站点渲染、统一查询）已在当前版本通过。

## 九、P1-B 站点内容集合按资源模型过滤（2026-09-10 完成）

### 9.1 契约

`homepage_config.sections[]` 新增可选字段 `model_key`：

```json
{"sections": [
  {"type": "latest", "title": "最新发布", "limit": 6},
  {"type": "latest", "title": "镜头精选", "model_key": "builtin_shot", "limit": 4},
  {"type": "column", "title": "镜头新闻", "section_slug": "news", "model_key": "builtin_shot"}
]}
```

- `model_key` 留空 = 不限模型（旧行为）。
- `model_key` 按**资源模型 key**（`model.resource_models.model_key`）匹配，不是 uuid；内置模型（`workspace_id IS NULL`）与工作区模型都可命中。
- 公开输出 `PublicSection.model_key` 回显该栏目的模型收窄，前端/模板可用。

### 9.2 后端实现

- `internal/site/public.go`：`PublicSectionConfig.ModelKey`/`PublicSection.ModelKey`；`ParseHomepageConfig` 解析 `model_key`；`modelIDByKey` 把 key 解析成模型 id；`latestPosts`（latest 栏目，走结构化查询）与 `boundVersionRows`（featured/column，走绑定目录）都接受 `model_key` 收窄；`Section(slug, sectionSlug, modelKey, limit)` 也支持 `?model_key=` 查询参数（`/api/public/sites/{slug}/sections/{sectionSlug}` 与 SSR `/sites/{slug}/sections/{sectionSlug}`）。
- **fail-closed**：未知 `model_key` 返回空集，绝不回退成全模型（避免输错 key 泄漏其它模型内容）。
- `internal/delivery/viewmodel.go`：`SectionVM.ModelKey`；`ResolveHome` 把带 `model_key` 的 latest/featured 栏目**独立成块**（标题回退用 model_key），不再并入通用「最新/精选」桶；column 的归并键改为 `section_slug + ":" + model_key`，同一 slug 服务两个模型不会互相覆盖。

### 9.3 前端实现
