# 会话笔记单一事实源整改设计方案

- 日期：2026-09-03
- 状态：已实施；**2026-09-04 修订：对话与笔记解耦**（见文末修订记录）
- 前提：开发期，不考虑兼容与旧数据；测试/本地库允许 reset 重建；共享部署环境在实施窗口内重建
- 关联：产品文档-v2 §5.4（版本/草稿/发布）、《关于录入页面的思考》（主干+派生）、7b1dd02（派生收割+引用收敛轮）

> **2026-09-04 修订（对话与笔记解耦）**：产品拍板"对话不进笔记"——笔记是用户从会话中主动收录/亲手撰写的成文稿，不是聊天全量抄录。本方案中"消息天然是块""聊天追加消息块"的前提作废，落地改为：
>
> 1. **消息只进 `message_blocks`**（不可变聊天记录），不再写 `block_placements`、不推进容器 revision 与 draft epoch——发消息不弄脏笔记。
> 2. 笔记树内容只有两个入口：手动块（`POST note/blocks` kind+content）；**存入笔记**（同端点传 `from_block_revision_id`，把某条消息正文复制为 quote/paragraph 摘录块，溯源记 `block_revisions.props`）。不做 Agent 直写笔记的工具——AI 总结仍是一轮普通对话，由用户点"存入笔记"收录。
> 3. 渲染器删除消息分支（`## User/## Assistant`）与转录分支：冻结产物天然是干净成文，无对话体。
> 4. 派生注入从"assistant 消息块"改为笔记树的**quote 引用块**（派生会话的对话从空白开始）；派生选块范围=源笔记树（origin 统一为 `note`）。
> 5. 语音转录同样只作消息记录（role=transcription），不进树，想留点"存入笔记"。
> 6. 无 DDL；`NoteBlock` 视图去掉 role/status；入库（commit）与发布链路不变——冻结的从来只是笔记树。
> 7. 前端两区域（我的灵感/知识库）为同一组列表 API 的组合视图，后端零改动（资产列表排除规则不变）。

## 1. 背景与根因

一次"保存笔记"在现状下写三处正文：note 容器块、`asset_versions.markdown`、`asset_drafts.markdown`。根因是两套内容模型并存：0007 的块运行时（容器+块）与 0005 的资产体系（markdown 字符串）在 `note_bindings`（`note_container_id`、`note_asset_id` 双 NOT NULL）握手，靠 `SyncNote` 手工抿齐。由此产生：

1. 两个事实源互搏：`PATCH /draft` 直改 markdown 绕过块（块树陈旧→派生选块选到旧文）；sync 全量重建转录覆盖草稿（手动编辑丢失）。
2. 块模型未兑现：sync 把整篇 markdown 塞进单个"段落块"，块寻址名存实亡。
3. 冗余机制：聊天与笔记双容器、每条消息全量复制 placements 造新容器版本（存储 O(n²)）。
4. 已实测的缺陷：会话可见性默认 `private` 违反 DB CHECK 直接 500；finalize 收割**源**笔记而非派生会话成果；删除会话遗留孤儿笔记资产。

## 2. 目标模型（已确认契约）

```
会话 1 ─── 1 笔记文档（容器+块树 = 唯一可编辑事实源，消息天然是块）
                 │ 每次固化（commit）冻结一次
                 ▼
             版本₁ ── markdown₁ + 块树快照   （不可变）
             版本₂ ── markdown₂ + 块树快照   （不可变）
                 ↑ 发布指针最多指向一个
```

- **块树是唯一事实源**：聊天追加消息块；手动编辑=增删改块（改内容=新块修订）。
- **markdown 是冻结产物**：固化时由块树渲染，存进不可变版本；每个版本一份（1:N）；永不被独立编辑。
- **草稿 markdown 退役**：`asset_drafts.markdown` 对会话笔记不再写入；"草稿"=活块树本身，drafts 行只留元数据（title/fields/revision 乐观锁）。
- **两类资产**：`root_container_id IS NOT NULL` ⇒ 会话孕育型（块树事实源，commit=渲染冻结）；否则表单录入型（现状不变：markdown 草稿直编辑）。派生收割产物=表单录入型文档（builtin_document）。
- 下游零改动：检索投影、站点 SSR/RSS、RAG、开放 API、审核全部只消费版本 markdown。

## 3. 数据模型变更（迁移 0019，破坏性，不搬数据）

| 变更 | 内容 |
| --- | --- |
| `content.containers` | 加 `asset_id uuid NOT NULL UNIQUE REFERENCES asset.assets(id)`（文档容器归属资产）、`revision bigint NOT NULL DEFAULT 1`（活树乐观锁，每次块编辑 +1）；`kind` 收敛为 `'note'`；删除 `current_version_id` |
| `content.block_placements` | `container_version_id` → `container_id`（挂活树）；保留 `position`（append 递增，允许空洞，排序 `ORDER BY position`）；去掉版本复制语义 |
| `content.container_versions` | **整表删除**（冻结快照改存 `asset_versions.blocks`） |
| `content.conversations` | 删 `container_id`（chat 容器概念消失）；`visibility` CHECK 改 `(workspace, organization, public)` |
| `content.note_bindings` | 删 `note_container_id`、`last_synced_message_sequence`；仅剩 `conversation_id PK → note_asset_id` |
| `asset.asset_versions` | 加 `blocks jsonb`（冻结时的块树快照，**引用式**：`[{position, block_revision_id, kind, role}]`，不内嵌正文——回放/溯源时 JOIN 不可变的 block_revisions 取内容，版本本体只增一份引用列表 + 渲染 markdown） |
| `asset.asset_drafts` | 列不变；会话笔记不写 `markdown`/`summary`（恒 NULL），`revision` 对齐容器 `revision` 供 commit 乐观锁复用 |

块类型沿用现有枚举（paragraph/heading/list/code/quote/message/qa/callout…），`message_blocks` 表原样保留（角色、序号、状态等消息元数据），块的角色在渲染/选块时经 `block_revision_id` JOIN 获得。

## 4. 核心链路重设计

**创建会话**：同事务建笔记资产 + 文档容器（挂资产）+ note_binding；不再建 chat 容器。可见性默认 `workspace`，接受三档。

**发消息**（`AppendMessage`/`persistChatMessage` 重写）：插 block+block_revision → placement 追加到文档容器尾部（容器行 `FOR UPDATE` 串行化，`revision+1`）→ message_blocks 行。不再复制 placements、不再产容器版本。聊天历史照旧读 `message_blocks`（零改动）。

**笔记手动编辑**（新块编辑面）：
- 追加块：`POST {kind, content}`（paragraph/heading/quote/code…）
- 修改块：`PATCH {blockId, content}` → 产生新块修订，placement 改指新修订
- 删除块：`DELETE {blockId}` → 移除 placement
- 全部要求 `If-Match: 容器 revision` + 幂等键；消息块同样可改可删（改=新修订，不破坏原始消息记录）

**固化（保存/提交更新版本）**：`POST /api/assets/{noteAssetId}/commit-draft` 语义按类型分叉——
- 会话笔记：锁容器 → `RenderMarkdown(活树)` → `CreateVersionTx(markdown=渲染产物, blocks=树快照)` → drafts 行 `revision/committed_revision` 对齐；
- 表单资产：现状 `commitDraftTx` 逻辑不变。
乐观锁统一为 `draft_revision`（会话笔记下即容器 revision），API 形状不变，前端按钮无感。

**读笔记**：`GET /api/conversations/{id}/note` 返回 `current_version{markdown,...}` + `draft_markdown`（活树实时渲染，只读投影）+ `dirty`（容器 revision ≠ 最新版本 blocks 快照指纹）。

**发布**：完全不变（confirm → publish / publication-requests），发布吃版本 markdown。

**派生**：选块范围=文档容器 placements（消息块+手动块统一一张查询，JOIN message_blocks 带 role）；`context_policy` 注入开场消息=追加消息块到派生会话的文档容器（同一条 AppendMessage 通路）。`derivation_sources`/`context_snapshot` 语义不变。

**派生收割（finalize）重设计**：
1. 内容源反转为**派生会话（target）的活块树**；目标树为空 → 409 `derivation_target_empty`。
2. 收割即定格：先对 target 笔记自动固化一个版本（收割的不可变出处），再以其渲染 markdown 建新文档资产（**builtin_document**，组织内置，缺失则 409）。收割成功后 target 会话默认自动归档（`auto_archive` 参数，默认 true），让"新思考"列表自然收敛。
3. 血缘：新文档 `derived_from` → target 笔记资产（物化到其 current working version，citation 带 derivation_id）；merge 处置=将 target 渲染 markdown append 到指定资产。
4. 乐观锁参数收敛：删 `expected_source_asset_version_id`、`expected_container_version_id`；merge 保留目标资产版本校验。

**删除会话（含 cascade）**：容器/placements/blocks/message_blocks/派生行照删；**笔记资产软删**（`deleted_at=now`，状态置 archived）并追加 `asset.archived` 事件（复用现有检索投影+站点缓存失效扇出）；收割产出的文档资产不受影响。

**note/sync 消亡**：端点删除，游标列删除。"保存"= commit（固化），产品语义不变。

## 6. 渲染器规范（`internal/content` 新增 render.go）

- 输入：活树 placements JOIN 块修订（+message_blocks.role）；输出：确定性的 markdown 字符串。
- 映射：message(user) → `## User` 段；message(assistant) → `## Assistant` 段；paragraph → 原文；heading/list/code/quote/callout → 对应 markdown 语法；qa → `## Q / ## A`；attachment/link → 链接行。
- 过滤：`status != completed` 的消息块不进冻结产物（pending/failed 留在活树）。
- **确定性要求**：同一块树必须渲染出相同 markdown（排序、空行、标题层级固定）；golden 用例进单测。
- 版本回放：`asset_versions.blocks` 快照可重放渲染，用于校验与溯源展示。

## 7. 实施阶段与验收

**阶段 A（缺陷修复，可先行独立提交）**：可见性三档+默认 workspace；finalize 收割对象反转（旧模型下读 target working version）；删除会话软删笔记资产+事件扇出。验收：ITV 补三条断言（无 visibility 创建 201；finalize 内容来自派生会话；删除后资产列表查不到笔记）。

**阶段 B（模型核心）**：迁移 0019；创建会话不再建 chat 容器；AppendMessage 重写（直写活树）；`note/sync` 删除；commit 分叉+渲染器；GET note live 渲染；`asset_versions.blocks` 快照。验收：长会话（100 消息）placements 恒为 100 行（无版本复制）；两次 commit 产出可 diff 的两个版本；draft PATCH 对会话笔记 422。

**阶段 C（编辑面+派生联动）**：块 CRUD 四接口；派生选块统一查询；finalize 自动固化+builtin_document；乐观锁收敛。验收：块编辑→commit 渲染包含编辑；派生选"手动块"；finalize 文档模型=builtin_document 且血缘指向派生笔记。

**阶段 D（契约与联调）**：openapi/yxt 契约/前端接入指南更新；ITV 套件改写；给前端的迁移说明（笔记编辑器从 markdown textarea → 块列表；"保存"→commit；sync 移除）。

## 8. 数据量与膨胀治理

版本**不是**每次编辑产生：改块只换活树上的块修订（增量行），版本仅在用户显式固化（保存/收割）时产生，频率由用户控制。对比现状反而是净减：消息 placements 从 O(n²)（每条消息复制全量）降到 O(n)；sync"整篇 markdown × N 次"变成按需固化；编辑从整篇草稿覆盖变成单块修订。

量级估算：100 条消息 × 1KB ≈ 100KB/篇；一天固化 20 次约 2MB 版本 markdown；块修订每改一次只多一行该块内容。块快照引用化后版本额外成本仅为引用列表。

后手（MVP 不做，量级到了再启用）：未发布版本保留最近 N 个（已发布版本全保）；被引用次数为零的历史块修订 GC。

## 9. 前端信息架构映射（新思考 / 我的文档 / 共享文档）

三层漏斗，全部用既有列表端点的筛选组合，无新概念：

| 前端视图 | 后端映射 | 说明 |
| --- | --- | --- |
| 新思考列表 | `GET /api/workspaces/{ws}/conversations`（已默认排除 archived） | 一个思考一个文档（1:1 笔记），"未整理"= active 且未收割 |
| 我的文档 | `GET /api/workspaces/{ws}/assets?created_by=me` | 个人视图（产品文档 v2：不形成独立所有权），筛选参数已支持 |
| 共享文档 | `GET /api/workspaces/{ws}/assets?visibility=organization`（或 workspace） | 可见性档位即共享范围，筛选参数已支持 |

**文档库排除规则**：资产列表默认排除"挂着 note_binding 且未发布"的会话笔记资产（列表 SQL 一个反 JOIN）——会话笔记只有两个出口进文档库：收割（产物天然无 binding）或自身发布。否则每聊一个天文档库就多一篇噪音。

整理动作闭环：新思考 →（派生收割 finalize，auto_archive 默认归档会话）或（直接发布笔记）→ 文档库出现对应文档；会话从新思考列表消失。

## 10. 风险与待确认点

1. **前端笔记编辑器形态**：块列表编辑 vs 只读+追加（MVP 建议后者，改动最小；全块编辑器可后置）。
2. **渲染格式即契约**：消息块渲染为 `## User/## Assistant` 沿用现状格式，前端若要更漂亮的对话体渲染，应在前端读 blocks 快照自渲染，而非改后端格式。
3. **conversation.title 与笔记 title 流向**：冻结时 `draft.title`（若手动设置）优先，否则取会话标题（现状行为保留）。
4. **共享环境重建窗口**：0019 破坏性 DDL 不搬数据，需要在部署侧配合 reset；与 forgeapi 解封/收尾窗口协调。
