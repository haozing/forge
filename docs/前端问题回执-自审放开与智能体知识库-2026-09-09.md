# 前端问题回执:自审放开 + 智能体知识库选择 — 2026-09-09

针对前端反馈的两个问题,后端已核查完毕,其中一个已修复并部署生产,另一个需要产品先拍板。本回执给出结论、接口行为变化和需要前端配合的事项。

---

## 问题 4:"提交文档不能自审,管理员应该可以审核" — ✅ 已修复并部署

### 结论

原规则是"**谁提交的请求,谁不能批准**,管理员也不例外"(无条件拦截,与角色无关,报 409 `self_approval_not_allowed`)。这是阶段 0 的防"自批"设计,不是 bug,但对小团队(尤其只有一个管理员时)确实会把流程卡死。

**2026-09-09 已按产品拍板放开**(commit `c60c162`,已部署生产 101.35.49.253 并实测):

### 现在的审批规则(以 `publication-requests` 为例)

| 谁 | 审批别人的提交 | 审批自己的提交 |
|---|---|---|
| workspace **admin / reviewer** | ✅(一直如此) | ✅ **本次放开** |
| workspace editor / viewer | ❌ 403 `action_not_allowed`(无权限,一直如此) | ❌ 同左 |
| Agent(智能体主体) | ❌ 永远不能审批(本次未改) | ❌ 同左 |

### 接口行为变化

- 接口不变:`POST /api/workspaces/{ws}/publication-requests/{rid}/approve|reject`(幂等键、Origin 等照旧)
- **`self_approval_not_allowed`(409) 错误码永久退役**:前端如有针对该码的分支/文案/枚举,请删除;该码不会再出现
- 生产已实测:管理员自批自己的请求 → `200`,`status=approved`,`submitted_by == decided_by`

### ⚠️ 别混淆:另一条"确认"没有变

之前截图里说的"**直接发布模式(通用文档)发布前必须勾'我核对过了'**"是**另一套机制,这次没有动**:

- 通用文档(builtin_document,direct 模式):发布前必须先调 `POST /api/asset-versions/{vid}/confirm`,否则 `POST /api/assets/{id}/publish` 返回 **409 `human_confirmation_required`**。**前端仍需补这个确认步骤**(发布按钮前加确认,或发布失败 409 后引导确认再重发)
- 笔记(builtin_note,approval 模式):链路不变 `commit-draft → confirm → 送审 → 有人批准`;变化的只是"批准人现在可以是提交者本人(前提是其有 admin/reviewer 角色)"
- 一句话:**普通文档靠"自己签字"(confirm),笔记靠"别人审批"(approve);自审放开只影响后者**

## 问题 5:"创建智能体能选知识库,列表不返回、编辑不能改" — 🔍 核查完毕,需产品拍板

### 核查结论(重要)

**后端从 API 契约到数据库全链路都不存在"智能体↔知识库"字段**,具体:

1. 创建接口 `POST /api/workspaces/{ws}/agent-applications` 的请求体**没有** `knowledge_base_ids` 之类字段,且后端开启 `DisallowUnknownFields`——前端真把该字段发过来会直接 **422 `validation_failed`**,创建都会失败。现在"创建能成功",说明前端的多选**只存在页面本地状态,从未提交到后端**
2. 数据库没有 `agent_knowledge_bases` 关联表;列表/详情响应里没有(也无法有)该字段
3. **现状的真实行为**:创建智能体时,后端自动把它授权到**所在工作区的默认资源模型**(`read + query.execute`,写入 `agent_access_policies`)。也就是说:页面上选什么都没用,智能体实际可见范围 = 工作区默认知识库

### 请前端现阶段配合

- 智能体表单里的知识库选择器请**先隐藏或置灰**(避免用户误以为选择生效)
- **不要**向创建/更新接口提交知识库字段(会 422)
- 编辑表单不要留知识库入口(接口不收,改不了)

### 修复需要产品先拍板(拍板后后端排期)

| 方向 | 做法 | 代价 |
|---|---|---|
| A. 轻量 | 后端列表/详情回读 `agent_access_policies` 回显知识范围;前端编辑走既有 `PUT /api/admin/agent-users/{agentUserId}/access-policy`(单资源模型替换) | 零迁移,但语义是"单知识库"而非多选 |
| B. 完整 | 新增"智能体↔知识库集合"存储与字段,create/update/list 全链支持多选 | 加表加列,契约三处同步,工期长 |

拍板前请前端先把选择器下线,避免继续积累无效交互。
