# React 前端接入指南（agentchunzhi v2 后端）

> 面向独立 React 前端工程。权威契约 = 仓库根 `openapi.yaml`（87 路径，与路由双向对照测试锁定），可 codegen。路由已收敛为**单一无版本树**：成员面 `/api`、匿名/公开面 `/api/public`、开放 API 面 `/api/open`、运维面 `/api/admin`——URL 中不再有 `v2`/`frontend`/`v1` 前缀。

## 1. 环境两模式

| | 本地联调（development） | 准生产（production + TLS） |
| --- | --- | --- |
| 栈搭建 | compose 起栈 + 空库重建（见 §6） | 同左 + TLS 反代（caddy/nginx） |
| cookie | `agent_session`（http 可用） | `__Host-agent_session`（**Secure：浏览器仅 HTTPS 携带**，必须反代 TLS） |
| CSRF Origin 门 | 不启用 | **`/api/` 与 `/api/public/` 的写请求必须携带白名单 Origin**（精确匹配，否则 403 `origin_not_allowed`）：把前端 origin 加入后端 `MEMBER_ALLOWED_ORIGINS`（逗号分隔，禁 `*`，改动需重启 api）。注意覆盖面：`/api/admin/*`、`/api/open/*` 的写请求**不受**此门保护（open 面走 Bearer 凭据鉴权）。浏览器跨域请求自动带 Origin；fetch 同源 POST 也会带 |
| 邮件 | capture 模式（不实发；token 走创建响应/日志获取） | SMTP 真实投递 |
| 语义检索 | 需配置 `RETRIEVAL_EMBEDDING_*`（可指向 mock `tmp_qa/mock_tls.py`） | 真实凭据（`.env` 已含） |
| 生产校验 | 宽松 | fail-fast 全量（缺键拒绝启动） |

**联调拓扑（必读）**：后端**不返回任何 CORS 头**（无 `Access-Control-*`），且会话 cookie 为 `SameSite=Lax`——浏览器跨域直连（如 Vite `:5173` → API `:8080`）会被双重拦死。前端页面必须与 API **同源**：

- 本地联调：Vite dev server 代理 `/api` 到 `:8080`（配置见 §6）；
- 准生产：TLS 反代把前端静态资源与 `/api` 挂同一域名（cookie `__Host-` 前缀同时要求 HTTPS）。

限流在 development 模式同样生效，共两层，联调前务必知晓（避免把限流误报为登录 bug）：

- **进程内桶**（可经 `.env.test` 调高 `RATE_LIMIT_LOGIN_PER_MIN` / `RATE_LIMIT_LOGIN_IP_PER_MIN`）：登录 10/min/账号+IP、IP 兜底 90/min——429 带 `Retry-After`。
- **数据库侧锁定**（策略固定，不可配置）：**同一账号 15 分钟内密码错 5 次 → 锁 15 分钟**；同 IP 15 分钟 30 次登录尝试；密码重置 3 次/小时、邀请发送 20 次/15 分钟。锁定期间即使密码正确也拒绝。解锁=等 15 分钟、换测试账号，或清 `security.auth_rate_limits` 表对应行。建议联调期准备多个测试账号轮换。

## 2. 核心约定（前后端契约硬规则）

1. **错误信封**：`{"error": {"code", "message"}, "request_id"}`。断言=状态码+code 双校验。全表见 `internal/httpapi/api_handlers.go` serviceError。
2. **幂等键**：`openapi.yaml` 契约端点（身份、组织/工作区、标签、审核流、建议流、站点、检索、开放 API）的 POST/PATCH/PUT/DELETE 必带 `Idempotency-Key`（≥16 字符）：缺失 428、<16 或非法 422、同 key 异体 409；同 key 同体重放返回缓存响应 + `Idempotency-Replayed: true`。从旧 frontend 面并入的域（资产列表/创建、附件、容器、会话聊天、自动化、导入导出、通知、模型管理）当前是 opt-in：不带键不报 428，服务端自动生成代理键（无跨请求重放去重），需要强幂等的写操作建议自行带上。公开面、GET、`/query`、`/references/validate`、`/stream` 一律例外。
3. **乐观锁**：草稿/标签/组织/偏好 PATCH 必带 `If-Match: "<revision>"`（GET 响应的 ETag）：缺失 428、过期 412、`*` 通配=存在即可。
4. **分页**：keyset——响应 `{items, next_cursor, has_more}`，下页带 `cursor`；cursor 是不透明串，不可自行构造，篡改 422。
5. **标签**：写入用 `tag_ids`（整组替换语义：省略=保留，数组可空=清空）；查询用 `tags_any/tags_all/tags_none`（normalized key）。归档标签不可挂载（409）。
6. **Agent 建议**：`pending→accepted/rejected`，accept 才写 draft（一次请求 revision 恰 +1；批量同轮也只 +1）；commit 后 `materialized_version_id` 回填。Agent 不能自确认/自审批。

## 3. 关键接口地图（React 页面 → 端点）

| 页面 | 端点 |
| --- | --- |
| 登录/会话 | POST `/api/public/sessions`；GET `/api/sessions`；DELETE `/api/sessions/current` |
| 邀请入职 | POST `/api/public/organization-invitations/resolve` / `accept` |
| 标签管理 | `/api/workspaces/{ws}/tags` CRUD + `/tag-facets` |
| 资产创作 | `/api/workspaces/{ws}/assets`（创建）；`/api/assets/{id}/draft`（GET/PATCH 草稿）；`/commit-draft`、`/asset-versions/{id}/confirm`、`/publish`、`/archive`、`/restore` |
| Agent 整理 | POST `/api/workspaces/{ws}/assets/{id}/prepare` → GET `.../suggestions` → POST `.../suggestions/{kind}/{id}/accept|reject` → `accept-batch`；处理结果 GET `.../processing-results` |
| 站点管理 | `/api/workspaces/{ws}/sites` CRUD + `/bindings` + `/preview`（JSON 快照） |
| 公开站点 | `/api/public/sites/{slug}`、`/posts`、`/posts/{displayPath}`、`/sections/{s}`、`/tags`、`/tags/{key}`、`/search`（匿名可读；成员会话按分档扩可见带） |
| 检索 | POST `/api/workspaces/{ws}/query`、`/api/organization/query`（mode: structured/fulltext/semantic/hybrid；citation opaque） |
| 审计 | GET `/api/query-executions`（两级）等 |
| 附件 | POST `/api/asset-versions/{versionId}/attachments`；GET `/api/attachments/{id}`（状态）、`/link`、`/download`、`/presigned-download` |
| SSE 流 | GET `/api/conversations/{id}/chat/stream`、`/api/agent-sessions/{id}/chat/stream`（打字机式聊天）；GET `/api/workspaces/{ws}/notifications/stream`（通知推送）。均为 `text/event-stream`，带 `heartbeat` 保活事件，重连用 `Last-Event-ID` |

公开站点**正文 markdown 为原文**：渲染与净化（rehype-sanitize/DOMPurify + CSP）是前端责任；后端已做白名单字段投影，摘要已安全截断。

## 4. 已知行为与限制（避免误报缺陷）

1. **真实 LLM 方差**：Agent 整理的建议数量随内容波动（短/无 schema 内容可能 0 建议）——前端按"可能为空"设计空态；准备→轮询 suggestions 的建议超时建议 ≥90s（真实 LLM 延迟）。
2. **公开站点检索时延**：发布→投影 ready→site search 命中，真实 embedding 下有分钟级窗口（列表/详情即时）。前端搜索空态应提示"索引中"。
3. **开放 API 创建资产**：组织级模型（builtin_*）**必须带 `workspace_id`**，否则 422；workspace 专属模型自动落绑定工作区。201 响应的 `asset.workspace_id` 会回带实际落位工作区，可直接断言。webhook 推送同语义（组织级模型要求显式 workspace）。
4. **开放发布门禁**：Agent/开放凭据发布未确认版本 → 409 `human_confirmation_required`（预期行为；人工 confirm 后可发布）。
5. 限流：登录 10/min（同 IP 同账号）、公开站点 120/min（同 /24）、开放凭据 60/min——429 带 `Retry-After`。
6. builtin_shot 等模型默认 `public_site`/`open_api` 通道关闭，站点/开放使用前需在模型版本 policy 开启（当前只能改 policy 后重新发布模型版本——管理面待阶段6+ 补 UI）。

## 6. 本地栈搭建速查

前端工程 `vite.config.ts` 同源代理示例（跨域直连必被拦，见 §1）：

```ts
export default defineConfig({
  server: {
    proxy: {
      // 浏览器只看到 :5173，cookie 与 CSRF Origin 天然同源
      "/api": { target: "http://localhost:8080", changeOrigin: false },
    },
  },
});
```

```bash
docker compose up -d postgres            # 或全栈 up
# 空库重建（bash 等价 reset 脚本；本机 PowerShell 不可用）
docker compose stop api worker
psql: DROP/CREATE DATABASE agentchunzhi
docker compose run --rm migrate
bootstrap: docker compose run --rm --entrypoint /app/agentchunzhi-bootstrap \
  -e ORG_SLUG=.. -e ORG_NAME=.. -e ADMIN_EMAIL=.. -e ADMIN_PASSWORD=.. api
APP_ENV_FILE=.env.test docker compose up -d api worker   # development 模式
# readyz: GET :8080/readyz == {"status":"ready"}
```

**`/readyz` 排障**：就绪时 `{"status":"ready"}`；异常时 503 + `{"status":"unavailable","failures":[...]}`——`retrieval_extensions_missing`/`manifest_identity_mismatch`/semantic 相关失败 = 检索配置问题（语义查询会降级或 503）；`database_*` = 数据库不可达。前端联调遇到检索"永远走不了语义"或数据不刷新时先看这里，再查 worker 容器日志。

生产/准生产模式直接用 `.env`（勿带 APP_ENV_FILE）：须先补齐 §1 表列生产键。
