# 公开站点主题化与 AI 设计重构 · 开发文档

版本：v1（2026-09-13）
决策人已拍板的前提：**不共存、不做兼容层、不保留旧设计数据**。pages_config / style_config / homepage_config / 导航配置体系整体退役，"主题模板（agent 生成、人审发布）"成为站点设计的唯一表达。

---

## 1. 目标与非目标

### 目标
1. 站点外观完全由**主题**（一组 Go html/template 模板文件 + CSS）表达，agent 在沙盒中直接编写，用户对话式沟通、iframe 实时预览、人工确认发布。**预览一律为实时渲染直出（预览端点 + 一次性签名），不使用截图**。
2. 模板体系是唯一的设计面：首页、文章详情、集合页、分类页、自定义页、错误页全部主题化；固定字体/CSS/模块目录/presets 全部删除。
3. agent 能力扩展为站点管家：设计页面之外，可改站点名称/描述、自定义数据模型（字段/出口通道）、管理自定义页——全部经工具调用，全部受权限矩阵约束。
4. 工作区设置/站点管理 UI 重构为**左对话、右预览+配置**的双栏工作台。

### 非目标
- 不动资产治理链：草稿→提交→人工确认→发布、human_only 发布、发布历史、可见性闸门、派生收录视图——语义不变。
- 不动多语言数据模型（locale 列/翻译组）、分类公开化（containers）、评论、搜索、媒体。
- 不引入外部 CMS（AnQiCMS 等）；编排引擎 M1 用现有 react runs 通道，Eino 作为 M2 编排层替换的评估项。

## 3. 数据模型与迁移（0040）

```sql
-- 0040_theme_foundation.sql
CREATE TABLE site.site_theme_revisions (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    site_id uuid NOT NULL,
    revision_no integer NOT NULL,
    status text NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','published','archived')),
    files jsonb NOT NULL DEFAULT '{}'::jsonb,   -- 槽位 → 模板源码；空对象 = 全槽位回退内置默认主题
    base_revision_id uuid,
    created_by uuid NOT NULL REFERENCES identity.users(id),
    created_at timestamptz NOT NULL DEFAULT now(),
    published_at timestamptz,
    UNIQUE (organization_id, id),
    UNIQUE (site_id, revision_no),
    FOREIGN KEY (organization_id, site_id) REFERENCES site.public_sites (organization_id, id)
);
-- 「每站点至多一个 draft / 一个 published」是发布事务的硬前提，必须索引级强制。
CREATE UNIQUE INDEX site_theme_revisions_one_draft
    ON site.site_theme_revisions (site_id) WHERE status = 'draft';
CREATE UNIQUE INDEX site_theme_revisions_one_published
    ON site.site_theme_revisions (site_id) WHERE status = 'published';

ALTER TABLE site.public_sites
    ADD COLUMN draft_theme_revision_id uuid,
    ADD COLUMN published_theme_revision_id uuid;
ALTER TABLE site.public_sites
    ADD CONSTRAINT public_sites_draft_theme_fk
        FOREIGN KEY (organization_id, draft_theme_revision_id)
        REFERENCES site.site_theme_revisions (organization_id, id),
    ADD CONSTRAINT public_sites_published_theme_fk
        FOREIGN KEY (organization_id, published_theme_revision_id)
        REFERENCES site.site_theme_revisions (organization_id, id);

CREATE TABLE site.site_pages (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    site_id uuid NOT NULL,
    slug text NOT NULL,
    title text NOT NULL,
    body_markdown text NOT NULL DEFAULT '',      -- 正文（同一 markdown 净化管线产出 HTML）
    seo_description text NOT NULL DEFAULT '',
    nav_order integer NOT NULL DEFAULT 100,      -- 越小越靠前；与固定路由/分类同序合并
    nav_hidden boolean NOT NULL DEFAULT false,
    locale text,                                 -- NULL = 全语言（与资产 locale 语义一致）
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (organization_id, id),
    UNIQUE (site_id, slug),
    FOREIGN KEY (organization_id, site_id) REFERENCES site.public_sites (organization_id, id)
);

-- 引导：每个站点建一个初始 published 修订版（files 留空 → 全槽位回退内置默认主题），
-- 并回填 draft/published 指针，保证发布事务有基线。
INSERT INTO site.site_theme_revisions
    (organization_id, workspace_id, site_id, revision_no, status, files, created_by, published_at)
SELECT s.organization_id, s.workspace_id, s.id, 1, 'published', '{}'::jsonb, s.created_by, now()
FROM site.public_sites s;

UPDATE site.public_sites s
SET published_theme_revision_id = r.id, draft_theme_revision_id = r.id
FROM site.site_theme_revisions r
WHERE r.site_id = s.id AND r.status = 'published';

-- 会话沙盒重建（drop + create，不搬存量，拍板不留旧数据）。
DROP TABLE IF EXISTS site.design_sessions;
CREATE TABLE site.design_sessions (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    site_id uuid NOT NULL,
    status text NOT NULL DEFAULT 'open' CHECK (status IN ('open','applied','discarded')),
    files jsonb NOT NULL DEFAULT '{}'::jsonb,
    base_theme_revision_id uuid,
    created_by uuid NOT NULL REFERENCES identity.users(id),
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (organization_id, id),
    FOREIGN KEY (organization_id, site_id) REFERENCES site.public_sites (organization_id, id)
);
CREATE INDEX design_sessions_site_status_idx ON site.design_sessions (site_id, status);

-- 旧设计体系退役（列 drop；数据丢弃为拍板决策）。
ALTER TABLE site.public_sites
    DROP COLUMN IF EXISTS homepage_config,
    DROP COLUMN IF EXISTS pages_config,
    DROP COLUMN IF EXISTS style_config,
    DROP COLUMN IF EXISTS navigation_config,
    DROP COLUMN IF EXISTS custom_css;
```

要点（与上面 DDL 一一对应，不再有"只在文字里"的变更）：
- `files` 用 jsonb（槽位→源码字符串）：单文件 256KB、整集 1MB，服务端限制。
- draft/published 指针落在站点表；`UNIQUE ... WHERE status` 两个部分索引强制单例，发布事务依赖它。
- `custom_css` 列一并 drop（由主题 `theme.css` 取代）——与 §2.1 删除表一致。

## 4. 主题文件规范

### 4.1 槽位（slot）清单

| 文件键 | 职责 | 渲染上下文（Go 类型） |
|---|---|---|
| `layout` | 全站骨架：head/导航/页脚，`{{template "content" .}}` 挂载点 | Chrome（`.Site`）+ NavItems |
| `home` | 首页 | HomeVM v2（Site / Items[]CardVM / TagCloud / NavItems）——`Sections`/`Blocks`/`HeroTitle` 随配置体系删除 |
| `detail` | 文章详情（现 renderer 名为 `detail`，**非 `post`**） | DetailVM（Title / ContentHTML(`template.HTML`) / TOC / Fields / Tags / Publications / Prev / Next / Attachments） |
| `list` | 文章集合页 `/posts/` | ListVM（Title / Items[]CardVM / Pager） |
| `tags` | 标签索引页（现 `tag_index`） | TagCloud/Facets |
| `tag_page` | 单标签页 | TagPageVM |
| `search` | 搜索结果页 | SearchVM（Query / Items / Pager） |
| `category` | 分类页 `/c/...` | CategoryVM（Crumb / Children / Items） |
| `page` | 自定义页 `/p/{slug}` | **CustomPageVM**（实名，非 PageVM）：Title / ContentHTML(`template.HTML`) / SEO description |
| `partials` | 公共片段库（card / tag_chips / pagination / header / footer） | 由调用处决定 |
| `tokens.css` | 设计令牌：颜色/字体/间距 CSS 变量 | —（纯 CSS，内联注入） |
| `theme.css` | 主题样式（引用 tokens 变量） | — |

**非主题系统页（不经主题引擎，agent 不可编辑）**：`error`、`gate`（内容不足门页）、`xml/rss.xml`、`xml/sitemap.xml`、`xml/robots.txt`、`static/delivery-search.js`。这些保持 Go 内置渲染；主题槽位缺失时回退**内置默认主题**（§5.4），不回退旧配置。`layout` 必须存在且定义 `content` 挂载点（校验器强制）。文件上限：单文件 256KB、整集 1MB。

### 4.2 渲染上下文 = agent 的 API（《模板上下文参考》文档）

- 每个槽位的 VM struct 字段全量文档化（现有 PageVM/Chrome/TagChip/PublicFieldValue/PublicationVM 等直接沿用，字段即契约）。
- 附每个字段的类型、可空性、示例值。该文档入库 `docs/theme-context.md`，并整份注入 agent 的 skill 系统提示。
- 语义变更即版本化：VM 增字段为兼容变更；删/改字段需主题上下文版本号 +1，并在文档 changelog 记录。
- **正文 HTML 的类型约束（安全关键）**：`DetailVM.ContentHTML`、`CustomPageVM.ContentHTML` 与首页 `BodyHTML` 现为 `string` 且模板靠 `{{noescape .}}` 输出（viewmodel.go:189/140）。主题化必须改为 `template.HTML`，**只由服务端 markdown 净化管线赋值**（模板写 `{{.ContentHTML}}` 即输出已净化 HTML）；agent 无法构造该类型。**严禁把 `noescape` 暴露给主题模板**——否则 agent 可 `{{noescape .任意字符串}}` 绕过自动转义，形成存储型 XSS。

### 4.3 函数白名单（M1 最小集）

`html/template` 内置之外，仅暴露：
`assetURL id`（→/sites/{slug}/media/id）、`absURL path`、`dateFmt layout time`、`truncate n s`、`json v`、`i18n key`。按需增补，每个函数进文档。**不引入 sprig，且永久不含 `noescape`**（见 §4.2）。未知函数在 `template.Parse` 阶段即报错。

### 4.4 导航的数据化

删除 navigation_config。导航 = 固定路由（首页/文章/标签）+ 启用分类 + `site_pages`（nav_order/nav_hidden）共同派生为 VM 的 `NavItems`，主题只负责渲染。语言切换器同理（已有 EnabledLocales 派生）。

## 5. 主题引擎（internal/theme）

### 5.1 编译与缓存

- 入口：`Compile(files map[string]string) (*Theme, error)`——将 layout/partials/各槽位合并为一棵 `template.Tree`；任何槽位编译错误返回**逐文件逐行**错误清单（agent 可读，用于自修复）。
- 编译缓存：按 (site_id, theme_revision_id) 缓存；修订版发布/回滚时失效。
- 渲染：`Render(slot, vm)`。**字段契约化，不承诺 `missingkey=zero`**——该选项只作用于 map 索引，struct 缺失字段在 html/template 执行期是错误而非零值。契约：VM 字段可空性在《模板上下文参考》逐字段标注，模板用 `{{if}}`/`{{with}}` 判空。

### 5.2 管线接入

- delivery 各 handler 的 buildFunc 改为：取站点 `published_theme_revision_id` 修订版 → 引擎渲染对应槽位。**取数复用、VM 需重定义**：`ResolveHome/ResolveList` 现签名含 `style site.StyleConfig`（viewmodel.go:351,481，将被删除）必须改签名；`HomeVM` 的 `Sections/Blocks/HeroTitle` 随 homepage_config/pages_config 删除而移除。非主题系统页（error/gate/xml）不走主题引擎。
- 预览路径：`RenderPreview(files, slot)` 编译沙盒文件集（不落库），供实时预览端点与 `render_html` 工具；`PreviewInput` 现含 `style_config/pages_config/custom_css`（preview.go:22-27）需重定义为 `files`+`slot`。

### 5.3 安全扫描（入站门禁，保存与发布前强制）

**作用域：只扫描 agent 写入/apply 的文件**。内置默认主题是可信基线，不参与扫描（其 header/search 自带 `<form>` 搜索框；见下）。
对每个（agent 产出的）模板文件：
1. 拒绝 `<script`、`javascript:`、`on*=` 事件属性、`<iframe|object|embed`、`data:text/html`；`<form` 仅允许 `method="get"` 且 `action` 为站内相对路径（默认主题的搜索框满足该白名单）。检测宜用 HTML 解析器而非纯正则（避免 `content` 等属性误伤）。
2. CSS 文件拒绝 `@import`、`url(` 中非 `data:image|/sites/|none` 的引用（外链字体/图片禁；CSP font-src/img-src 亦兜底）。
3. 模板语法静态限制：禁 `{{template` 引用未定义名称（编译期自然失败）、禁止调用非白名单函数（解析期失败）。
4. 违规返回结构化错误（文件/行/规则），直接进 agent 工具响应供自修复。
CSP 继续 `default-src 'none'; style-src 'unsafe-inline'; script-src 'self'; img-src 'self' data:`，作为运行时最后防线。

### 5.4 内置默认主题

现 `templates/` 的重写版：干净的一套 tokens（米白/衬线标题，即现视觉）+ 各槽位模板，作为内置回退与新建站点起点， agent 可 fork。

## 6. 发布流与版本语义

```
agent 会话(草稿 files) --apply--> 站点 draft 修订版（每站点至多 1 个）
用户「发布」＝ 原子事务：
  draft 修订版 status→published（旧 published→archived）
  站点表 published_theme_revision_id 指向新修订版
  创建站点 release（快照：theme_revision_id + 收录状态），历史可回滚
  缓存失效（复用站点级 invalidation）
```

- 回滚 = 将某历史 published 修订版重新置为 published（新 revision_no 顺延，幂等）。
- 内容发布（asset publish）不变：仍写 asset_publications、slug 切换、收录视图。**外观与内容两条版本线，release 同时钉住两者**。
- 「发布」按钮的权限沿用 site.lifecycle（人类）；agent 永远只能到达 draft（human_only 不变）。

## 7. AI 设计会话 v2 与双栏工作台

### 7.1 会话沙盒

- `site.design_sessions` 重建：`id, site_id, status(open/applied/discarded), files jsonb（沙盒文件集，fork 自 published 或 draft）, created_by, created_at, updated_at`。
- fork 语义：从站点当前 draft（如有）否则 published 修订版拷贝文件集。
- apply：校验（编译+扫描+槽位齐全）通过后写入/更新站点 draft 修订版；discard 零残留。
- 不设 observe/截图端点；agent 感知渲染结果的方式是 `render_html`（确定性文本）与 `validate_theme`（结构报告）。
- **预览渲染源 = 会话沙盒 `files`**；站点 `theme/draft` 是右下配置面板的工作副本；只有 `apply` 才把沙盒写入 draft。二者不得混用（否则"预览的内容与最终发布的不一致"）。

### 7.2 agent 工具集（M1 清单）

| 工具 | 能力 | 权限 |
|---|---|---|
| `read_theme` / `write_theme` | 按 slot 读/写草稿文件（写后自动编译+扫描，错误即回显） | site.design |
| `render_html` | 编译沙盒 → 渲染指定槽位 → 返回渲染后 HTML 源码（agent 以文本自检结构/内容，无需视觉） | site.design |
| `preview_link` | 生成一次性签名预览 URL（60s TTL、单次使用、绑定会话+站点+成员），供双栏 iframe | site.design |
| `validate_theme` | 编译/扫描/槽位完整性/死链检查报告 | site.design |
| `update_site` | 改名称/描述 | **site.design**（代码无 `site.update` 动作：authz/actions.go 仅 site.read/design/lifecycle；名称/描述现由 PATCH sites 在 site.design 下修改，sites.go:167。若要独立动作需同步动作表+角色矩阵） |
| `manage_model` | 自定义数据模型：建模型/增删改字段/设展示名/出口通道（走 resourcemodel 现有服务） | model.manage |
| `manage_pages` | 自定义页增删改（site_pages） | site.design |
| `search_assets` | 检索库查询（找内容/找字段样例） | **query.execute**（authz/actions.go:27） |

### 7.3 双栏工作台 UI（替换旧设计 Tab）

## 13. 审计记录（2026-09-13，对照仓库现状逐条核实）

审计方法：把文档中每条代码级断言（文件路径、类型名、权限动作、表结构、模板集）与 forge/zck-web 仓库逐个比对。发现 18 项，其中 P0 五项会导致实施失败或引入安全漏洞——**均已在本文档正文修正**。

### P0（会导致失败/安全漏洞）

1. **`noescape` 缺失 → 正文渲染失效；若补进白名单 → 存储型 XSS**。现模板用 `{{noescape .ContentHTML}}` 输出净化后的 markdown，字段是 `string`（viewmodel.go:189/140）。白名单不含 noescape 则正文被转义成源码；把 noescape 交给 agent 模板则可 `{{noescape .任意串}}` 绕过自动转义。**已定：ContentHTML/BodyHTML 改为 `template.HTML`（仅服务端赋值），白名单永久不含 noescape**（§4.2/§4.3）。
2. **默认主题自带 `<form>` 会被扫描器拒绝**。partials/header.html:10、pages/search.html:3 均有搜索表单，而原 §5.3 一律拒 `<form`。**已定：扫描器只作用于 agent 文件；form 规则放宽为 method=get + 站内 action**（§5.3）。
3. **预览 iframe 被现有 CSP 阻止**。`deliveryCSP` 含 `frame-ancestors 'none'`（delivery_routes.go:29），预览 HTML 拿去喂 iframe 会渲染空白。**已定：预览响应单独下发 `frame-ancestors 'self'`**（§7.3）。
4. **迁移 §3 不可执行**：缺 `published/draft_theme_revision_id` 的 ALTER、缺 design_sessions 的 CREATE、缺默认修订版 bootstrap、缺"单 draft/单 published"的部分唯一索引、缺 FK 与 `UNIQUE (organization_id, id)`。**已按本仓惯例（见 0034）重写完整 DDL**（§3）。
5. **`site_pages` 无正文列**。自定义页内容现取自 pages_config 的 PageDef.Blocks（public.go:1971-1978），删配置后无处存放正文。**已加 `body_markdown`**（§3）。
