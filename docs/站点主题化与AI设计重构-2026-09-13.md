# 公开站点主题化与 AI 设计重构 · 开发文档

版本：v2（2026-09-13）

> v2 变更：合并审计修正意见，消除正文与审计的双重表述；补全槽位（section / about / archive）与搜索脚本岛方案；勘误依据移至「附录 A」。迁移 SQL 已在本地库以事务回滚方式实跑通过。

**前提（已拍板）**：不共存、不做兼容层、不保留旧设计数据。pages_config / homepage_config / style_config / navigation_config / custom_css 体系整体退役，「主题模板（agent 生成、人审发布）」成为站点设计的唯一表达。

---

## 1. 目标与非目标

### 目标
1. 站点外观完全由**主题**表达——一组 Go `html/template` 模板文件 + CSS。agent 在沙盒中直接编写，用户对话式沟通、**iframe 实时预览**、人工确认发布。
2. 模板体系是唯一的设计面：首页、文章详情、集合页、分区页、分类页、标签页、搜索页、归档页、自定义页全部主题化；固定字体、固定 CSS、模块目录、样式预设全部删除。
3. agent 升级为「站点管家」：设计页面之外，可改站点名称/描述、自定义数据模型（字段/出口通道）、管理自定义页——全部经工具调用，全部受权限矩阵约束。
4. 站点管理 UI 重构为**左对话、右预览+配置**的双栏工作台。

### 非目标
- 不动资产治理链：草稿→提交→人工确认→发布、human_only 发布、发布历史、可见性闸门、派生收录视图——语义不变。
- 不动多语言数据模型（locale 列/翻译组）、分类公开化（containers）、评论、搜索、媒体、RSS/sitemap/robots。
- 不引入外部 CMS；编排引擎 M1 用现有 react runs 通道，Eino 作为 M2 编排层替换的评估项。

### 贯穿性约束
- **发布永远由人触发**（`site.lifecycle`）；agent 只能到达草稿。
- **预览不使用截图**，一律实时渲染直出 + 一次性签名。
- 主题模板运行在受限上下文：无外部资源、无脚本、无任意函数。

## 3. 数据模型与迁移（0040）

```sql
-- 0040_theme_foundation.sql
CREATE TABLE site.site_theme_revisions (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    site_id uuid NOT NULL,
    revision_no integer NOT NULL,
    status text NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','published','archived')),
    files jsonb NOT NULL DEFAULT '{}'::jsonb,   -- 槽位 → 模板源码；空对象 = 全槽位回退内置默认主题
    base_revision_id uuid,
    created_by uuid NOT NULL REFERENCES identity.users(id),
    created_at timestamptz NOT NULL DEFAULT now(),
    published_at timestamptz,
    UNIQUE (organization_id, id),
    UNIQUE (site_id, revision_no),
    FOREIGN KEY (organization_id, site_id) REFERENCES site.public_sites (organization_id, id)
);
-- 「每站点至多一个 draft / 一个 published」是发布事务的硬前提，索引级强制。
CREATE UNIQUE INDEX site_theme_revisions_one_draft
    ON site.site_theme_revisions (site_id) WHERE status = 'draft';
CREATE UNIQUE INDEX site_theme_revisions_one_published
    ON site.site_theme_revisions (site_id) WHERE status = 'published';

ALTER TABLE site.public_sites
    ADD COLUMN draft_theme_revision_id uuid,
    ADD COLUMN published_theme_revision_id uuid;
ALTER TABLE site.public_sites
    ADD CONSTRAINT public_sites_draft_theme_fk
        FOREIGN KEY (organization_id, draft_theme_revision_id)
        REFERENCES site.site_theme_revisions (organization_id, id),
    ADD CONSTRAINT public_sites_published_theme_fk
        FOREIGN KEY (organization_id, published_theme_revision_id)
        REFERENCES site.site_theme_revisions (organization_id, id);

CREATE TABLE site.site_pages (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    site_id uuid NOT NULL,
    slug text NOT NULL,
    title text NOT NULL,
    body_markdown text NOT NULL DEFAULT '',      -- 正文；经与资产同一 markdown 净化管线产出 HTML
    seo_description text NOT NULL DEFAULT '',
    nav_order integer NOT NULL DEFAULT 100,      -- 越小越靠前；与固定路由/分类同序合并
    nav_hidden boolean NOT NULL DEFAULT false,
    locale text,                                 -- NULL = 全语言（与资产 locale 语义一致）
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (organization_id, id),
    UNIQUE (site_id, slug),
    FOREIGN KEY (organization_id, site_id) REFERENCES site.public_sites (organization_id, id)
);

-- 引导：每个站点建一个初始 published 修订版（files 留空 → 全槽位回退内置默认主题），
-- 并回填 draft/published 指针，保证发布事务有基线。
INSERT INTO site.site_theme_revisions
    (organization_id, workspace_id, site_id, revision_no, status, files, created_by, published_at)
SELECT s.organization_id, s.workspace_id, s.id, 1, 'published', '{}'::jsonb, s.created_by, now()
FROM site.public_sites s;

UPDATE site.public_sites s
SET published_theme_revision_id = r.id, draft_theme_revision_id = r.id
FROM site.site_theme_revisions r
WHERE r.site_id = s.id AND r.status = 'published';

-- 会话沙盒重建（drop + create；不搬存量）。
DROP TABLE IF EXISTS site.design_sessions;
CREATE TABLE site.design_sessions (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    site_id uuid NOT NULL,
    status text NOT NULL DEFAULT 'open' CHECK (status IN ('open','applied','discarded')),
    files jsonb NOT NULL DEFAULT '{}'::jsonb,
    base_theme_revision_id uuid,
    created_by uuid NOT NULL REFERENCES identity.users(id),
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (organization_id, id),
    FOREIGN KEY (organization_id, site_id) REFERENCES site.public_sites (organization_id, id)
);
CREATE INDEX design_sessions_site_status_idx ON site.design_sessions (site_id, status);

-- 旧设计体系退役（列 drop；数据丢弃为拍板决策）。
ALTER TABLE site.public_sites
    DROP COLUMN IF EXISTS homepage_config,
    DROP COLUMN IF EXISTS pages_config,
    DROP COLUMN IF EXISTS style_config,
    DROP COLUMN IF EXISTS navigation_config,
    DROP COLUMN IF EXISTS custom_css;
```

要点：
- `files` 为 jsonb（槽位→源码字符串）：单文件上限 256KB，整集上限 1MB，服务端强制。
- draft / published 指针落在站点表；两个部分唯一索引强制单例，发布事务依赖之。
- 状态迁移：`archived` 只增不减；回滚是「历史修订版重新置为 published」而非就地改内容。
- 预览 token 若落库需另一张表（§7.3），0040 不含，随端点实现补迁移。

## 4. 主题文件规范

### 4.1 槽位（slot）清单

| 文件键 | 对应页面 | 渲染上下文（Go 类型） |
|---|---|---|
| `layout` | 全站骨架（head / 导航 / 页脚），须含 `{{template "content" .}}` 挂载点 | Chrome（`.Site`）+ NavItems |
| `home` | 首页 `/` | HomeVM |
| `detail` | 文章详情 `/posts/{path}` | DetailVM |
| `about` | 关于页 `/about/` | DetailVM（Kind="about"，复用详情结构） |
| `list` | 文章集合页 `/posts/` | ListVM |
| `section` | 分区页 `/sections/{slug}` | ListVM |
| `category` | 分类页 `/c/{path}` | CategoryVM（Crumb / Children / Items） |
| `tags` | 标签索引页 `/tags` | TagCloud / Facets |
| `tag_page` | 单标签页 `/tags/{key}` | TagPageVM |
| `search` | 搜索结果页 `/search` | SearchVM（Query / Items / Pager） |
| `archive` | 归档页 `/archive/` | ArchiveVM（Years[]ArchiveYearVM；现为匿名结构，本次具名化） |
| `page` | 自定义页 `/p/{slug}` | CustomPageVM |
| `partials` | 公共片段（card / tag_chips / pagination / header / footer） | 由调用处决定 |
| `tokens.css` | 设计令牌（颜色 / 字体 / 间距 CSS 变量） | —（纯 CSS，内联注入） |
| `theme.css` | 主题样式（引用 tokens 变量） | — |

规则：
- `layout` 必须存在且定义 `content` 挂载点；其余槽位缺失时回退**内置默认主题**对应文件（§5.4）。
- 槽位数上限 32；单文件 256KB，整集 1MB。
- 媒体路由 `/media/{id}` 非页面，不设槽位。
- **搜索岛**：搜索页依赖第一方脚本 `/static/delivery-search.js`。主题模板禁写 `<script`，故提供白名单函数 `{{searchIsland}}`——输出该脚本标签（`template.HTML`，仅此一个固定片段）。agent 在 `search` 槽位中调用它即可启用实时搜索。

### 4.2 渲染上下文（《模板上下文参考》）

- 每个槽位的 VM 字段全量文档化：类型、可空性、示例值、是否可空（模板用 `{{if}}` / `{{with}}` 判空）。
- 文档入库 `docs/theme-context.md`，整份注入 agent skill 的系统提示；VM 字段即 agent 的 API。
- 版本化：新增字段为兼容变更；删除或改变语义需主题上下文版本号 +1，并在文档 changelog 记录。

**正文 HTML 的类型约束（安全关键）**：`DetailVM.ContentHTML`、`CustomPageVM.ContentHTML`、首页 `BodyHTML` 一律为 `template.HTML`，**只由服务端 markdown 净化管线赋值**——模板写 `{{.ContentHTML}}` 即输出已净化 HTML，agent 无法构造该类型。函数白名单永久不含 `noescape`（§4.3），否则 agent 可绕过自动转义造成存储型 XSS。

### 4.3 函数白名单

`html/template` 内置之外，仅暴露：
`assetURL id`、`absURL path`、`dateFmt layout time`、`truncate n s`、`json v`、`i18n key`、`searchIsland`（§4.1）。

按需增补，每个函数进《模板上下文参考》。不引入 sprig，永久不含 `noescape`。未知函数在 `template.Parse` 阶段即报错。

### 4.4 导航的数据化

删除 navigation_config。导航 = 固定路由（首页 / 文章 / 标签）+ 已公开分类 + `site_pages`（nav_order 排序、nav_hidden 隐藏）共同派生为 `NavItems`，主题只负责渲染。语言切换器沿用 `enabled_locales` 派生。

## 5. 主题引擎（internal/theme）

### 5.1 编译与缓存

- **模板是数据，不是代码**：用户主题存于 `site_theme_revisions.files`（jsonb），引擎用 `template.New(...).Parse(字符串)` 在**运行时编译**——改主题 = 改数据库记录，零代码变更、零部署。内置默认主题经 `embed` 打包进二进制，仅作回退，随版本更新。
- `Compile(files map[string]string) (*Theme, error)`：把 layout / partials / 各槽位合并为一棵模板树；任何槽位编译错误返回**逐文件逐行**清单（agent 可读，用于自修复）。
- 缓存按 `(site_id, theme_revision_id)`；修订版发布 / 回滚时失效。
- `Render(slot, vm)`：不依赖 `missingkey` 语义（该选项仅作用于 map）；VM 字段可空性由《模板上下文参考》约定，模板判空。
- 数据流：模板（DB）与内容（Postgres，经现有取数逻辑）在渲染时由 VM struct 接合——`取数 → 构造 VM → Execute`。改代码仅发生于平台能力升级（新增白名单函数 / VM 字段），与"做设计"严格分离。

### 5.2 管线接入

- delivery 各 handler：取站点 `published_theme_revision_id` → 引擎渲染对应槽位。**取数逻辑复用，VM 需重定义**——`ResolveHome` / `ResolveList` 现含 `style site.StyleConfig` 参数（随 StyleConfig 删除而改签名）；`HomeVM` 的 `Sections` / `Blocks` / `HeroTitle` 随配置体系移除。
- 预览：`RenderPreview(files, slot)` 编译沙盒文件集（不落库），供预览端点与 `render_html` 工具。
- 非主题系统页（error / gate / xml / static）不走引擎。

### 5.3 安全扫描（入站门禁：保存与发布前强制）

**作用域：只扫描 agent 写入与 apply 的文件**。内置默认主题是可信基线，不参与扫描（其 header / search 自带搜索表单与脚本标签）。

对每个 agent 产出的模板文件：
1. 拒绝 `<script`、`javascript:`、`on*=` 事件属性、`<iframe|object|embed`、`data:text/html`；`<form` 仅允许 `method="get"` 且 `action` 为站内相对路径。用 HTML 解析器而非纯正则（避免 `content` 等属性误伤）。
2. CSS 拒绝 `@import` 与 `url(` 中的非白名单引用（仅允许 `data:image`、`/sites/`、`none`）。
3. 模板静态限制：`{{template}}` 引用未定义名称在编译期失败；非白名单函数在解析期失败。
4. 违规返回结构化错误（文件 / 行 / 规则），直接进 agent 工具响应供自修复。

运行时兜底：CSP `default-src 'none'; style-src 'unsafe-inline'; script-src 'self'; img-src 'self' data:`（交付页）。

### 5.4 内置默认主题

现有模板的净化重写版：一套干净的 tokens（米白底 / 衬线标题，即当前视觉）+ 全槽位模板，作为缺失回退与新建站点起点，agent 可 fork 后改。

## 6. 发布流与版本语义

```
agent 会话（草稿 files） --apply--> 站点 draft 修订版（每站点至多 1 个）
用户「发布」＝ 原子事务：
  draft 修订版 status → published（旧 published → archived）
  站点表 published_theme_revision_id 指向新修订版
  创建站点 release（快照 = 主题修订版引用 + 收录状态）
  缓存失效（复用站点级 invalidation）
```

- 回滚 = 历史 published 修订版重新置为 published（新 revision_no 顺延，幂等）。
- 内容发布（asset publish）不变：仍写 asset_publications、切换 slug、更新收录视图。
- **外观与内容两条版本线，release 同时钉住两者**。
- 「发布」权限沿用 `site.lifecycle`（人类）；agent 只能到 draft（human_only 不变）。

## 7. AI 设计会话 v2 与双栏工作台

### 7.1 会话沙盒

- `site.design_sessions`：`status ∈ {open, applied, discarded}`，`files` 为沙盒文件集。
- fork 语义：从站点当前 draft（若有）否则 published 修订版拷贝文件集。
- apply：校验（编译 + 扫描 + 槽位齐全）通过后写入 / 更新站点 draft 修订版；discard 零残留。
- **预览渲染源 = 会话沙盒 `files`**；站点 `theme/draft` 是右下配置面板的工作副本，只有 apply 才写入。二者不得混用，否则预览与最终发布不一致。
- 不设截图 / observe 端点。agent 感知渲染结果靠 `render_html`（确定性文本）与 `validate_theme`（结构报告）。

### 7.2 agent 工具集（M1 清单）

| 工具 | 能力 | 权限 |
|---|---|---|
| `read_theme` / `write_theme` | 按槽位读 / 写草稿文件（写后自动编译 + 扫描，错误即回显） | `site.design` |
| `render_html` | 编译沙盒 → 渲染指定槽位 → 返回 HTML 源码（agent 以文本自检） | `site.design` |
| `preview_link` | 签发一次性预览 URL（供双栏 iframe） | `site.design` |
| `validate_theme` | 编译 / 扫描 / 槽位完整性 / 死链检查报告 | `site.design` |
| `update_site` | 改站点名称 / 描述 | `site.design` |
| `manage_model` | 自定义数据模型：建模型、增删改字段、设展示名、出口通道 | `model.manage` |
| `manage_pages` | 自定义页增删改（`site_pages`） | `site.design` |
| `search_assets` | 检索库查询（找内容 / 字段样例） | `query.execute` |

编排引擎 M1 用现有 react runs 通道注册上述工具；工具 schema 与《模板上下文参考》共同构成 skill。M2 评估 Eino 替换编排层（接口已按工具清单抽象）。注意：站名 / 描述现挂在 `site.design` 下（无独立 `site.update` 动作）；若要细分需同步动作表与角色矩阵。

### 7.3 双栏工作台 UI（替换旧设计 Tab）

- **左**：会话流（消息 / 工具调用卡片 / 错误回显 / 「应用到草稿」）。
- **右上**：预览区 = iframe 实时预览。`GET .../design-sessions/{id}/preview?slot=home&token=…` 直出 `text/html`。
  - 预览响应须单独下发 `frame-ancestors 'self'`（交付页 CSP 的 `frame-ancestors 'none'` 会阻止 iframe），且不得设 `X-Frame-Options: DENY`。
  - token：HMAC 一次性签名，60 秒 TTL、单次消费、绑定会话 + 站点 + 成员；存储用 DB 表（本仓无 Redis）。
  - iframe 加 `sandbox=""`（预览 HTML 本无脚本）；桌面 / 移动切换 = 切换容器宽度。
  - 会话产生文件变更后前端自动换签刷新。
- **右下**：简单配置（站点名称 / 描述、自定义页列表、模型入口）——表单直改，走对应 API。
- 「发布主题」仅人类可见（`site.lifecycle`）；点击前强制展示 `validate_theme` 报告与全槽位预览确认清单。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| agent 模板质量不稳 | 默认主题兜底 + validate 报告 + 逐槽位应用（不必全站） |
| XSS / 外链资源 | 入站扫描 + html/template 自动转义 + CSP 三层 |
| 模板失控改不回来 | 修订版快照 + 一键回滚 + apply 前强制基线 |
| VM 字段变更破坏存量主题 | 上下文版本号 + 文档 changelog + 发布前编译校验 |
| token / 延迟成本 | agent 自检以 render_html 文本为主；write 槽位级 diff 而非整站重写 |
| 预览越权 / 泄漏 | 一次性签名 token（短 TTL、单次消费、绑定会话 + 成员）；预览 HTML 无脚本无表单 |
