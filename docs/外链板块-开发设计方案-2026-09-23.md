# 外链板块开发设计方案 v2

日期：2026-09-23（v2：从外链定制页升级为平台通用能力）
状态：方案定稿（待实施）
关联：《外链板块-SEO执行方案-2026-09-23.md》《公开站点简化方案（v7）》

## 0. 结论先行（v2）

**本方案从「为外链定制一个页面」升级为「补齐平台通用能力：模型公开目录页（Model Directory Pages）」**。外链板块是该能力的第一个消费者，知识卡/FAQ/未来任何结构化模型的公开目录随即免费获得。

### 0.0 平台功能缺口（为什么这是通用能力建设）

外链板块暴露了四个交付层能力缺口，它们是平台不健全而非外链特需：

| # | 缺口 | 现状 | 通用能力（v2 新增） |
|---|---|---|---|
| G1 | 模型记录无一等公开页 | sections 集合页恒 noindex（P2-2 补丁），记录发布后公开站无体面呈现 | 目录页种类：任意模型可配置生成可收录的公开目录页 |
| G2 | 页面级 TDK/Schema 配置缺失 | TDK 仅文章级与站点级 | 目录页级 Title/Description/H1 模板 + CollectionPage/ItemList Schema 注入 |
| G3 | 公开向模型提交记录无通道 | 匿名写面仅评论与问答 | 通用提交模块：公开表单 → 模型草稿记录 → 进治理链审核 |
| G4 | 目录型列表装配缺失 | 分组/排序/分页/精选每处手写 | 目录页配置化：分组字段、排序策略、每页条数、精选字段、引言文案 |

### 0.1 数据层映射（全部复用，零开发）

**外链板块完全复用现有自定义数据模型（resource model）+ 治理链 + 公开站投递层，不新建独立存储、不新建管理界面。** 核心映射：

| 设计需求 | 项目现有机制 | 结论 |
|---|---|---|
| 外链站点数据结构 | 自定义数据模型（field_schema/form_schema/list_schema） | 建一个 `external_site` 模型，字段即结构 |
| 每条外链记录 | 模型记录 = asset（一卡对一文） | 一条外链 = 一条记录 |
| 公开提交 → 人工审核 | 治理链（draft → commit-draft → confirm → publish） | 提交件落草稿，审核=确认+发布，零新流程 |
| 联系邮箱不对外泄露 | D5 字段展示白名单（默认全关，勾选才公开） | email 字段永不勾选公开 |
| 目录页/分类页上站 | 收录三道闸（已发布 + 可见性 + 模型 public_site 通道） | 发布即上站，自动进投递层 |
| 管理外链的后台 | 数据表记录页（tables/[modelId]，含新建/编辑/发布/归档） | 复用，零新控制台代码 |
| 每月死链巡检 | 记录列表按 updated_at 排序 + 归档操作 | 手工巡检即可支撑当前规模 |

需要新开发的就是 §0.0 的通用能力本体：**交付层的「模型目录页」种类（builder + 配置驱动装配）+ 目录页配置管理 + 通用提交模块**。外链板块 = 该能力的一次配置实例化，不含一次性代码。

### 0.2 为什么仍有开发量（关键论证 + 降级方案对比）

"项目支持"覆盖的是**数据层与治理层**：建模、录记录、审核、发布、自动上站全部零开发（上表已列）。剩余开发量集中在**公开呈现层**，原因是硬性的：

1. 现有唯一能公开列出模型记录的页面是 sections 集合页，但它被审计决议（P2-2）**恒 noindex**——设计意图就是"实现细节面不进索引"。一个不收录的页面做不了外链目录的 SEO。
2. SEO 目标页需要：分组目录 + Featured 区 + 提交表单 + FAQ + Directory Schema + 关键词 TDK。任何现有页面种类（文章/分类页/自定义页/标签页）都不提供这些模块。

**降级方案对比**（如果连一个页面种类都不想开发）：

| 方案 | 效果 | 代价 |
|---|---|---|
| 零开发：不给 sections 解除 noindex，外链仅存于后台 | 无 | 板块不存在，SEO 目标全部落空 |
| 微开发：给 Section 增加按模型策略的强制索引开关 | 记录列表可收录（URL 形如 /sections/xxx，无关键词、无引言/FAQ/表单/Schema 模块） | SEO 竞争力弱；且"解除 noindex"本身也是交付层改动，省不了多少 |
| **本方案 P0：新增目录页种类**（推荐） | 关键词 URL、完整落地页模块、Schema、分页、提交入口 | 交付层一个 builder + 模板，约 1.5~2 天 |

若接受微开发方案的弱形态，可把 P0 进一步缩为"Section 索引开关 + 模型字段微调"（约半天），后续再升级为完整目录页——两者不冲突，升级时废弃开关即可。**默认按 P0 推进。**

## 1. 数据模型设计

### 1.1 模型定义

| 项 | 值 |
|---|---|
| model_key | `external_site` |
| 名称（label） | 外链站点（External Site） |
| content_kind | record（结构化记录，同知识卡） |
| status | active |
| 创建方式 | 管理台「数据模型」新建，或复用内置模型种子机制（0043 同款）追加组织级种子 |

### 1.2 字段表（field_schema / form_schema / list_schema）

一条提交 = 「推荐的站点 + 提交者自己的站点（奖励外链）」，同一记录承载，审核时一并审定。字段分两组：

**A 组：推荐的站点（主目录收录对象）**

| 字段 key | 类型 | 展示名（label，D17） | 必填 | 公开白名单 | 说明 |
|---|---|---|---|---|---|
| site_name | string | Site Name | ✓ | ✓ | 锚文本用，品牌名为主 |
| site_url | string | Site URL | ✓ | ✓ | 出站链接目标；**纯字符串，不做 URL 类型强校验**：提交只查非空，审核时规整，渲染兜底（自动补 https:// + 协议白名单仅 http/https，防注入）；同 URL 去重 |
| category | enum | Category | ✓ | ✓ | 枚举：`seo-tools` / `content-creation` / `monetization` / `operations` / `website-building`；提交者自己的站点默认继承同分类 |
| description | text | Short Description | ✓ | ✓ | ≤160 字符原创英文描述，禁止复制官网文案 |
| tested_date | date | Tested On（实践日期） | — | ✓ | 团队实测/使用该站点的日期，公开展示为信任信号（E-E-A-T 体验证据）；随手填，缺省不显示 |
| agent_skill | text | Agent Skill（自动提交说明） | — | ✓ | 可选：提交者撰写的 SKILL.md 风格技能说明——"如何让 Agent 自动向该站点提交外链"的步骤/表单字段/注意事项，公开渲染为可复制的代码块，访客粘贴给自己的 Agent 即可自动执行；≤8000 字符，纯文本转义渲染（不执行、不内联 HTML） |
| tags | multiselect | Tags | — | ✓ | 枚举：featured / dofollow / new 等 |
| featured | boolean | Featured | — | ✗（内部） | 精选标记，控制总目录页 Featured Sites 区 |

**B 组：提交者的站点（奖励外链，分类页 Community Picks 位展示）**

| 字段 key | 类型 | 展示名（label，D17） | 必填 | 公开白名单 | 说明 |
|---|---|---|---|---|---|
| submitter_site_name | string | Your Site Name | — | ✓ | 提交者自己站点的锚文本 |
| submitter_site_url | string | Your Site URL | — | ✓ | 奖励外链目标；同上纯字符串+渲染兜底；同 URL 去重（同分类只展示最新一条，防刷量） |
| contact_email | string(email) | Contact Email | ✓ | **永不开白名单** | 审核通知用，仅内部可见 |
| submission_note | text | Submitter Note | — | ✗ | 提交者留言，仅内部可见 |

要点：
- B 组两个字段可选填：填了 = 接受奖励外链，进分类页 Community Picks 位；不填 = 纯推荐。
- 提交者站点分类默认继承 A 组 category（表单不增加第二选择，降低门槛），随主记录同组展示。
- 白名单遵循 D5「默认全关」语义；contact_email/submission_note 永不公开。

要点：
- 白名单遵循 D5「开启公开通道那一刻默认全关」的既有语义；本模型的白名单默认值直接在 field_schema 里声明（site_name/site_url/category/description/tags 开，featured/contact_email/submission_note 关）。
- `enum` 的选项集即分类体系，未来新增分类 = 模型改枚举 + 发新模型版本，走既有版本化机制。

## 2. 数据流与审核机制

```
访客提交表单（/external-links 页内）
  → POST /external-links/submit（公开端点，public_site_ip 限流 + 蜜罐字段）
  → 创建 external_site 记录：publication_status = draft，origin 标记 = external_submission
  → 控制台「知识卡同款记录列表」按 draft 过滤 = 待审队列
  → 管理员人工审核：确认版本（confirm）+ 发布（publish）
  → 三道闸通过 → 自动出现在 /external-links 总目录与对应分类分组
  → sitemap / 内链随发布自动更新
```

- 审核标准（SEO 方案§规则页）由人工执行，系统只提供状态流转与黑名单字段校验（category 枚举、URL 格式）。
- 拒绝 = 归档记录（archived），不公开、可追溯。
- 已上线的站点需要下架 = 归档，投递层按三道闸自动摘除并失效缓存。

## 3. 交付层实现（通用能力本体）

### 3.1 目录页实例（外链板块 = 首个配置）

目录页由「站点级目录配置」驱动（存站点设置 JSON，格式见 §3.4），每个实例 = 一条配置：

```json
{
  "slug": "external-links",
  "model_key": "external_site",
  "group_by": "category",
  "sort": "featured_desc,updated_at_desc",
  "page_size": 20,
  "tdk": {
    "title": "External Links Directory for SEO | Free Backlink Submission",
    "description": "Curated external links directory for indie developers & SaaS sites...",
    "h1": "External Links Directory & SEO Guide"
  },
  "intro": "A curated directory of high-quality external links...",
  "submission": { "enabled": true, "honeypot": true },
  "schema": ["CollectionPage", "ItemList", "FAQPage"]
}
```

### 3.2 路由（由配置实例生成，新增 3 + 1）

| 路由 | 页面 | 实现要点 |
|---|---|---|
| `GET /external-links` | 总目录页 | 新 page builder：按 category 分组渲染记录，featured 区置顶；分页每页 20 条 |
| `GET /external-links/{category}` | 分类子页 | 同 builder 按 category 过滤；**两个展示位**：目录收录区（A 组记录）+ Community Picks 区（B 组提交者站点，同分类聚合、按 URL 去重取最新、奖励链接属性走站点级 nofollow 开关）；category 枚举白名单校验，非法值 404 |
| （条目级） | Agent Skill 块 | 填了 agent_skill 的条目，条目尾部渲染可折叠的「Agent Skill」代码块（纯文本转义 + 一键复制），访客复制给自己的 Agent 即可自动向该站点提交；字数计入页面内容厚度，是天然的差异化 UGC |
| `GET /external-links/submission-guidelines` | 规则说明页 | 静态内容页（模块参数化文案），无记录查询 |
| `POST /external-links/submit` | 提交端点 | JS-free 表单 POST（仿 deliverySiteCommentPost 模式）；字段校验 + 蜜罐 + 限流；成功 303 回总目录页#submit 并提示 |

- 路由注册进 `internal/httpapi/router_groups.go` 的 registerDeliveryRoutes；仅当站点 active 且模型 public_site 通道开启时输出内容（复用 SiteFacts 判定）。
- 总目录页与分类页**可收录**（不设 noindex）——注意与 sections 集合页（恒 noindex 的实现细节面）划清边界：本页面是对外内容面，走独立 builder，不复用 Section。

### 3.2 页面 SEO 装配（复用现有管线）

- **TDK**：Title/Description 来自页面常量表（SEO 方案§TDK 定稿），走 `injectSEOMeta` 既有注入管线；canonical 自指。
- **结构化数据**：总目录页 JSON-LD `CollectionPage` + `WebSite`；分类页 `ItemList`；FAQ 区 `FAQPage`（extension：injectSEOMeta 增加页面级 JSON-LD 透传，或 builder 直接拼入 vm.JSONLD）。
- **分页**：`?page=N`，页码页 canonical 指第一页（与既有列表页口径一致，P1-1 惯例）。
- **sitemap**：`Service.Sitemap` 增加外链组——总目录页 + 各分类子页（有记录才列）。
- **出站链接渲染**：`target="_blank" rel="nofollow ugc"` 起步可配（SEO 方案：初期 dofollow 吸引提交，风险开关预留 nofollow 切换——做成站点级配置或模板常量）。
- **内链**：面包屑 `Home > External Links > {Category}`；Related Articles 区复用 related 推荐管线取 SEO 分类文章。

### 3.3 缓存与失效

- 页面走既有 pipeline（PageCache + revision key）；记录 publish/archive 时既有失效事件自动覆盖外链页（模型通道资产变更已进 invalidator）。

## 4. 管理台

- **模型创建**：数据模型管理页手工新建（推荐，走版本化），字段按 §1.2。
- **审核台**：数据表记录页选 external_site 模型 → 状态筛选 draft = 待审队列；行内发布/归档即审核动作。
- **新增工作量**：仅记录列表增加「来源」徽标（区分访客提交/自建），P1 可选项。

## 6. 分期与工作量

| 期 | 内容 | 预估 |
|---|---|---|
| P0 | 通用能力：目录配置存储 + 目录页 builder + 模板 + sitemap/TDK/Schema 注入；external_site 模型建模 + 首个实例 `/external-links` 上线 + 首批记录录入 | 2~2.5 天 |
| P1 | 通用提交模块：公开表单端点（form_schema 校验/限流/蜜罐/草稿落库）+ 审核台来源徽标 | 1 天 |
| P2 | 分类子页由 group_by 自动拆分（各分组 ≥10 条启用）+ 规则说明页 + FAQPage schema | 1 天 |

能力回收：P0 完成后，知识卡/FAQ 等任何模型的公开目录 = 加一条配置，零代码；P1 完成后，任何模型都具备公开征集记录的能力（外链提交、资源推荐、投稿征集同为实例）。

## 7. 边界与风险

- sections 集合页恒 noindex 是有意设计，外链页不复用该实现，避免破坏既有口径。
- 公开提交端点是新增匿名写面：必须挂 public_site_ip 限流 + 蜜罐 + 草稿态（不通过发布永不上站），无提权风险。
- 经典镜头库（builtin_shot）已退役；external_site 走正式建模流程，不做一次性内置种子（除非后续多组织复制需要）。
