# 垂直领域高质量数据资产库

产品文档 v0.1  

> 最终实现修订（2026-08）：Agent 统一采用本系统内置 Eino Runtime。ModelEndpoint 负责 OpenAI/OpenAI-compatible 等云端模型连接，AgentApplication 绑定 endpoint；支持固定 RAG、受限 ReAct、固定 Graph、审批中断和持久化恢复。外部业务系统只通过受限 Open API 访问数据。
状态：概念定义 / 需求基线  
适用对象：企业、部门、专业团队

## 1. 产品概述

### 1.1 一句话定义

这是一个面向企业或专业团队的垂直领域数据资产中台：把人工、API、软件工具和外部系统产生的原始信息，沉淀为可管理、可追溯、可授权、可被 Agent 使用的数据资产。

### 1.2 产品定位

产品不是普通文件盘，也不是把数据复制给外部平台的单一知识库，而是企业内部数据和检索能力的权威来源：

`输入采集 → 原始数据留存 → Agent 整理加工 → internal 内部版本 → 管理员/编辑显式发布 → 企业数据资产库与检索索引 → 权限内展示 / 问答 / 外部系统与 Agent 查询`

### 1.3 要解决的问题

- 垂直领域数据分散在文档、表格、聊天记录、工具和个人电脑中，难以持续沉淀。
- 不同领域的数据结构不同，固定表结构无法覆盖实际业务。
- 原始资料通常不完整、不规范、重复或缺少上下文，无法直接供人或 Agent 可靠使用。
- 三人团队首期只使用管理员、编辑两个成员角色；Agent 的数据权限由独立白名单控制。
- 外部 Agent 需要获得已发布数据，但企业不希望把整个数据库暴露给外部系统。
- 前台既要展示可公开的数据资源，也要支持有权限的 Agent 问答；外部业务系统通过开放 API 获取授权数据。

### 1.4 产品目标

1. 提供通用文档 / 笔记、FAQ 等系统内置数据模型，并允许企业管理员按垂直领域配置专业资源模型；普通内容用户不需要设计数据表。
2. 让任何来源的数据都能保留原始版本，并形成到加工结果的可追溯关联。
3. 用可配置 Agent 将原始资料整理成结构化、去重、补全、可检索的数据资产。
4. 让同一套权限规则同时作用于管理后台、前台资源、开放 API 和 Agent 工具；前台问答另行区分“用户是否可使用 Agent 应用”与“Agent 用户可访问的数据范围”。
5. 让外部 Agent 通过密钥获得明确、可撤销、可审计的数据访问能力。
6. 让用户把通用文档当成记事本使用，也可以通过数据模型生成的 CMS 动态表单规范录入。
7. 由本系统统一负责文档、笔记、FAQ 和结构化资产的留存与检索，外部 Agent 只通过统一 API 获取权限内结果。

### 1.5 核心产品体验

产品的第一入口应当是通用的“笔记文档”，而不是要求用户先理解数据表。用户可以像使用记事本一样输入标题、正文、附件和标签，正文优先使用 Markdown，系统再由 Agent 进行分类、整理和关联。对经典镜头等需要精确录入的场景，系统提供基于内置模型的 CMS 动态表单、内部保存、自动保存、预览和显式发布能力。

资源模型负责把“记录方式”和“发布规则”一起配置好：字段、表单布局、默认整理 Agent、默认权限和检索 / API 范围都属于模型配置。系统提供通用模型，企业管理员可以配置专业模型；普通内容用户只负责记录和填写表单，不需要设计数据表。

首个业务方向暂定为“经典镜头库”，同时建设不依赖具体领域的通用资源模型：文档、笔记、FAQ、附件和引用关系。这样镜头数据可以使用专业字段，编辑记录的笔记和资料也能进入同一套整理、发布、权限和检索流程。

### 1.6 非目标（第一阶段不做）

- 不自研通用大模型，通过 Eino ChatModel adapter 接入 OpenAI/OpenAI-compatible 等云端模型；模型凭证由 ModelEndpoint 管理。
- 不把所有数据强制转成向量；结构化字段优先通过精确 API 查询，文档检索由本系统统一提供全文、语义和混合检索。
- 不在第一阶段实现复杂的字段级加密、跨企业共享和计费系统。

### 1.7 架构判断

“数据留存在本系统，检索也由本系统提供，外部 Agent 统一调用查询 API”是当前更合适的方案，建议作为产品的正式架构原则。

- **数据单一来源**：文档、笔记、FAQ、结构化资产、版本和附件只在本系统维护，模型只接收权限过滤后的上下文。
- **权限集中生效**：成员角色、Agent 数据白名单、发布状态和归档操作都在统一查询 API 中实时判断，减少外部 Agent 复制数据后的权限漂移。
- **检索组件可替换**：PGroonga、pgvector 或其他检索组件只是索引实现，替换时不影响主数据、前台和外部 Agent 接口。
- **内置 Agent 更简单**：Eino 负责问答、工具调用和固定流程，不需要部署外部编排平台或维护知识库副本。
- **需要接受的代价**：本系统需要建设检索服务、索引更新、引用校验和查询限流；索引存在短暂最终一致，但查询权限必须以主数据为准。

## 2. 核心概念

| 概念 | 定义 |
| --- | --- |
| 企业组织 | 当前系统唯一的数据管理边界。用户、资源表、Agent 和权限都归属于这一个企业，不做多企业隔离。 |
| 资源表 / 数据模型 | 一类内容集合，例如通用文档、FAQ、经典镜头。模型可以由系统内置或企业管理员配置，普通内容用户不直接设计数据表。 |
| 资产 | 资源表中的一条可管理记录，既可以是结构化记录，也可以包含正文、附件和多媒体。 |
| 通用笔记文档 | 以标题、Markdown 正文、附件和标签为主的通用内容资产，不是临时草稿；后续可由 Agent 分类、补充字段并关联到专业模型。 |
| 原始数据 | 用户或外部来源首次提交的内容，必须保留，不被加工结果覆盖。 |
| 可发布资产 | 经 Agent 处理或人工编辑、校验完成后，由管理员或编辑显式发布并供业务和 Agent 使用的版本。 |
| 资产关联 | 原始数据、加工任务、加工结果、引用资料和相关资产之间的可追溯关系。 |
| 数据文档 | 以 Markdown 正文、附件和来源为主的资产类型，适合知识阅读、全文检索和语义检索。 |
| 统一查询 API | 本系统对前台、Agent 应用和外部系统提供的统一查询入口，覆盖结构化、全文、语义、混合检索、详情和关联查询。 |
| 检索索引 | 从已发布资产生成的全文、分块、向量和关键词索引，用于加速检索；索引不是权威数据源，可以重建。 |
| 检索投影 | 从已发布资产生成的全文、分块、向量和关键词索引；不替代本系统保存原始内容、权限和版本。 |
| 外部 Agent | 本版本不部署外部 Agent 平台；外部系统如需调用业务数据，使用受限 Open API 和 Agent 用户身份。 |
| Agent 用户 | 内置 Agent 或外部业务调用使用的技术身份，通过 API Key 认证，并使用独立的 Agent 数据权限白名单。 |
| Agent 应用 | Agent 用户对外提供的可使用能力，例如“镜头问答助手”或“内容处理助手”。普通成员需有“使用 Agent”权限才可在前台发起问答或任务。 |
| Agent 接入信息 | 创建 Agent 用户后由系统生成的对接包，包括基础地址、Agent ID、一次性显示的 API Key、认证方式、OpenAPI 地址、可调用接口说明和测试示例。 |
| Agent 定时任务 | 由系统按时间或事件触发的任务配置，定义哪个 Agent 读取哪个开放接口、处理后调用哪个开放接口写回结果。 |

### 2.1 数据状态

首期资产只使用一个三态生命周期：

`internal → published → archived`

- **internal**：新建、编辑和 Agent 加工产生的内部版本。它可以继续被编辑、处理或再次发布，但不进入默认前台、开放 API、全文和语义检索结果。
- **published**：管理员或编辑显式选定一个不可变 `AssetVersion` 后原子切换的当前公开版本。编辑已发布资产只会创建新的 `internal` 版本，旧发布版本持续可用，直到另一个版本被显式发布。
- **archived**：资产从默认出口和检索结果移除，但版本、来源、附件和审计仍保留。

文件扫描、抽取、Agent 整理的进行中、成功或失败状态属于附件任务和 `ProcessingJob`，不进入资产生命周期；首期不创建审核任务、退回状态或质量等级状态机。

### 2.2 处理信息

Agent 处理可记录输入版本、引用依据、字段差异、置信度、错误和重试信息，用于审计和人工判断；这些信息不阻断 `internal` 版本的编辑，也不构成另一套发布状态。

## 3. 产品架构

```text
人工输入 / API / 文件导入 / 软件工具 / 外部系统
                       │
                       ▼
                 资产中台（本产品）
       ┌──────────┬──────────┬──────────┬──────────┐
       │ 原始数据 │ 数据模型 │ 权限审计 │ 版本血缘 │
       └──────────┴──────────┴──────────┴──────────┘
                       │
                       ▼
             Agent 整理与发布流程
                       │
                       ▼
           PostgreSQL + 阿里云 OSS（权威数据源）
                       │ 资产发布 / 更新事件
                       ▼
          检索服务（全文 / 结构化 / 语义 / 混合）
                       │
              PostgreSQL 检索索引与分块层
                       │
                       ▼
                 统一查询 API
          ┌────────┬────────┬────────┬────────┐
          │资源展示│Agent问答│外部系统│外部Agent│
          └────────┴────────┴────────┴────────┘
```

产品的统一原则是：所有出口都先经过本产品的身份识别和权限过滤，外部 Agent 不直接访问数据库或检索投影。检索索引必须能由 PostgreSQL 中的已发布资产重建；资产下线、权限变化和删除会触发索引更新或删除。

## 4. 用户与角色

### 4.1 主要用户

- **管理员**：配置工作区成员、资源模型、Agent 应用、Agent 数据白名单和系统规则。
- **编辑**：提交原始数据、补充字段、上传附件、处理 Agent 结果、发布和归档资产。
- **成员**：以 `editor` 角色查看、编辑和发布工作区资产，或以受限入口使用已授权 Agent 应用。
- **Agent 用户**：外部服务使用的技术身份；以 API Key 调用开放 API，数据范围由独立白名单决定。

### 4.2 权限动作

权限至少拆成以下动作：

`查看、创建、编辑、删除、处理、发布、归档、导出、调用开放 API、使用 Agent、管理 Agent 应用、管理定时任务、发起问答`

首期成员只保留 `admin` 和 `editor` 两个工作区角色。管理员管理成员、模型、Agent 应用和全部资产；编辑可以创建、编辑、处理、发布和归档资产。第一版的最小数据权限粒度是资源模型；资源模型中的记录、字段和附件继承模型权限，不单独配置 ACL。

## 5. 权限体系

### 5.1 统一授权模型

采用“成员角色 + Agent 数据白名单 + 资源范围”的模型，不建设 OAuth/SSO、部门、用户组或完整 RBAC 矩阵。

- **主体**：`admin` / `editor` 成员，或技术身份 Agent 用户。
- **动作**：查看、编辑、发布、问答、导出等。
- **资源范围**：资源表和 Agent 应用；所有资源默认属于当前企业。资源表中的记录、文档、附件和字段在第一版继承所属资源表权限。
- **条件**：登录状态、发布状态、来源或其他业务条件。

权限判定顺序：

1. 判断主体是否存在且有效。
2. 判断是否满足动作权限。
3. 判断主体是否能访问目标资源范围。
4. 对列表、搜索、详情、下载、导出和开放 API 内容按请求主体做同样的过滤；前台问答先校验发起用户能否使用 Agent 应用，再由绑定 Agent 用户按其自身权限调用查询 API。
5. 记录关键访问、导出、发布和密钥调用日志。

### 5.2 可见性级别

建议把“谁能看”和“数据是否已发布”分开管理。

| 可见性 | 访问条件 | 典型用途 |
| --- | --- | --- |
| 公开 | 无需登录 | 官网 / 前台资源展示、公开知识 |
| 登录可见 | 登录后可见 | 企业内部全员资源 |
| 工作区成员可见 | 登录且属于当前工作区 | 企业内部资源 |
| 仅内部处理 | 仅后台或指定处理 Agent 可用 | 原始输入、处理中数据、敏感草稿 |

以上可见性在第一版按资源模型配置。资源模型中的记录、文档和附件沿用该配置；“公开”只代表访问范围，不代表内容一定可以被搜索或被外部 Agent 获取，是否进入出口还要同时满足 `published` 和出口策略。

### 5.3 Agent 身份规则

Agent 用户不是第三种业务角色，只是外部服务的技术主体。管理员可以创建、启停和轮换其 API Key，并为其配置资源模型/动作白名单。

- 创建 Agent 用户时不设置密码，系统生成一个或多个 API Key；密钥仅在创建或轮换时显示一次，支持命名、过期、吊销、限流和最后调用时间。
- Agent 用户通过 API Key 调用开放 API，服务端按 `AgentAccessPolicy` 的资源模型/动作白名单执行授权，不继承成员角色。
- Agent 用户可以拥有 `read/create/edit/publish/archive` 中的明确动作；没有 `publish` 权限时只能创建或编辑 `internal` 版本。
- Agent 应用与 Agent 用户分离：前者决定谁能在前台使用该能力，后者决定该 Agent 服务能访问和写入哪些系统数据。

## 6. 功能模块

### 6.1 企业组织管理

- 设置企业名称、Logo、默认语言和默认可见性。当前版本只维护一个企业组织，不提供创建多个企业组织的入口。
- 管理成员、邀请关系和工作区角色。
- 配置 Agent 数据权限白名单。
- 查看登录、权限变更、导出、API 调用和 Agent 操作审计日志。

### 6.2 数据模型与 CMS 动态表单（核心能力）

系统预置通用文档 / 笔记和 FAQ，可预置经典镜头等示例专业模型。数据模型 = 业务字段 + 录入方式 + 展示方式 + 整理规则 + 权限和检索 / API 策略。管理员可以创建和配置专业资源模型；编辑直接使用通用文档或模型生成的动态表单，不参与数据表设计。没有选择专业模型时，内容默认保存为通用笔记文档。

字段类型建议包括：

`短文本、长文本、Markdown、内容（Block）、数字、金额、日期、单选、多选、布尔、人员、部门、标签、附件、图片、视频、地理位置、关联记录、JSON`

其中，`Markdown` 是普通文本字段；`内容（Block）` 是可选的结构化内容字段。只有模型明确声明了内容字段时，该字段才绑定到 Block 容器并以 Block 树作为权威内容，不能把普通文本、JSON 或 Markdown 字段自动转换为 Block。

管理员配置能力：

- 创建或启用模型，设置名称、描述、图标、所属领域和默认权限。
- 添加业务字段，配置是否显示、是否必填、默认值、枚举值、校验规则和帮助说明。
- 配置唯一字段、关联字段、计算字段和可搜索字段。
- 配置列表、详情、录入表单和前台展示视图。
- 配置表单分组、字段顺序、宽度、占位提示和默认值。
- 通用文档模型固定提供标题、Markdown 正文、附件、标签、来源、作者和关联内容；专业模型如需段落级编辑，可额外声明 `content` 字段。
- 配置“录入后自动整理”“允许哪些 Agent 发布”“哪些 Agent 可以通过 API 查询”等规则。
- 发布规则只负责校验字段、附件和处理结果；首期不配置审核用户组或多级审批。
- 支持 CSV / Excel 导入导出和 API 写入。
- 模型字段、枚举、必填/唯一约束或出口策略发生变化时，创建新的模型版本；先提供影响预览和批量校验，再执行可重试的迁移任务。迁移未完成前，表单、API 和 Agent 工具继续绑定原模型版本，不能把半迁移数据发布出去。

#### 6.2.1 两种录入方式

1. **通用笔记文档**：标题 + Markdown 正文 + 附件 + 标签，支持自动保存、草稿、粘贴图片和预览。用户把它当成企业内部记事本，发表后可由 Agent 分类、整理和建立关联。需要结构化段落时，专业模型使用单独的 `content` 字段承载 Block。
2. **笔记块与正文图片（2026-09-04）**：笔记树块词表为 paragraph/heading/quote/code/list/callout/image（封闭枚举，变体走 props）。image 块只存附件引用（`attachment_id` + 可选 alt/caption，各 ≤500 字），不存文件本体；heading 级别走 `props.level`（1-6，缺省 3）。冻结产物携带中性引用 `chunzhi-media://{id}` 与最终 alt（块级优先、识图默认兜底），公开页渲染期重写为同源媒体地址，外部图片链接一律剥除。识图为附件生成 OCR、内容描述（进检索索引）与默认 alt（建议值，展示级修改须用户确认）；AI 无直写笔记通道，插图以建议卡 + 用户确认落地。
2. **模型动态表单**：根据经典镜头、FAQ 等系统内置或管理员配置的模型显示结构化字段，支持必填校验、关联选择、附件上传、预览和保存 internal 版本。

两种方式都产生原始版本。用户未选择专业模型时直接使用通用笔记文档；该文档可以保持为独立资产，也可以由 Agent 关联或转换为经典镜头等专业资产，转换不会覆盖原始文档。

### 6.3 数据采集与原始资产管理

输入方式包括：

- 通用笔记文档和模型动态表单。
- 后台批量录入和批量导入。
- 开放 API、Webhook、定时同步。
- 文件上传：文档、图片、音频、视频和压缩包。
- 从软件工具或其他系统采集。
- 前台用户提交，进入 `internal` 状态，等待编辑或 Agent 处理。

系统提供“我的笔记 / 待整理”入口，集中展示用户发表的通用文档和待处理内容。每条原始输入需要保存：来源、提交人、提交时间、原始内容、原始文件、来源链接、导入批次和校验结果。批量导入按行保存校验错误和幂等键，失败行可下载错误报告，重试不能覆盖已经接收的原始数据；批量导出按当前用户权限生成固定快照并记录审计。原始数据不可被高质量版本覆盖。附件上传后，用户可以在当前工作版本页面查看扫描和抽取状态，但不能看到对象存储地址。

附件上传成功只表示二进制已保存，初始状态为“待扫描”。系统异步完成恶意文件扫描，扫描通过后再抽取正文和元数据；扫描阻断或抽取失败的附件不得进入全文、语义检索或 Agent 整理输入。处理状态、失败原因和处理器版本对后台用户可见，重复投递不得重复生成抽取文本。编辑版本和 Agent 候选通过版本父链继承附件，不复制 OSS 对象；发布、检索和下载时都按当前版本父链重新检查附件状态。

### 6.4 Agent 整理与资产加工

管理员可为系统内置或管理员配置的数据模型设置 Agent 整理流程，流程由以下步骤组成：

1. 读取原始文本、附件或结构化字段。
2. 抽取目标字段，转换为资源表结构。
3. 标准化术语、单位、格式和标签。
4. 识别重复内容，推荐合并或关联记录。
5. 根据领域规则补全摘要、分类、关键词和关系。
6. 给字段或整条记录生成置信度、引用依据和处理说明。
7. 输出新的 `internal` 整理版本；由管理员/编辑显式发布，或由具备 `publish` 白名单动作的 Agent 发布。

处理结果必须保存：

- 使用的 Agent、模型 / 流程版本和执行时间。
- 输入资产 ID 和引用片段。
- 输出字段、修改前后差异和置信度。
- 错误信息、重试次数和人工修订记录。

默认情况下 Agent 只能产生 `internal` 版本。对于允许发布的 Agent，服务端按 `AgentAccessPolicy` 校验资源模型和 `publish` 动作；发布必须记录 Agent、规则版本、处理结果和发布时间。管理员可以随时撤销白名单。

资产发布或更新后，系统异步生成 / 更新检索索引：通用文档、笔记和 FAQ 生成全文索引、分块和可选向量；结构化资产生成字段索引和可选语义索引。索引任务失败不影响主数据发布，但必须显示状态并支持重试。索引只服务查询，不作为编辑、发布、权限或版本的来源。

### 6.5 发布与版本管理

- 工作台集中展示 `internal` 资产、处理失败、索引失败和最近发布记录。
- 管理员或编辑选择一个不可变 `AssetVersion` 显式发布，事务原子切换当前发布指针。
- 编辑已发布资产只创建新的 `internal` 版本；旧发布版本继续可见，直到新版本发布。
- 不创建审核任务、退回状态或多级审批；处理意见作为审计信息保存。
- 发布后保留版本历史，可查看谁在何时修改了什么。
- 归档资产从前台和问答结果中移除；本系统的全文 / 向量 / 分块索引通过索引事件删除或更新。

### 6.6 资源前台（CMS 式展示）

- 公开资源无需登录即可访问。
- 登录后根据工作区角色展示更多资源；第一版按资源模型授权，模型内资产继承模型权限。
- 支持领域导航、资源表导航、标签筛选、关键词搜索和关联内容浏览。
- 资源详情展示正文、结构化字段、附件、来源、更新时间和关联资产。
- 对内部数据隐藏未授权字段和附件，不仅隐藏列表入口。
- 支持可配置首页、专题页、目录页和资源卡片视图。

### 6.7 Agent 问答

用户在前台选择有权限的 Agent 或问答入口后：

1. 前端将问题和当前用户身份提交给本项目。
2. 本项目校验成员角色、AgentAccessPolicy 和 Agent 应用可用范围。
3. 本项目确认该 Agent 应用可被当前用户使用后，Eino Runtime 按应用绑定的 ModelEndpoint 生成答案；检索只使用该 Agent 用户自身的资源表、动作和模型出口权限。
4. 本项目将 Agent 权限内的上下文、字段结果和引用信息交给 Eino ChatModel/ChatModelAgent，并记录发起用户、Agent 应用、模型接口和 Agent 用户。
5. 内置 Agent 只负责推理、工具调用和表达，不作为企业文档、笔记或 FAQ 的数据源。
6. 本项目校验答案引用是否来自该 Agent 用户当前可访问、已发布且允许 Agent 出口的资产后返回前端，并记录问答审计日志。

启动问答前，系统创建短期 Agent 会话，记录发起成员、所选 Agent 应用和绑定 Agent 用户；成员只需要拥有该应用的“使用 Agent”权限。Eino Tool 调用始终使用绑定 Agent 用户的实时数据权限，不能读取或提交前台成员的资源权限。

外部 Agent 不应直接持有普通用户的长期凭证，也不应直接连接 PostgreSQL 或检索投影。普通用户的 `使用 Agent` 权限只决定其能否启动某个 Agent 应用，不参与该 Agent 的工具数据范围计算；Agent 的数据范围完全由其 Agent 用户身份决定。用户经授权启动 Agent 应用后，可接收该应用按自身数据权限生成的回答。答案中的资源详情链接仍按点击用户的直接资源权限校验，不能借链接绕过资源前台权限；问答答案、引用和调用主体必须完整审计。

### 6.8 Agent 用户接入、Agent 应用与统一查询

本系统的 Agent 是内置 Eino Runtime。每个 AgentApplication 绑定一个 Agent 用户和一个 ModelEndpoint，可配置 `rag`、`react` 或固定 `workflow`；外部系统如需调用业务数据，使用独立 Agent 用户的 Open API 权限。本系统保存并检索文档、笔记、FAQ 和结构化资产，模型不复制或托管企业权威数据。

#### 6.8.1 Agent 用户与普通成员统一管理

- 管理员在“用户与权限”中创建 Agent 技术身份，生成 API Key，并配置 `AgentAccessPolicy`。
- Agent 用户的动作仅来自资源模型/动作白名单，例如 `read`、`create`、`edit`、`publish`、`archive`；没有发布权限时只能生成 `internal` 版本。
- Agent 不继承成员的部门、用户组或角色。白名单收紧、Agent 停用或密钥吊销后，调用结果立即收紧或失效。
- Agent 用户通过 API Key 调用开放 API，不直接访问数据库、对象存储或检索投影。
- 资产发布、更新、下线、删除和权限变更生成索引更新事件；事件只刷新本系统检索索引，不把业务数据推送为外部 Agent 知识库副本。

#### 6.8.2 Agent 应用是可被使用的系统资源

Agent 用户负责“这个运行身份能访问和写入什么数据”；Agent 应用负责“哪些普通用户能使用这个能力”。管理员为 Agent 用户绑定 Agent 应用，并配置名称、能力类型、ModelEndpoint、运行模式和健康状态。

- Agent 应用进入成员角色权限体系。只有具备 `agent.use` 的成员，才会在前台看到并调用该应用。
- 用户在前台提问时，用户的 `使用 Agent` 权限决定其能否启动该应用；实际传给 Agent 的上下文 = 该 Agent 用户可读取的数据 ∩ 已发布和资源表策略允许的数据。用户本人的资源表读取权限不缩小 Agent 的工具查询范围。
- 后台处理型 Agent 应用可不在前台展示，只供定时任务或人工发起处理使用。
- Agent 应用可记录负责人、服务状态、调用量、失败原因、限流、最后调用时间和审计记录；这些是运行信息，不是独立的授权范围。

#### 6.8.3 创建后提供接入信息

创建 Agent 用户并生成密钥后，系统显示可复制的接入信息：基础地址、Agent 用户 ID、仅显示一次的 API Key、认证方式、当前可调用的 OpenAPI 地址、可访问的数据模型列表、测试请求示例，以及 Agent 应用回调和任务测试信息。密钥支持命名、到期、轮换、吊销和最后调用时间查看。

开放 API 文档根据该 Agent 用户的实际权限动态说明可调用接口；权限被调整后，接入信息和接口行为同步变化。外部开发者用该信息即可接入，不需要再维护一套 Agent 专用授权配置。

#### 6.8.4 内置 Eino 运行方式

AgentApplication 通过 `model_endpoint_id` 绑定 ModelEndpoint。`rag` 模式使用 Query Service + ChatModel，`react` 模式使用 ChatModelAgent 和受限 Tool Calling，`workflow` 模式使用固定 Eino Graph。所有检索结果都回到本系统完成权限过滤、版本校验和引用生成；高风险 Tool 通过 Stateful Interrupt 等待审批。

### 6.9 外部社群系统边界

本系统不建设社群、论坛、帖子、评论、点赞、收藏、举报、置顶、精华或社群内容审核等功能，也不在本系统维护对应的业务实体、页面和互动权限。

后续社群由外部系统独立建设并持有社群内容。外部系统如需使用本系统的数据资产，应通过单独定义的开放 API 契约接入，使用调用方 Agent 用户的实时权限；外部系统负责社群内容、互动关系和社群侧审核，本系统只负责自身资产的存储、检索、权限和审计。

### 6.10 开放 API

开放 API 是本系统统一的数据访问、写入和检索层，供前台、Agent 用户及受控外部系统使用。所有接口使用同一套身份、资源表权限、发布状态和审计规则。

**读取与检索能力**：

- 查询调用方可访问的领域和数据模型。
- 结构化查询：按数据模型、字段条件、标签、关键词、排序和分页检索已发布资产。
- 全文查询：按标题、Markdown 正文、标签、来源和附件文本检索。
- 语义查询：将自然语言问题转换为文档 / 笔记 / FAQ 的相关片段。
- 混合查询：结合结构化过滤、关键词和语义相关性，适合“找符合条件的镜头并参考相关笔记”。
- 获取单条资产详情、版本、来源、关联记录和引用片段。
- 查询结果包含 `asset_id`、`version`、`title`、`snippet`、`source`、`updated_at` 和可供 Agent 使用的引用信息。
- 查询资源表、可访问的数据模型和字段定义。

**写入与任务能力**：

- 创建和编辑通用文档、笔记、FAQ 与专业资源表资产；上传附件并建立资产关联。
- 按权限保存 `internal` 版本、发布或归档资产。
- 查询任务运行状态、回写处理结果、错误信息、来源引用和幂等键。

每个接口必须校验调用用户的动作权限和资源模型权限。例如 `创建资产`、`发布资产` 和 `查询任务` 是相互独立的动作，Agent 用户不会因持有 API Key 自动取得写入或发布能力。社群实体和互动接口不属于本版开放 API，后续由外部社群系统单独定义和接入。开放 `OpenAPI` 描述文件、可访问模型清单和测试示例，方便内置 Agent 或受控外部系统接入。

首版为 Eino 内置 Tool 和受控外部系统提供统一查询 API。调用方使用绑定 Agent 用户的 API Key，既可以查询经典镜头等结构化数据，也可以检索文档、笔记和 FAQ；接口返回内容必须遵循该 Agent 用户权限，并包含资产 ID、版本、更新时间和来源引用。

建议的统一查询请求：

```json
{
  "query": "找低机位远景镜头，并参考相关拍摄笔记",
  "mode": "hybrid",
  "data_models": ["shot", "document"],
  "filters": {"shot_size": "远景", "camera_angle": "低机位"},
  "top_k": 10
}
```

查询服务必须在召回前或召回后完成权限过滤，不能让未授权资产的标题、分数、数量或引用片段泄露给调用方。

### 6.11 数据留存与检索服务

#### 6.11.1 三层职责

| 层级 | 主要职责 | 是否权威 |
| --- | --- | --- |
| 主数据层 | PostgreSQL 保存资产元数据、Markdown 正文、结构化字段、版本、权限、来源和关系；阿里云 OSS 私有 Bucket 保存附件二进制。 | 是，唯一权威来源 |
| 检索索引层 | 生成全文索引、关键词索引、文档分块、向量和召回辅助数据；使用 PostgreSQL 能力或 pgvector。 | 否，可删除和重建 |
| 统一查询层 | 统一身份认证、权限过滤、结构化查询、全文查询、语义查询、混合检索、引用生成、限流和审计。 | 是，唯一对外查询入口 |

#### 6.11.2 索引生命周期

1. 资产创建或更新后，主数据事务提交并产生索引任务。
2. 只有 `published` 内容才进入对外检索索引；`internal` 和 `archived` 数据不进入公开召回。
3. 索引任务读取主数据，生成分块、关键词和向量，并保存资产 ID、版本号和权限范围映射。
4. 查询时使用索引快速召回，再以主数据中的当前发布状态、版本和资源模型权限做校验。
5. 资产归档、删除或权限收紧时，立即影响主数据查询，并异步删除或刷新索引。
6. 索引失败不阻塞内容编辑和发布，但必须显示为待重试状态；重建索引不会改变资产版本。

### 6.12 Agent 定时任务

定时任务把“读取系统数据 → 外部 Agent 处理 → 通过系统 API 写回结果”配置为可控、可重试和可审计的闭环。它不是通用脚本执行器，输入与输出都必须从本系统已登记的开放 API 操作中选择。

任务定义至少包含：任务名称、绑定的 Agent 应用和 Agent 用户、触发方式（Cron / 手动 / 业务事件）、输入 API 操作及筛选条件、外部 Agent 回调地址、输出 API 操作及字段映射、超时、并发数、重试策略、幂等规则和启停状态。保存任务时，系统校验 Agent 用户当前同时拥有输入读取和输出写入所需的权限。

一次任务运行的过程如下：

1. 调度器创建任务运行记录，并签发仅对本次运行有效的短期任务凭证。
2. 本项目向 Agent 应用的回调地址发送任务 ID、运行 ID、输入读取地址、输出写入地址和短期凭证。
3. 外部 Agent 使用该凭证读取已配置的数据，完成处理后调用已配置的输出 API 回写结果。
4. 服务端以“任务允许的操作 ∩ Agent 用户实时权限”执行每次调用；权限在运行中被收紧时，后续读取或写入立即失败。
5. 系统记录输入范围、输出资产、引用、耗时、错误、重试和幂等键，避免同一输入被重复写入。

首版提供两类模板：

- **文档整理入库**：读取指定状态的已录入文档 → 外部 Agent 抽取和补全 → 创建或更新可检索的数据资产，并关联原始文档。
- 社群或论坛的自动回复由外部社群系统自行实现，不纳入本系统定时任务模板；如需回写本系统资产，必须调用已登记且受权限约束的开放 API。

## 7. 关键业务流程

### 7.1 配置数据模型

管理员启用系统内置模型或创建专业模型 → 配置字段和表单布局 → 设置默认可见性 → 配置展示视图 → 选择有权限的整理 Agent 用户 / 应用 → 配置发布和 Agent 数据白名单 → 发布模型。

### 7.2 原始输入成为可发布资产

```text
提交原始数据
  → 保存原始版本和来源
  → 自动校验
  → Agent 整理 / 抽取 / 去重 / 建立关联
  → 生成 internal 版本和处理报告
  → 管理员/编辑校验后显式发布
  → 生成 / 更新本系统检索索引
  → 按权限进入前台、问答和统一查询 API
```

### 7.3 权限变更

管理员修改成员角色或 AgentAccessPolicy → 系统立即影响前台和统一查询 API → 产生权限变更审计日志 → 更新本系统检索索引的授权过滤 / 删除任务 → 记录索引处理结果；外部 Agent 后续查询立即使用新的权限。

### 7.4 用户发起问答

用户登录 → 选择有 `使用 Agent` 权限的 Agent 应用 → 本项目校验应用使用权限 → Eino 按绑定 Agent 用户和 ModelEndpoint 执行 RAG/ReAct → 按 Agent 用户的数据范围检索本系统数据 → 本项目校验 Agent 数据范围、发布状态和引用 → 返回答案并记录日志。

## 8. 信息架构

### 8.1 管理后台

`工作台 / 写笔记 / 我的笔记 / 数据资产 / 数据模型配置 / 版本与发布 / 检索与索引 / 用户与权限 / Agent 应用 / 定时任务 / 查询审计 / 系统设置 / 审计日志`

### 8.2 前台

`首页 / 领域与资源目录 / 搜索 / 资源详情 / Agent 问答 / 我的提交`

### 8.3 重要页面

- **工作台**：internal 数量、整理失败、索引失败、最近发布和快捷入口。
- **写笔记 / 我的笔记**：类似企业记事本的连续记录入口，支持 Markdown、草稿、附件、标签、发表和发起整理。
- **数据模型详情**：系统内置或管理员配置的模型字段、表单布局、发布策略和检索 / API 策略。
- **资源表详情**：筛选、批量操作、发布状态、版本入口和前台预览。
- **资产详情**：当前发布版本、原始数据、处理链路、引用来源、关联资产和权限。
- **整理任务详情**：输入、输出、字段差异、置信度、引用依据和处理结果。
- **版本与发布**：查看 internal、published、archived 版本，执行显式发布和归档。
- **检索与索引**：查看全文、向量和混合索引状态，处理索引失败、重建和删除任务。
- **权限配置页**：管理员/编辑角色和 AgentAccessPolicy 白名单的生效结果预览。
- **用户与权限**：管理成员角色和 Agent 技术身份；创建 Agent 用户时生成 API Key 和资源模型/动作白名单，明文 Key 只显示一次。
- **Agent 应用页**：绑定 Agent 用户，配置外部服务地址、问答 / 整理能力、前台可用范围、健康检查、回调认证和调用日志。
- **定时任务页**：配置输入 API、筛选条件、Agent 应用、输出 API、Cron / 事件触发、并发、重试和运行历史。
- **查询审计**：按 Agent、用户、数据模型、接口和时间查看查询记录、耗时、返回数量和引用。

## 9. 产品级数据对象

核心对象建议包括：

`Organization、User、WorkspaceMember、AgentAccessPolicy、Invitation、ResourceModel、ResourceModelVersion、FieldDefinition、FormLayout、ModelMigrationJob、Asset、AssetVersion、RawInput、AssetRelation、ProcessingJob、ImportBatch、ImportRow、ExportJob、RetrievalProjection、QueryLog、ApiKey、ModelEndpoint、AgentApplication、AgentSession、AgentTask、automation.Run、AuditLog`

其中 `Organization` 在当前版本只有一条企业组织记录；`User.user_type` 区分普通成员和 Agent 用户，`ApiKey` 归属于用户；`ModelEndpoint` 保存模型接口 revision，`AgentApplication` 绑定 endpoint 和 Eino 运行模式，`AgentSession` 记录成员启动应用时的短期绑定和审计，`AgentTask / automation.Run` 记录自动化任务及运行闭环。产品侧的“资源表 / 表版本 / 检索索引”在内部分别对应 `ResourceModel / ResourceModelVersion / RetrievalProjection`，新 API、数据库迁移和代码统一使用内部名称。`RawInput → ProcessingJob → AssetVersion` 是数据可信度和追溯的主链路；`AssetRelation` 用于记录来源、引用、派生、重复、上下位和关联关系；检索投影是可重建的副本，`QueryLog` 记录统一查询 API 的调用、权限范围、耗时和结果审计。

## 10. MVP 范围

### P0：第一版必须可用

- 单一企业组织、用户、`admin/editor` 工作区角色和 AgentAccessPolicy。
- 系统内置通用文档 / 笔记和 FAQ，并提供经典镜头专业模型；普通内容用户无需设计数据表。
- 管理员可创建专业资源模型，配置字段、表单布局、发布权限、Agent 整理和检索 / API 策略。
- 通用笔记文档：标题、Markdown 正文、附件、标签、自动保存草稿、预览和发表。
- 经典镜头等专业模型的 CMS 动态表单、文件上传、CSV 导入和资产 CRUD。
- 原始数据留存、版本记录和基础关联。
- Agent 整理任务：抽取字段、生成摘要、标签和候选版本。
- 三态生命周期：`internal → published → archived`；不做审核任务、退回或多级审批。
- 资源模型级公开 / 登录 / 工作区可见性；记录和字段继承资源模型权限。
- 数据模型可配置指定 Agent 是否拥有 `publish` 白名单动作。
- 前台资源目录、搜索、详情。
- Agent 用户使用独立 AgentAccessPolicy 和 API Key，不继承成员角色。
- 管理员可创建、轮换和吊销 Agent API Key；密钥明文仅在创建或轮换响应中显示一次，旧 Key 轮换后立即失效。
- Agent 应用作为可授权资源，支持前台问答 / 使用权限、接入信息和调用审计。
- 开放 API 支持按权限读取、检索、创建 / 更新资产，以及查询任务和回写处理结果。
- Agent 定时任务：可配置输入 API、外部处理回调和输出 API，并提供短期任务凭证、重试和运行审计。
- 首版 Agent 使用内置 Eino，模型通过 ModelEndpoint 接入云端，不保存企业权威知识副本。
- 本系统留存文档、笔记和 FAQ，并提供统一的全文、语义、混合和结构化查询 API。
- 为内置 Agent Tool 提供统一查询能力：既能查询经典镜头等精确字段，也能检索文档、笔记和 FAQ。
- PostgreSQL / 阿里云 OSS 作为权威数据源，PGroonga/pgvector 作为可重建的检索投影。
- 建立索引更新、删除、重试和查询审计机制。
- 经典镜头库专业资源模型，以及通用文档 / 笔记资源模型。

### P1：形成团队协作闭环

- 多 Agent 应用、统一用户权限管理和更丰富的统一查询工具配置。
- 外部社群系统接入另行定义开放 API 契约；本系统不建设社群页面、互动模型或社群内容整理流程。
- 批量发布/归档和更丰富的处理规则。
- 权限变更自动触发检索索引授权更新 / 删除。
- 更完整的查询审计、索引失败重试和调用限流。

### P2：规模化和专业化

- 字段级权限和敏感字段脱敏。
- 多企业 / 多租户隔离、跨企业共享和对外数据产品。
- 更丰富的媒体解析、向量检索和领域质量评分。
- 可视化数据血缘、质量趋势和 Agent 效果评估。

### 10.1 首版技术约束

- 后端以 Go 为主，核心数据存储使用 PostgreSQL。
- 产品界面以现有截图中的“资产中台”为主线：后台采用笔记文档、CMS 动态表单和版本发布体验，前台提供资源展示和问答入口；外部社群由独立系统建设。
- 内置 Eino 首先覆盖 RAG、受限 ReAct 和固定 Graph；消息队列、缓存和其他 adapter 按索引可靠性需要逐步加入。

## 11. 非功能要求

- **安全**：密钥加密存储；传输使用 HTTPS；敏感操作二次确认；权限默认拒绝。
- **可追溯**：原始数据、版本、Agent 处理和人工修改均可回溯。
- **一致性**：资产发布后的检索索引最终一致；索引失败可重试和人工补偿；查询始终以主数据权限和发布状态为准。
- **可扩展**：新数据模型、新 Agent 平台、新检索组件和新输入源不应要求重写核心权限系统或统一查询 API。
- **可用性**：列表、搜索、详情和权限判断具备稳定分页与限流策略。
- **可解释**：Agent 产出的关键字段尽量附带依据、置信度和处理说明。

## 12. 核心验收标准

1. 系统提供通用文档 / 笔记和 FAQ 模型，企业管理员可以配置经典镜头等专业模型；普通内容用户无需设计数据表。
2. 用户可以使用 Markdown 笔记文档发表内容，也可以使用专业模型生成的 CMS 动态表单提交结构化资产。
3. 一条输入数据可以同时查看原始内容、Agent 处理结果、人工修改和当前发布版本。
4. `editor` 成员能看到授权资源模型，未授权主体看不到；搜索、详情、下载、导出和 API 结果均一致。前台问答先判断是否有 `agent.use`，Eino Tool 结果以绑定 Agent 用户的 AgentAccessPolicy 为准，并完整审计发起成员与 Agent 用户。
5. 公开资源在未登录状态可访问，受限资源不会因直接访问 URL、搜索或引用而泄露。
6. 资产严格按 `internal → published → archived` 流转；发布由管理员/编辑或具备白名单 `publish` 动作的 Agent 显式执行，不包含审核任务或退回状态。
7. Agent 用户的 API Key 和 AgentAccessPolicy 可创建、轮换、收紧和吊销；权限变化后下一次调用立即生效。
8. 资产归档或数据模型权限收紧后，前台和统一查询 API 不再返回；检索索引产生更新 / 删除任务。
9. 文档、笔记和 FAQ 的原始内容、版本和附件留存在本系统，检索投影不可替代主数据。
10. Eino 内置 Tool 可以通过统一查询 API 同时查询结构化资产和文档类资产，查询身份为绑定的 Agent 用户，返回结果包含该 Agent 用户权限内的引用来源。
11. Agent 整理失败不会覆盖原始数据，任务可重试并能定位失败原因。
12. 本系统不建设社群及其互动内容；外部社群系统后续通过单独定义的开放 API 契约接入，本系统不维护社群实体或社群侧审核状态。
13. 普通成员只有得到 `agent.use` 权限后才可在前台调用某个 Agent 应用；问答工具查询严格使用绑定 Agent 用户的实时数据权限，成员的使用权限不改变或缩小该 Agent 的数据范围。
14. 定时任务可以实现“读取已录入文档 → 外部 Agent 整理 → 创建可检索资产”和“读取授权资产 → 外部 Agent 处理 → 通过开放 API 回写资产结果”；每个运行均可审计、重试且不会因重复调用造成重复写入。

## 13. 建议指标

- 有效资源表数量、活跃资源表数量。
- 每周新增原始输入数、转化为已发布资产的比例。
- Agent 整理成功率、发布采纳率和处理时长。
- 已发布资产的复用次数、搜索命中率、问答引用率。
- 检索索引新鲜度、索引成功率、查询成功率、查询延迟和权限过滤命中率。
- 外部 Agent 调用量、调用成功率、引用有效率和限流次数。
- 权限误配事件、敏感数据访问告警和审计覆盖率。

## 14. 当前理解与待确认问题

### 14.1 对当前构想的理解

你的构想可以概括为：

> 以“资产中台”为中心，系统提供通用文档 / 笔记模型，企业管理员可以配置经典镜头等专业模型；普通用户既可以像使用记事本一样发表 Markdown 文档，也可以通过 CMS 动态表单录入结构化内容。内置 Eino Agent 以 Agent 用户身份对内容进行整理、补全、关联或问答，形成高质量数据资产。文档、笔记、FAQ 和结构化资产统一留存在本系统，并通过本系统的全文、语义、混合和结构化查询能力被前台、Agent 应用及受控外部业务系统使用。

这个理解与现有截图的“资产中台”方向一致；`js.md` 已按本版方案明确为“本系统留存与检索，外部 Agent 通过统一开放 API 调用”。

### 14.2 需要后续确认的关键决策

本轮已确定的产品方向：

1. Agent 统一为外部智能服务，在系统中是技术身份；它使用 API Key 和独立 AgentAccessPolicy，不继承成员角色。
2. 用户和 Agent 先保存 `internal` 版本，再由管理员/编辑或具备白名单 `publish` 动作的 Agent 显式发布。
3. 第一版最小权限粒度为资源表 / 数据模型，记录、字段和附件继承模型权限。
4. 每个 Agent 只通过统一开放 API 获取其用户权限与数据模型策略允许的数据；前台用户使用 Agent 应用问答时，用户权限只用于校验 `agent.use`，不参与也不缩小 Agent 工具的数据权限范围。
5. 社群等外部内容业务不纳入本系统建设，后续由外部系统独立建设，并通过单独定义的开放 API 契约接入。
6. 首版 Agent 使用内置 Eino；Eino 使用统一查询 API，编辑器优先使用 Markdown。Agent 创建后显示 ModelEndpoint、运行模式和应用接入信息，并可作为前台可用的 Agent 应用或后台自动化服务。
7. 定时任务使用已登记的输入 / 输出 API 与短期任务凭证，实现 Agent 的“读取 → 处理 → 写回”闭环，不允许绕过权限直接写数据库。

后续仍需确认的实现细节：

1. 经典镜头库第一版的字段模板、枚举词典和质量检查规则。
2. 统一查询 API 的具体接口字段、权限上下文和 Eino Tool 调用方式。
3. 通用文档的附件类型、大小限制和 Markdown 扩展能力。

## 15. 与现有技术文档的衔接

现有 `js.md` 已提供后端实现方向：资产表、Outbox 事件、检索索引和开放 API。本产品第一版以 Go + PostgreSQL + River/Outbox 为主，内置 Eino 负责 RAG、ReAct 和固定 Graph，不把 Redis/NATS 作为当前必选的任务队列或消息中间件。Agent 专用授权表统一为“Agent 用户 + AgentAccessPolicy + Agent 应用 + 定时任务”，企业数据始终由本系统留存与检索。

界面设计以现有截图中的“资产中台”为主线：资产中台是中心，后台采用通用 Markdown 笔记文档、数据模型动态表单和版本发布体验，前台连接资源展示和 Agent 问答；外部社群由独立系统建设并通过开放 API 接入。产品实现时应以本文的权限和数据生命周期为上层约束；技术文档中的 `visibility` 落到资源模型级的公开、登录、工作区和内部处理策略，统一查询 API 则按调用用户（包括 Agent 用户）的实时权限返回结果。
