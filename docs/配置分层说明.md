# 配置分层说明

项目配置分为四层：容器基础设施、API/Worker 启动配置、首次初始化配置和后台业务配置。

## 1. Compose 基础设施

`docker compose up --build -d` 会读取 `.env`。数据库密码和加密根没有默认值，第一次启动前必须填写；其他部署参数可以使用默认值。

| 配置 | 是否需要填写 | 说明 |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | 必须 | PostgreSQL 密码；`.env.example` 中为空，必须填写。 |
| `POSTGRES_DB` | 可选 | 默认 `agentchunzhi`。 |
| `POSTGRES_USER` | 可选 | 默认 `agentchunzhi`。 |
| `API_HOST_PORT` | 可选 | 宿主机 API 端口，默认 `8080`。 |
| `GO_BASE_IMAGE`、`PGROONGA_BASE_IMAGE`、`CLAMAV_IMAGE` | 可选 | 只有使用内部镜像仓库或离线构建时才需要修改。 |
| `PGVECTOR_VERSION`、`PGVECTOR_REPO`、`ALPINE_MIRROR`、`GO_PROXY` | 可选 | 数据库镜像和 Go 依赖下载源。 |

Compose 会自动为 API/Worker 生成容器内 `DATABASE_URL`，不需要在 `.env` 中填写它。

## 2. API/Worker 启动配置

### 必须有效

| 配置 | API | Worker | 说明 |
| --- | --- | --- | --- |
| `DATABASE_URL` | 是 | 是 | 必须能连接 PostgreSQL；Compose 会自动生成。 |
| `SEARCH_CURSOR_SECRET` | 是 | 是 | 查询游标签名密钥；Compose 要求显式填写。 |
| `AGENT_MODEL_SECRET_ENCRYPTION_KEY` | 是 | 是 | Base64 编码的 32 字节密钥，用于加密 ModelEndpoint 凭证。 |
| `AGENT_CHECKPOINT_ENCRYPTION_KEY` | 否 | 是 | Base64 编码的另一组 32 字节密钥，用于持久化 Agent checkpoint。 |
| `OSS_REGION` | 否 | 条件 | 只有启用 OSS 附件存储时填写；填写时必须与 `OSS_BUCKET` 成对出现。 |
| `OSS_BUCKET` | 否 | 条件 | 只有启用 OSS 附件存储时填写真实私有 Bucket。 |
| `MIGRATION_PATH` | 是 | 是 | 默认 `db/migrations`，运行目录必须存在 SQL 迁移。 |

Compose 不再为数据库密码和加密密钥提供默认值，启动前必须填写；OSS 不配置时允许系统启动，但附件相关操作不可用。

### 有默认值、通常不必填写

`HTTP_ADDR`、`OSS_ENDPOINT`、`OSS_PREFIX`、`AGENT_MODEL_DEFAULT_TIMEOUT_SECONDS`、`AGENT_MODEL_MAX_CACHE_ENTRIES`、`AGENT_MODEL_MAX_CONCURRENT_REQUESTS` 都有代码默认值。Compose 要求显式填写 `SEARCH_CURSOR_SECRET`，避免生产环境误用代码开发默认值。

`AGENT_MODEL_ALLOWED_HOSTS` 不是启动硬依赖，但创建 ModelEndpoint 时会校验 Base URL。为空时不会允许任何模型主机；生产应填写实际模型域名，例如 `api.openai.com,api.deepseek.com`。

### 运行功能的可选配置

| 配置组 | 启动是否必需 | 未配置时行为 |
| --- | --- | --- |
| `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` | 条件 | API 可以启动；启用 OSS 后实际附件上传、读取或删除时需要有效的云凭证或实例角色。 |
| `ATTACHMENT_CLAMAV_ADDR` | 否 | Worker 可以启动；Compose 默认连接 `clamav:3310`。生产建议保留扫描。 |
| `ASR_*`、`TENCENTCLOUD_SECRET_ID/KEY` | 否 | 不使用音频转写；填写不完整时转写运行会失败，不影响启动。 |
| `EMBEDDING_*` | 否 | development/test 使用 hash embedding；生产未配置时语义检索不可用，结构化/全文检索仍可用。 |
| `RERANKER_*` | 否 | 不启用 reranker，不影响其他查询模式。 |

## 3. 首次初始化管理员

只在运行 `cmd/bootstrap` 时需要：

| 配置 | 是否必需 |
| --- | --- |
| `DATABASE_URL` | 是 |
| `ORG_NAME` | 是 |
| `ADMIN_LOGIN` | 是 |
| `ADMIN_PASSWORD` | 是 |
| `ADMIN_DISPLAY_NAME` | 否，默认使用 `ADMIN_LOGIN` |

这些变量不是 API/Worker 的长期运行依赖。可以临时放在 `.env` 中，也可以只在执行 bootstrap 的终端会话中设置。

## 4. 后台数据库配置

以下配置不写入 `.env`，由组织管理员通过后台管理 API 保存到 PostgreSQL：

### ModelEndpoint

每个接口配置：

- `provider_type`：`openai` 或 `openai_compatible`
- `base_url`：HTTPS 地址，且主机必须命中 `AGENT_MODEL_ALLOWED_HOSTS`
- `model_name`
- API Key（应用层加密保存）或 `secret_ref`（如 `env://MY_MODEL_KEY`）
- timeout、输入/输出 token 上限、temperature
- streaming、tool calling、structured output 能力

如果使用 `secret_ref`，对应的环境变量必须同时注入 API 和 Worker；否则模型运行时无法解析凭证。

### AgentApplication

每个 Agent 应用绑定一个 `ModelEndpoint`，再配置：

- `runtime_mode`：`rag`、`react` 或 `workflow`
- `workflow_key`（仅固定 Graph 需要）
- 应用名称、启停状态和能力范围

因此可以创建多个 Agent，分别绑定不同供应商、模型、API Key 和推理参数；系统启动不要求存在默认 Agent，但要使用 Agent，至少要有一个健康检查通过且已启用的 ModelEndpoint 和 AgentApplication。

### 其他后台配置

Agent 用户/API Key、AgentAccessPolicy、资源模型、字段、发布策略、检索/API 出口策略和定时任务也都保存在数据库，由后台管理，不放在 `.env`。

## 5. 推荐填写顺序

1. 复制 `.env.example` 为 `.env`，填写数据库密码、两组加密密钥和 `SEARCH_CURSOR_SECRET`；使用附件时再填写 OSS 配置。
2. 运行 `docker compose up --build -d`，确认 `/readyz` 正常。
3. 用 `ORG_NAME`、`ADMIN_LOGIN`、`ADMIN_PASSWORD` 执行一次 `cmd/bootstrap`。
4. 登录后台创建并测试 ModelEndpoint。
5. 创建 Agent 用户、AgentApplication 和 AgentAccessPolicy。
6. 按需配置 OSS 凭证、ASR、Embedding 和 Reranker。
