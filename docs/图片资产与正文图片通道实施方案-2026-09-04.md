# 图片资产与正文图片通道实施方案（2026-09-04）

## 0. 背景与范围

本方案收敛 2026-09-04 三轮讨论的结论：图片资产层（上传→ClamAV→OSS→草稿/版本关联→同源媒体路由→变体）已就绪；真缺口在内容层——图片进不了笔记正文、识图文本进不了检索索引。块模型业界对照（WP Gutenberg / 飞书）后的结论是：只借鉴护栏类机制（封闭校验、操作面收敛），不引入结构性膨胀。

本方案遵守产品理念约束：

- **Agent 唯一入口、小白用户**：图片进入笔记由 Agent 建议卡 + 用户确认完成，AI 永无直写笔记通道（铁律不动）。
- **数据库决定长相**：图片 URL 一律由数据库派生，冻结产物只存 attachment 引用，全链路不落裸 URL。
- **封闭参数空间**：块词表只加 `image` 一种类型；样式变体走 props；不做嵌套框架、不做全类型 schema 体系。
- **四铁律对图片同样生效**：对话里的图永不自动进笔记；图进笔记 = 用户显式动作；入库成文时图片必须 clean 并冻结进版本。
- **零兼容、零旧数据**：枚举直接加值、渲染器直接改，不做数据迁移；存量 heading 块一律按 level 3 解释（与现渲染行为一致）。

## 1. 总原则（六条，实施与评审依据）

1. **块存引用不存文件**：image 块的 `props` 存 `{attachment_id, alt, caption}`；`content` 一律空字符串。attachment_id 永不进 content（检索投影吃 content，uuid 会污染 chunk）。
2. **URL 永不落库**：冻结 markdown 存中性引用语法 `chunzhi-media://{attachment_id}`；公开渲染期重写为同源路径 `/sites/{slug}/media/{id}`。
3. **冻结时物化最终 alt**：最终 alt = 块级 `props.alt` 优先，回退附件 `default_alt_text`（P1 识图产出）。冻结产物携带最终 alt，重放与 traceability 天然稳定；渲染期只重写 URL、不再查 alt。
4. **AI 产出走既有门禁分档**：识图产出的描述/OCR 属资产元数据，直接进检索索引，不需审核；展示级 alt/caption 修改走建议卡 + 用户确认。
5. **封闭校验只做 image 一种**：为 image 块定义唯一的 props 校验（必填 uuid、字符串上限），不建全类型 schema 框架。
6. **不过度借鉴**：WP/飞书对照中已裁剪掉的项见 §5，不得以"业界都有"为由回潮。

## 2. P0 — 正文图片通道（一个迁移 + 四处改动）

### 2.1 迁移 `0024_image_block.sql`

- `content.blocks.block_type` CHECK 枚举追加 `'image'`（开发期免兼容，直接改约束）。
- `asset.attachments` 加列 `default_alt_text text NOT NULL DEFAULT ''`（P1 识图写入，P0 先占位，封面链路暂不迁移到该列）。
- 无任何数据迁移。

### 2.2 image 块契约与写入校验

改动点：`internal/content/note_view.go`（`editableNoteKind` 白名单）、`internal/content/service.go`（块写入校验）、`openapi.yaml`（kind 枚举）。

- props 封闭校验（全仓唯一一份块级 props schema）：
  - `attachment_id`：必填 uuid，必须存在、同 org、`media_type LIKE 'image/%'`、`status='clean'`、未过期；
  - `alt`：可空，≤500 字符；
  - `caption`：可空，≤500 字符；
  - 其余键拒绝。
- `content` 强制空字符串；`content_checksum` 照常计算。
- 校验失败整块拒绝（不是剥属性），Agent 与前端走同一校验。

### 2.3 冻结渲染器（`internal/noteblocks/noteblocks.go`）

- `RenderMarkdown` 增加 image 分支：输出 `![{最终alt}](chunzhi-media://{attachment_id} "{caption}")`；最终 alt 在冻结时解析（`props.alt` || `attachments.default_alt_text`），caption 为空则省略 title 位。
- **顺手修复 heading 级别**：新增 `props.level`（整数 1–6，可空默认 3）校验于写入层；渲染按级别输出对应 `#` 数。存量块无 level，按默认 3 解释，与现行为一致，零迁移。

### 2.4 公开渲染：URL 派生与外链封禁（`internal/delivery/`）

- 渲染管线在 markdown 解析后、bluemonday 清理前增加**重写 pass**：
  - `chunzhi-media://{id}` → `/sites/{slug}/media/{id}`；
  - 授权复核沿用 `internal/delivery/pages2.go:127` 的模式（必须是当前发布版本物化过的附件），不合法则整张图剥除（连 alt 一起不留）。
- 白名单收紧（`internal/delivery/markdown.go:49`）：`<img>` 的 `src` 仅允许重写产物（本站相对路径），任意外链图片一律剥除。`<a href>` 不受限（正文引外部链接合法）。
- 模板侧（`templates/pages/detail.html`）正文图默认 `variant=full`，卡片场景由模板控制，复用既有 srcset 消费方式。

### 2.5 commit 冻结物化（`internal/asset/draft_service.go`）

- 推广现有 cover 物化事务（draft_service.go:442 模式）：commit 时收集快照内全部 image 块引用的 attachment_id，逐个复核 clean + 未过期后写入 `asset.asset_version_attachments(role='body')`；`(version_id, attachment_id)` 主键天然去重多块同图。
- sealed 版本不可变由既有约束保证，无新增工作。

## 3. P1 — 识图入资产与检索闭环

### 3.1 识图管线（复用附件抽取状态机）

改动点：`internal/attachment/`（上传 clean 后的抽取钩子）、新增 vision extractor。

- 触发：附件 `status='clean'` 且 `media_type LIKE 'image/%'` → 进入既有 `extraction_status` 状态机，extractor 记 `vision-v1`。
- 产出与落位：
  - OCR（图内文字）+ 内容描述 → `asset.attachment_texts.text_content`（`extractor`/`extractor_version` 记录来源，支持换模型幂等重跑）；
  - 默认 alt（10–40 字）→ `asset.attachments.default_alt_text`。
- 模型走既有 ModelEndpoint 体系，不新增模型管理面。

### 3.2 检索投影接入（`internal/retrieval/`、`internal/query/`）

- 投影 canonicalizer 增补 attachment 数据源：已发布资产版本的 body/cover 附件的 `attachment_texts` 内容参与切段，`source_type='attachment'`，chunker 与嵌入复用现有管线。
- 效果：图片文本进入 hybrid 检索；命中后 citation 的 snippet 即图片描述文本，Agent 引用图片回答的链路随现有结构自动成立。**不新增检索工具**（`getAttachmentText` 按 ID 取，索引命中走既有 hybrid）。

### 3.3 Agent 插图建议卡（对话内建议，用户通道落地）

- Agent 在对话中输出结构化建议卡：附件预览（经既有 attachment API 取元数据与缩略变体）+ 建议插入的笔记与位置 + 建议 alt/caption。
- 用户确认后由前端调用**既有**笔记块创建 API 写入（§2.2 校验）。后端不新增任何直写笔记通道，铁律不动。
- 不做 `save_image_to_note` 类工具。

## 4. P2 — 资产治理加固（小活，可与 P1 并行）

1. **sha256 引用去重**：上传时按 `(org, sha256)` 查重，命中且源附件未删除则直接返回既有 `attachment_id`（引用关系由 draft/version 关联表承担）。零迁移。
2. **孤儿回收 job**：定期清理"无任何 draft/version 关联、无 image 块引用（`block_revisions.props->>'attachment_id'` 扫描）、`expires_at` 已过期或悬空超过阈值"的附件，删行 + 删 OSS 对象。
3. **`presigned-download` 正名**：路由与文档更名为 resolved-download（返回同源代理地址是隐私取舍，保留代理行为，不实现 OSS 直签）。

## 5. 明确不做（本期与可预见期，防止回潮）

| 项 | 不做的理由 |
| --- | --- |
| 动态块类型正式化（render_callback 式） | 相关文章区块已在渲染层工作，无需进块词表 |
| 嵌套框架 / allowedBlocks 父子矩阵 | 冻结快照是扁平序列，当前词表无嵌套需求；等真需求出现先升级快照结构再谈规则 |
| 全类型块 props schema 框架 | 只有 image 需要结构校验；框架是过度开发 |
| patterns / 样板体系 | 有价值但属独立特性，待块词表稳定后单独立项 |
| 对话发图（用户上传图给 Agent / vision 输入） | 改变 Agent 能力面与计费面，单独拍板，不混入本期 |
| 变体/缩略图落库落表 | OSS Process + CDN 已解决，不新增资产 |
| 多模态嵌入、图片 chunk 参与 VL 重排 | `qwen3-vl-rerank` 伏笔留待，文本先行收益最大 |
| 飞书式类型膨胀、WP 式块级样式自由、WP 式 HTML 内联序列化 | 违背封闭词表 / 数据库决定长相 / 规范化行存储三原则 |

## 6. 验收口径（建议新增 itd_p9 套件）

1. **正文图片全链路**：上传 jpg（clean）→ 笔记插入 image 块 → 冻结 markdown 含 `chunzhi-media://` 引用与最终 alt → commit 后 `asset_version_attachments` 出现 role='body' 行 → 公开页渲染同源 `<img>`（srcset 含 thumb/card/full 变体）→ og:image 正常。
2. **heading 级别**：level 1/2/3 块冻结输出 `#`/`##`/`###`；无 level 的存量块输出 `###`。
3. **外链封禁**：markdown 正文携带外部 `http(s)` 图片 → 公开页剥除；本站 media 引用正常出图。
4. **写入校验**：非 image 媒体、rejected/过期附件、非法 props 键 → 整块拒绝。
5. **版本纪律**：sealed 版本的图片引用不可变更；`ReplayMarkdown` 重放与冻结产物一致。
6. **识图闭环（P1）**：上传含文字的图片 → `extraction_status='succeeded'` 且 `attachment_texts` 含 OCR+描述、`default_alt_text` 非空 → 以图内关键词检索命中该资产 → citation snippet 含图片描述。
7. **治理（P2）**：同图二次上传返回同一 attachment_id；孤儿附件被回收且已物化引用不受影响。
