# 上线就绪度分析（Go-Live Gap Analysis）— 2026-09-12

> 范围：资产中台作为站点发布到公网（人类访客浏览公开站点 + 内部运营 + 外部 agent 接入），**以功能维度为主体**的差距分析；工程与合规层（域名/TLS/备案等）在文末单独列出。
> 依据：代码现状（forge @ e21a5e5、zck-web @ c90ca86+）、线上部署实测、产品文档（CMS 呈现层设计方案 §10-11 等）。

---

## 一、总体结论

产品骨架完整：公开站点交付（首页/列表/详情/标签/搜索/RSS/评论）、站点管理六 Tab、内容生产链（灵感→AI 整理→确认→发布）、Agent 生态（MCP 9 工具 + 会话内建模工具）都已实现并实机验证。

但对照产品文档与"真实站点"的完整体验，**功能维度还有三类缺口**：

- **访客侧**：详情页缺附件下载列表与上/下篇导航——影响内容完整性的呈现
- **运营侧**：AI 起草建模、发布差异对比、页面模块编辑器等"降操作成本"的能力缺失——站点能开，但运营效率是手工模式
- **Agent 侧**：能力已实现，缺的是**授权配置的管理界面**与端到端实测收尾

分级：🔴 功能缺失（上线前应补）、🟡 体验优化（上线后迭代）、⚪ 有意不做/待上游。

## 二、访客侧（公开站点读面）

### 🔴 2.1 详情页缺「附件下载列表」

产品文档 §11.2 要求详情页呈现：标题、时间、标签、正文、结构化字段（均已实现）、**附件**（缺失）、**上一篇/下一篇**（缺失）、相关推荐（已实现）。

- 现状：正文内嵌图片会经授权后同源渲染（`authorizedBodyImages`），但**正文之外的上传附件（PDF 等）没有任何下载入口**——访客拿不到资产附带的资料
- 改法：详情 VM 增加附件列表（已发布版本的 `asset_version_attachments`，role=body/cover 之外的文件附件），模板渲染下载列表；媒体路由已可校验同站点资产附件，扩展至非图片类型即可

### 🔴 2.2 详情页缺「上一篇 / 下一篇」导航

产品文档 §11.2 明确要求。现状：detail.html 只有相关推荐（Related，全文召回），没有同栏目内按发布顺序的上/下篇。改法：detail 查询时按同站点+同栏目取相邻已发布资产，模板加两条链接。工作量小，对连续阅读体验提升明显。

### 🟡 2.3 列表分页只有「下一页」

`pagination.html` 只渲染正向下一页（游标分页天然只支持正向）。产品文档 §11.2 即如此设计（游标分页），不算违约，但访客翻过头后只能用浏览器后退。可选项：页码窗口 + 游标快照，或接受现状。

### ✅ 已具备

首页 hero 介绍、首页栏目（latest/featured/模型专栏）、列表卡与分页、标签导航、站内搜索（real search 页）、RSS + sitemap.xml、访客评论（表单 + 审核 + 纯文本）、结构化字段表、正文目录 TOC、相关推荐、正文图片授权同源渲染、og/twitter 分享元数据、404/错误页。

### ⚪ 差异说明

- 自定义 CSS：文档初版禁止，2026-09-02 修订为 L2 受控白名单（已按修订实现，双端清洗）
- 预览必须真实 Delivery 渲染：已实现

## 三、运营侧（站长/内容运营）

### 🔴 3.1 「让 AI 起草数据表」缺产品入口（能力已实现）

内部 agent 已有 `create_resource_model` / `update_resource_model_draft` 工具（AgentDraftService：只建**草稿**模型，校验/发布强制由人完成），三重授权（应用 tool_policy 的 model.manage + HighWrite 许可、模型级策略行、工作区绑定）本轮也已在线上配好并验证授权链路。**但产品上没有任何入口让运营者用它**。

**建议落点**：设置中心「数据模型」Tab 顶部加"让 AI 起草数据表"——输入自然语言描述 → 后端走 agent 会话调用建稿工具 → 产出的草稿模型直接落入现有字段编辑器（人工校验、发布）。这符合"AI 起草、人做主"的产品红线，也是数据表冷启动最省力的方式。

### 🟡 3.2 「发布差异」缺对比视图

产品文档 §10.8 要求发布抽屉展示：与线上 Release 的配置差异、导航/主题变化、校验告警。现状：发布页只有配置摘要文本（模板/评论/CSS），**没有 diff 对比**。真实渲染预览已实现，可先补"当前草稿 vs 线上版本"的配置字段级 diff（数据都在 Release 快照里）。

### 🟡 3.3 概览缺「未发布修改」警示

产品文档 §10.3 要求概览展示"当前草稿是否有未发布修改"。现状概览只显示发布版本号；站点 revision 与线上 release revision 的差值其实就是该警示的数据源，加一行状态即可。

### 🟡 3.4 应用 tool_policy 的管理界面缺失

agent 能不能用建模/高风险写入工具，由 `agent_applications.tool_policy`（allow_high_write / allowed_capabilities）+ `agent_access_policies.actions` 决定——其中 **allow_high_write 是"SQL-only"（代码注释明说没有控制台通道）**。本次实测就是靠手工 SQL 授权的。管理台「智能体管理」应补：能力勾选、高风险写入开关、模型级策略绑定（部分已有）。

### 🟡 3.5 多站点列表在设置中心的呈现

公开站点已迁入设置中心，站点列表/详情/发布页功能完整；仅缺一个"公开访问地址"的显式链接（当前依赖 slug 拼接），配合 P1-D 域名路由时一并处理。

### ✅ 已具备

站点增删改/停用、内容绑定（校验已发布资产）、字段展示白名单、首页栏目 + 导航编辑、样式预设与 Token、自定义 CSS、版本发布与回滚、成员/角色管理、审计日志、FAQ、数据表记录管理。

## 五、工程与合规层（非功能，已在上版分析中详述，此处仅列结论）

1. **P0**：正式域名 + 可信 TLS；Host→站点路由（P1-D，nginx 草案与后端改动点已明确）；`APP_ENV=production` 生产加固（当前容器为 development 态）；ICP 备案（周期最长，建议最先启动）；每日备份 + 恢复演练（当前无定时备份）

## 七、结论

**访客可看的站点骨架已完整，缺的是三个具体功能点（附件列表、上下篇、AI 起草入口）和一批"降运营成本"的管理界面**——都在一次迭代内可完成。上线的主要阻塞在工程合规层（域名/证书/备案/生产加固），与功能开发可并行推进。
