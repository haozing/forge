## 1. 目标与范围

### 1.1 目标链路（完成标准原文的落地形态）

```
RawInput（asset.raw_inputs，人/API/webhook 写入，永不被 Agent 修改）
  -> Agent ProcessingJob（automation.runs：asset_prepare，可重试/可取消/有审计）
  -> 建议集（三类，全部 pending）：
       字段/摘要建议、标签建议（TagSuggestion）、资产关联建议
  -> 用户确认（accept 写入受控 AssetDraft / reject 丢弃，Agent 无法自确认）
  -> commit-draft => internal AssetVersion（origin=ai_assisted，未发布、未确认）
  -> 显式发布（成员触发；Agent 仅在持有 asset.publish + policy 直发/提审，且永不能 human_confirmed / approve）
```

「internal/draft 版本」在 v2 词汇下的精确含义：**未发布的工作版本**（资产 `publication_status='draft'` 下的 working version，或提交前的 AssetDraft）。v2 没有 `internal` 资产状态，不新增该值。

## 2. 核心设计决策

**D1 三段式：建议（pending）→ 确认（写 draft）→ 物化（commit 时落版本）。**
建议是记录不是关系（`suggestion_service.go` 头注释的原设计）。Agent 一切产出先落 pending 建议表；accept 是唯一把建议写进 AssetDraft 的动作，且必须由成员执行；`commit-draft` 物化版本并在同事务回填 `materialized_version_id`。原始输入、源版本、既有正式标签关系全程只读。

**D2 去掉「候选直接成为 working 版本」。**
现状 `preparation.go:224-226` 把候选设为 `current_working_version_id`——这是对工作态的覆盖，与「Agent 不覆盖原始输入」「查看并采用建议→提交」（§12.2）冲突。阶段 4 改为：Prepare 只产出建议集，`working` 指针与 AssetDraft 均不动；版本只在用户 commit 自己的 draft 时产生。副作用消除：不再需要 CancelPendingRequestsTx（不推进指针就不会顶替 pending 发布请求）。

**D3 三类建议同构、三张表、同一状态机。**
`pending → accepted / rejected`（terminal），`accepted → materialized`（commit 回填）。标签复用既有表；字段/摘要、关联各一张新表（见 §3）。不合并成单表：标签表已有独立列语义（resolved_tag_id/normalized key），强统一会丢类型约束。

**D4 处理结果（Processing Result）是独立可审计实体。**
每次 Prepare 对每个资产落一行：输入版本、建议汇总、字段差异（diff）、逐项与汇总置信度、引用（citations jsonb）。它回答 §8.1「必须附带处理任务、输入版本、引用依据、字段差异和置信度」；输出版本列在用户 commit 后回填（与建议物化同事务）。

**D5 标签词表约束提取面。**
提取 prompt 注入工作区 active 标签候选集（key+display_name），模型只能从候选集选或显式标 `is_new=true` 建议新 key；新 key 走 NormalizeKey，确认时可经 resolver（import 语义）创建。防止模型自由造词污染词表。

### 3.2 新表

```sql
-- 0005_assets.sql：字段/摘要建议（summary 用 kind='summary'、value 存文本）
CREATE TABLE asset.asset_field_suggestions (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    source_version_id uuid NOT NULL,
    run_id uuid NOT NULL REFERENCES automation.runs(id) ON DELETE CASCADE,
    kind text NOT NULL CHECK (kind IN ('field', 'summary')),
    field_key text NOT NULL DEFAULT '',                 -- kind=field 时必填
    value jsonb NOT NULL,                               -- 字段值或摘要文本
    previous_value jsonb,                               -- 字段差异：旧值（源版本当前值）
    confidence numeric(4,3) NOT NULL CHECK (confidence >= 0 AND confidence <= 1),
    citation jsonb NOT NULL DEFAULT '{}'::jsonb,
    status text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','accepted','rejected')),
    reviewed_by uuid REFERENCES identity.users(id),
    reviewed_at timestamptz,
    accepted_into_draft_id uuid,
    materialized_version_id uuid,
    created_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (source_version_id, run_id, kind, field_key)
);

-- 0005_assets.sql：资产关联建议
CREATE TABLE asset.asset_relation_suggestions (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    source_version_id uuid NOT NULL,
    run_id uuid NOT NULL REFERENCES automation.runs(id) ON DELETE CASCADE,
    target_asset_id uuid NOT NULL,                      -- 确认时物化到 target 当前 working 版本
    relation_type text NOT NULL CHECK (relation_type IN
        ('related_to','references','derived_from','cites','continues_from')),
    confidence numeric(4,3) NOT NULL CHECK (confidence >= 0 AND confidence <= 1),
    citation jsonb NOT NULL DEFAULT '{}'::jsonb,        -- 引用依据：chunk/片段/query 命中
    status text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','accepted','rejected')),
    reviewed_by uuid REFERENCES identity.users(id),
    reviewed_at timestamptz,
    accepted_into_draft_id uuid,
    materialized_version_id uuid,
    materialized_relation_id uuid,                      -- commit 后回填 asset_relations.id
    created_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (source_version_id, run_id, target_asset_id, relation_type)
);

-- 0008_agent_runtime.sql：处理结果（§8.1 五要素的载体）
CREATE TABLE integration.agent_processing_results (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    run_id uuid NOT NULL REFERENCES automation.runs(id) ON DELETE CASCADE,
    asset_id uuid NOT NULL,
    input_version_id uuid NOT NULL,
    output_version_id uuid,                             -- 用户 commit 后回填
    agent_user_id uuid NOT NULL,
    agent_application_id uuid NOT NULL,
    rule_version text NOT NULL DEFAULT '',              -- workflow definition checksum/code_version
    suggestion_summary jsonb NOT NULL DEFAULT '{}'::jsonb, -- {field:n,summary:n,tag:n,relation:n} 按 status
    field_diff jsonb NOT NULL DEFAULT '[]'::jsonb,      -- 字段差异视图：[{key,old,new,confidence}]
    overall_confidence numeric(4,3),
    citations jsonb NOT NULL DEFAULT '[]'::jsonb,       -- 全部引用（去重）：[{kind,ref,snippet}]
    input_tokens integer NOT NULL DEFAULT 0,
    output_tokens integer NOT NULL DEFAULT 0,
    created_at timestamptz NOT NULL DEFAULT now(),
    completed_at timestamptz,
    UNIQUE (run_id, asset_id)
);
```

索引：三张建议表 `(organization_id, source_version_id, status)`；results `(organization_id, asset_id, created_at DESC)`。

### 3.3 状态机

```
建议：    pending --accept(member)--> accepted --commit--> (materialized_version_id 回填)
          pending --reject(member)--> rejected（终态）
处理结果：created(run 启动) --suggestions落库--> completed --用户commit--> output_version_id 回填
run：     复用 automation.runs 既有 queued/running/…/attempt/cancel
```

## 4. 服务层改造（全部给出落点）

### 4.1 workflows 提取面扩展

`internal/workflows/registry.go`：

```go
type Input struct { // 增列
    TagCandidates []TagCandidate // 工作区 active 标签（key+display_name），受约束词表
    ExistingSummary string

    FieldConfidence  map[string]float64
```

`asset_candidate.go`：response schema 顶层加 `summary`（string）、`tags`（array of {key, display_name, is_new, confidence}，enum 约束为候选集 key ∪ is_new=true）、`relations`（array of {target_asset_id, relation_type(enum 五值), confidence}）；prompt 增「标签只能从候选集选择，新标签必须置 is_new；关系只能指向提供的可关联资产清单」。**可关联资产清单**来自统一查询（ForAgent scope 的 workspace published 资产 top-N，或本轮 RAG 检索命中）——防幻觉目标 id：模型只能从清单内选，服务端二次校验。

### 4.2 preparation.go 改造（保留权限双检/sealed 校验/防注入）

`loadSource`（:119）增读：源版本摘要、源版本标签集（`asset_version_tags ⋈ tags`，带出给 prompt 做 preserve 语义）、工作区 active 标签候选集、可关联资产清单（查 `query` 统一服务的 ForAgent 语义，`asset.read` 模型集内 published 资产，limit 50）。

`persistCandidate`（:176-245）**整体替换**为 `persistSuggestions`（单事务）：

1. `LoadLifecycleTx` 锁资产行（不推进任何指针）；
2. 写 `integration.agent_processing_results`（input 版本、rule_version=workflow checksum、token 用量）；
3. 逐条写三类建议（tag 建议走 `tag.SuggestionService.CreatePending` 的 Tx 变体，带 run_id/citation/is_new）；唯一约束兜底 run 重试幂等；
4. `field_diff` 由 (源值, 建议值) 计算；`suggestion_summary` 汇总；
5. 审计 `asset.version.prepare_suggested`；事件 `agent.processing_completed`（outbox）；
6. **不** `CreateVersionTx`、**不**动 working 指针、**不** CancelPendingRequests、**不**改 AssetDraft。

### 4.3 确认服务（新 `internal/asset/suggestion_review.go`）

- `List(ctx, principal, workspaceID, assetID, status)`：三类建议联合视图（UNION ALL，按 kind 排序）+ 处理结果摘要；
- `Accept(ctx, principal, suggestionKind, suggestionID, {tag_id?, override_value?})`：单事务——建议 pending→accepted（`FOR UPDATE`）+ 写 AssetDraft：
  - field/summary：draft.title/summary/fields 合并（等价一次 AutosaveDraft，revision 恰 +1；复用 `draft_service` 的更新语句，遵守 schema 校验 `ValidateFields`）；
  - tag：`tag.SuggestionService.AcceptTx`（已实现，写 `asset_draft_tags` source='ai'）；
  - relation：draft 记录？——关系是版本级，draft 无关系暂存区 → **新增 `asset.asset_draft_relations`**（对齐 draft_tags 形态：draft_id、target_asset_id、relation_type、source、confidence、citation、added_by），accept 写入此处；
- `Reject(...)`：状态翻转（tag 用既有 `Reject`，另两类同款）；
- `AcceptBatch`：同一事务内循环（draft revision 仍只 +1——合并为一次 autosave 语义）。

### 4.4 commit 物化扩展（`internal/asset/draft_service.go` commitDraftTx）

在 `CreateVersionTx` 之后同事务：

1. `tag.SuggestionService.MarkSuggestionsMaterialized(draftID, versionID)`（已实现）；
2. field/summary 建议：`UPDATE ... SET materialized_version_id` WHERE accepted_into_draft_id=draftID；
3. 关系物化：draft_relations → `asset_relations`（target 取该 target 资产**当前 working 版本**，source='ai'，confidence/citation/suggestion_id 带入；封存守卫只约束写入时点——写的是新 version 的出边，合法）→ 回填 `materialized_relation_id/materialized_version_id`；
4. processing results 回填 `output_version_id`（accepted_into_draft 关联链）。

### 4.5 发布记录六要素（§8.3）

成员/Agent 发布与 review approve 的审计 metadata 中，当资产版本 `created_by` 为 agent（`identity.users.user_type='agent'`）时追加：`agent_user_id、agent_application_id（经 run 关联）、rule_version、input_version_id（parent_version_id）、output_version_id、processing_result_id`。落点：`RecordAssetAuditTx` 调用处（member Publish / asset.Service Publish / review decide）扩一个 `agentProvenanceTx` 查询 helper。Agent 不能 `human_confirmed`（confirm 端点 `v2Principal` 仅 member——保持）与不能 approve（review decide 校验 principal.UserType==member——**补这一行校验，当前 decide 只查角色不查主体类型**）。

### 4.6 automation 统一 API 读写

`processor.go`：`assetPreparationVersions`（直接 SQL）改为经 `agenttask`/`query` 既有服务面（成员语义的 ForAgent scope 查询资产与版本）；`asset_publish` 等动作分支逐步迁到 v2 服务调用（本阶段只迁 prepare 分支，其余记账到台账）。run 输出快照 `output_snapshot` 增 `suggestion_ids`、`processing_result_ids`。

## 8. 失败、重试与审计语义

- Agent 失败零污染：建议与结果是旁路记录，raw_inputs/源版本/working 指针/draft 全程不动（D2 后天然成立）；
- run 重试幂等：三张建议表 `(source_version_id, run_id, …)` 唯一 + results `(run_id, asset_id)` 唯一，重跑 upsert；
- run 可取消/有 attempt_count（既有）；每步审计；
- **真库验证纪律（吸取 77a86ac 教训）**：本阶段所有新 SQL 必须在合入前经真库冒烟（prepare→建议→accept→commit→发布全链 + run 重试重放），列入退出门槛。
