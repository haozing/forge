## 1. 目标与范围

**一句话目标**：一个知识库一张对外的脸（1:1 建站、零配置上线），Agent 与人在同一套权限体系里协作（Agent 止于起草与确认，人负责发布）。

### 范围内

| 域 | 内容 |
|----|------|
| 站点基础 | 1:1 约束、自动收录、标题拼音 slug + 发布时原子 301、内容清单 |
| 设计中心 | 页面模块目录 + 布局三层、字段展示名（label）、字段白名单下沉、自定义页、导航自动枚举 |
| SEO | 分类树公开化（`/c/`）、`chunzhi-asset://` 引用内链、权重金字塔、更新记录可信度块 |
| 权限 | 权限矩阵数据化、Agent 入成员表、`human_only` 动作、`site.manage` 拆分、能力清单统一 |
| AI 改站 | 设计会话（沙盒 + 截图观察 + 人类旁观）、MCP 同源工具 |
| 多语言 | 资产 locale + 翻译组、子路径路由 + hreflang + 回退 |

### 范围外（明确不做）

- 拖拽自由画布、任意 HTML / 自定义 CSS 注入（设计会话的 `custom_css` 白名单是既有能力，不扩展）。
- 字段级翻译、自动机翻、cookie/GeoIP 语言跳转。
- 独立 `/history` 索引页、旧版本内容查看、自动 diff 展示。
- 自定义角色 UI（数据化之后属纯 UI 工作，P4 视需求）。
- 兼容层与旧数据迁移代码（`site_content_bindings` 直接退役，现网测试数据一次性清理）。

## 3. 依赖与关键路径

```
独立可先做（零依赖，净收益）
  ├─ 修 2 个现存缺陷（审批邮件 NULL、附件不校验 user_type）      [A1]
  └─ 权限矩阵数据化（词表合并 + human_only + 判权公式）          [A2]

权限地基 ──────────────► 决定"谁能进设计 Tab""Agent 能干什么"
  A2 → A5(site.manage 拆分) ──► C2(设计 Tab) ／ D(AI 设计会话)
  A3(Agent 成员行) → A4(判权公式) → A10(min 权限) ──► D

站点地基（与权限并行）
  B1(1:1) → B2(三表+退役绑定表) → B3(SQL 改写) → B4(收录) → B5(slug/301) → B6(清单 Tab)
                                        │
                                        ▼
  C1(pages_config v2 + 模块目录) ──► C2/C3/C4/C5/C6/C7 ──► D(设计会话，还依赖 C1 + 截图池)

多语言（独立，可并行）
  E1(资产 locale/翻译组) → E2(路由/SEO) → E3(录入 UI)
```

**关键路径**：`A2 → A3/A4 → B2 → B3 → B5 → C1 → D`。其中 **B2/B3 是最重的一段**（数据模型重建 + 交付层全量改写），**C1 是设计中心与 AI 改站的共同前置**。

### 已定决策（原"未决项"与"审计遗留"，2026-09-12 定）

| # | 议题 | 决定 |
|---|------|------|
| K1 | Agent 成员是否计席位 | **不计席位，改为配额**：每工作区 Agent 成员上限默认 10（组织可调）。理由：Agent 是人授予的工具，计席位会让"5 个 Agent 的工作区付 5 倍"，且 Agent 数量本无界 |
| K2 | 外部 key 的 Agent 身份 | **集成级身份，key 可轮换**：一个"外部集成"= 一个 agent user（成员行挂其上），一个集成可持多个 key；轮换/吊销 key 不影响成员行与已授权限。签发时可选"绑定现有集成"或"新建集成"。审计按集成归属、按 key 记明细（`api_keys.id` 已可区分） |
| K3 | Agent 成员行是否随 key 过期移除 | **不自动移除**：key 过期仅凭证失效（访问自然中断），成员行保留并显示"无有效凭证"徽标 + 提供"清理无凭证 Agent 成员"手动动作。理由：自动移除会让轮换 key 丢角色 |
| K4 | 自定义页数量 | **上限 20 个/站点**（含内置 `about`，分类页不计入）。理由：薄页面是 SEO 负资产，且防滥用 |
| K5 | `ranked` 排序字段范围 | **维持限定已公开标量字段**，不放宽（防侧信道泄露未公开字段信息） |
| K6 | 分类页与集合页的收录优先级 | **分类页为主**（canonical 指向自身、可索引）；**当某模型存在公开分类挂载时，其集合页自动 `noindex, follow`**（同批内容不留两个可索引入口）；站点可在设计里手动强制某集合页索引。无公开分类挂载的模型，集合页正常索引 |
| K7 | locale 保留字表 | 保留字 = **固定路由段**（`posts` `sections` `c` `p` `tags` `search` `archive` `about` `media` `static` `rss.xml` `sitemap.xml` `robots.txt`）+ **全部 ISO 639-1 两字母语言码**（对未来开启的语言同样安全）。自定义页/分类 slug 与 `model_key` 不得取保留字，保存时 422 |
| K8 | 面包屑层级归属 | **分类是面包屑的中间层**：`首页 → 分类各级 → 当前页`；**集合页不进面包屑**（它是类型索引不是层级），消除"两条父子链"。无分类挂载时 `首页 → 当前页`；集合页/标签页/归档页各自面包屑为 `首页 → 该页` |
| K9 | `public_view` 下沉后的差异面板 | 差异面板**移除字段白名单项**（已随模型版本走）；新增只读信息行"引用的模型版本"（记录 release 时各模型版本号）；字段白名单变更走模型发布流程，UI 提示"需重发布内容才生效" |
| K10 | 默认首页与分类块的交付顺序 | C1 先交付默认首页（hero/latest/各模型聚合块）；**分类导航块在 C5（分类公开化）落地后作为"新建站默认项"追加**——已建站不回填（不擅自改动用户已发布页面） |
| K11 | 内容创建时的 locale 默认值 | 人工新建文档/FAQ 与 AI 起草（react runs / MCP）= **工作区默认语言**（新增工作区设置，默认 `zh`）；数据表记录 = **NULL**（语言无关，全语言可见）；"添加翻译" = 显式目标语言（必填）；表记录派生文档 = 继承记录的 locale |

**暂无其他阻塞性未决。** 观察项（无需现在决策，出现再议）：Agent 配额的默认数值是否随组织套餐差异化；多语言 UI 文案的本地化。

## 9. 坑位总表（施工时对照，均经代码核实）

1. **`asset_versions` 无 `published_at`/无"曾发布"标记** → 版本轨迹必须新建 `asset_publications`；`change_note` 属发布动作不属版本内容（该表有不可变触发器）。
2. **`DROP site_content_bindings` 会被 `site.path_redirects` 的 FK 阻塞** → 先重建 redirects。
3. **`PathRedirect` 在 `internal/site/public.go`（不在 delivery），行由 binding.display_path 写入** → 301 是重建不是复用。
4. **`/sites/{slug}/` 是站点级 404 兜底**（测试钉为契约）→ 新子路由必须显式注册。
5. **集合页实为 `/sections/{sectionSlug}`**，`model_key` 只是查询参数 → 新方案按 model 驱动属语义变更。
6. **`dateModified` 早已输出**（`service.go:681-686`）→ D16 只缺轨迹块。
7. **`site.manage` 是 admin-only** → 必须拆 `site.design`/`site.lifecycle`。
8. **字段属性实为 key/type/options/default/unique/properties/items/searchable；`required` 后端从不校验**；label 要落 `field_schema.fields` + `list_schema.columns`；**卡片模板不渲染字段名**（是新增非替换）。
9. **`PublicPostContent.fields` 在 openapi 中错写为 object**（实际数组）→ C3 顺修。
10. **`public_view` 下沉是待实施**（`resource_model_versions` 是四个独立 jsonb 列）；生效时机随内容重新发布。
11. **release 快照不含栏目/绑定**（content 永不 pin）→ 文档表述已改。
12. **`template` 不是纯死字段**（拼进首页 meta description，`service.go:375`）→ 删除要连带清理。
13. **Agent 动作判定有四套词表 + 三条绕过判权的路径** → "删两表即单一来源"不成立。
14. **`asset.archive` 漏在硬编码表外** → Agent 归档永远 403（同类事故第二例）。
15. **决策 D（min 权限）零实现**，工具一律用 Agent 全量身份。
16. **决策 E 是同表两列**（`agent_applications.capabilities` 与 `tool_policy`）。
17. **附件 `requireWorkspaceMember` 不校验 `user_type`** → Agent editor 拿到附件全权（P0 修）。
18. **审批邮件 Scan NULL email 致事务回滚**（P0 修）。
19. **`identity.users` 未强制 Agent 的 email/password 为 NULL**；`granted_by` FK 允许指向另一个 Agent（需显式校验）。
20. **迁移必须走 migrate 服务记账**；`draft_revision` 一律发数字（既有铁律）。
