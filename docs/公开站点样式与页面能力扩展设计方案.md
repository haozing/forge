# 公开站点样式与页面能力扩展设计方案（二期）

> 状态：目标设计（待评审）
> 版本：2026-09-02，基于 main `d65b79e`
> 范围：样式布局能力从 L1 到终态的六项扩展——布局目录（瀑布流/时间轴/轮播）、L2 受控 CSS、组织级自定义预设、首图与卡片比例（含公共媒体路由）、页面类型（关于页/归档页）、评论区
> 产品前提（本版确立）：**用户是零开发知识的小白，Agent 是其唯一操作入口**——用户只会用自然语言说"想要什么"，其余（参数补丁、CSS、预览、发布确认）全部由 Agent 与系统完成。方案中任何"靠用户手工完成"的通道一律不成立；控制台按钮只是等价的便捷入口，不是必要条件
> 前提：开发期，不做数据迁移与双写兼容；存量行仅靠新列默认值自然兜底
> 承接：`docs/公开站点SSR投递与样式参数空间设计方案.md`（一期，已实施并验收，报告见 `docs/公开站点SSR投递实施验收报告.md`）。一期确立的契约不变：**数据库里的 style_config（+内容数据）完全决定站点长相，二进制只是解释器，发版不改变任何站点的样子**

## 1. 目标与非目标

### 1.1 目标

1. 六项能力全部落成"改数据库即生效"的用户面能力（管理台/Agent/API），开发方零参与；
2. 每项能力落进封闭参数空间或固定目录，Agent 治理链（候选→预览→人工发布→可回退）自动覆盖；
3. 安全边界不后退：无任意模板、无任意代码、L2 有白名单清理器。

### 1.2 非目标

- 不做模板在线编辑、不做任意页面路由的运行时创建（新页面类型 = 固定目录 + 代码，一期红线不变）；
- 不做评论的嵌套楼层/富文本/表情（v1 平铺纯文本，理由见 §8）；
- 不做主题包（L3）——运营期再议。

## 2. 总览

```text
用户免代码操作面（全部落库）
├─ 布局参数     list_style += masonry|timeline；home_style += carousel     （§3）
├─ 受控 CSS     public_sites.custom_css（白名单清理，Agent 为主通道）           （§4）
├─ 自定义预设   site.style_presets（组织级，style_config.preset 可指向）     （§5）
├─ 首图         附件角色 role='cover' + 卡片比例参数生效 + 公共媒体路由      （§6）
├─ 页面类型     /about/（绑定 content_type='about'）、/archive/（按月归档）  （§7）
└─ 评论区       site.site_comments（成员评论 + 默认先审后显 + 站点开关）     （§8）
```

共同机制（全部复用一期，无需新造）：Release 快照与回退、预览真实渲染、
缓存失效链（事件→delivery.cache_invalidations→api 轮询）、Tier 分档、
CSP/安全头、路由表测试与 openapi 契约门。

## 3. 布局目录扩展：masonry / timeline / carousel

### 3.1 参数与校验

- `layout.list_style` 枚举扩展：`list | grid | masonry | timeline`（internal/site/style.go styleListStyles）；
- `layout.home_style` 枚举扩展：`hero | plain | grid | carousel`；
- 预设默认值不变；写入与渲染双侧校验照旧（style.go 的枚举表是唯一事实源）；
- Agent 提示词同步（style_suggest.go 的指令枚举列表加新值，工具层自动获得）。

### 3.2 渲染（纯 CSS 为主）

| 形态 | 实现 | 依据/最佳实践 |
| --- | --- | --- |
| masonry | `.cards` 容器 `columns: 3`（窄屏 1/2 列媒体查询）+ `.card { break-inside: avoid }` | CSS multi-column 瀑布流是业界通用做法；已知取舍：列内自上而下排序，非严格按时间——在文档注明 |
| timeline | `.cards` 纵向时间轴：容器左缘竖线（`border-left`），`.card::before` 圆点锚定，日期提升到卡片顶部 | 纯伪元素重排现有卡片 DOM，零新组件 |
| carousel | featured 区渲染为横向 `scroll-snap` 轨道：`.cards-featured { display:flex; overflow-x:auto; scroll-snap-type:x mandatory }`，卡片 `scroll-snap-align:center`；同源静态 JS（`/static/delivery-carousel.js`，CSP `script-src 'self'` 已允许）只做左右按钮与圆点指示，**无自动播放**（自动播放伤 LCP 与可访问性）；`prefers-reduced-motion` 时禁用平滑滚动 | MDN scroll-snap 模式；键盘可达（tabindex/aria-label） |

### 3.3 模板与 VM

- home/list 模板按 body 布局类（`list--masonry` 等）分流，模板结构不分支（CSS 驱动），只有 carousel 需要模板输出轨道包装与按钮（single partial `partials/carousel.html`）；
- 无新 ViewModel 字段。

## 4. L2 受控 CSS（custom_css）

### 4.1 定位

L1 之上给一层**受限的自由表达**：对**现有组件**做白名单内的 CSS 覆写，覆盖 L1 参数
表达不了的视觉细节（悬浮动效、局部间距微调、特殊强调）。仍走 候选 → 预览 → 人工
发布 → 可回退。

**作者是 Agent**（产品前提：用户是小白）。L1 参数与 L2 CSS 的分工在提示词里固化为
层级：**能用参数表达的绝不用 CSS**（参数可预测、可 diff、可回退到语义单位；CSS 只做
参数覆盖不到的长尾）。管理台粘贴框保留为等价便捷入口，不是必要条件。

### 4.1.1 信任模型（与 L1 同构）

```text
L1：模型产出参数 → 校验器拒绝越界（代码强制） → 预览（人眼判断好看与否） → 发布/回退
L2：模型产出 CSS  → 清理器剥除白名单外（代码强制）→ 预览（人眼判断好看与否） → 发布/回退
```

安全从来不依赖模型自觉：钓鱼覆盖（position:fixed）、外传（url()）、注入（@import）
在进库前被清理器剥除，模型"写不出"危险的东西；视觉失败的兜底是预览闸门 + Release
可回退——小白用户判断"好不好看"恰在其能力圈内，这正是预览存在的意义。

### 4.2 数据模型

```sql
ALTER TABLE site.public_sites
    ADD COLUMN custom_css text NOT NULL DEFAULT '';
```

- Release 快照 config 增加 `custom_css` 字段（site_releases.config jsonb 内，发布/回退随快照走）；
- 限额：64KB 上限（写入口校验）。

### 4.3 清理器（安全核心）

实现：**gorilla/css 词法分析器**逐 declaration 走白名单（该库已在依赖树内——bluemonday 的传递依赖，零新增）。

```text
允许：颜色/背景（无 url()）、字体/文本、间距/边框/圆角/阴影、
     display/flex/grid/gap、width/height/max-*/aspect-ratio、
     opacity/transform/transition、overflow/object-fit/letter-spacing/line-height、z-index(≤10)
选择器：类/元素/后代/子代组合 + :hover/:focus-visible/:focus-within；
        单条规则选择器长度上限 256 字符
@规则：仅 @media，条件白名单 = prefers-color-scheme / prefers-reduced-motion / min/max-width
禁止：url() 一切形式（外传/追踪）、@import/@charset/@keyframes、
     position:fixed|absolute（点击劫持覆盖）、pointer-events:none、
     content 属性、behavior/expression、filter、position:sticky（布局劫持）
```

- 写入侧：PATCH 时清理，**存清理后的规范输出**（存的就是安全的）；
- 渲染侧：输出前再过一遍清理器（纵深防御，幂等）；
- 单测矩阵：每条禁止项一个用例（position:fixed 覆盖、url() 外传、@import 注入…）。

### 4.4 渲染与 CSP

- StyleEngine 输出顺序：`:root` 变量 → 基础样式 → **custom_css（最后，级联覆盖）**；
- CSP 不变（内联 `<style>`，`style-src 'unsafe-inline'` 已覆盖）。

### 4.5 API

- `PATCH /api/workspaces/{ws}/sites/{siteId}` 增加 `custom_css` 字段（整体替换语义，不做 patch 合并——CSS 无合并语义）；
- 预览 POST body 增加 `custom_css`（候选 CSS 与候选参数同理真实渲染）。

### 4.6 Agent 面（本节为产品核心通道）

`site_style_suggest` 工具升级为**参数 + CSS 双产物**：

- 结构化输出 schema：`candidates:[{rationale, style_patch?, custom_css?}]`——
  一个候选可以只带参数补丁、只带 CSS、或两者皆带（合并后的完整效果进预览）；
- 提示词层级：**参数优先**——"能映射到 style_config 参数的诉求必须用参数表达，
  只有参数无法表达的视觉细节才写 custom_css"；CSS 限 16KB/候选；
- 工具层先清理后返回：候选 custom_css 过清理器，被剥到与输入不符（危险/越界内容）
  的候选整体拒绝并**回传被剥的具体规则作为修正提示**（同一自愈回路，与 L1 越界参数同款）；
- 预览端点天然支持（§4.5），候选 CSS 与参数合并真实渲染，用户看到的就是将上线的。

`site_style_suggest` 的输入上下文同步扩展（§5.3/§6.4）：组织预设清单、站点已绑定
内容的首图情况，让模型能建议"套用你存的'品牌绿'预设"或"给这篇配张首图"。

## 5. 组织级自定义预设

### 5.1 数据模型

```sql
CREATE TABLE site.style_presets (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    name text NOT NULL CHECK (name ~ '^[^[:space:]]([^[:space:]]| ){0,30}[^[:space:]]$'),
    style_config jsonb NOT NULL,
    custom_css text NOT NULL DEFAULT '',
    created_by uuid NOT NULL REFERENCES identity.users(id),
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (organization_id, id),
    UNIQUE (organization_id, name)
);
```

### 5.2 引用方式（干净，不造第二套机制）

`style_config.preset` 的值域扩展为：**5 个内置名 ∪ 本组织 style_presets.id（uuid）**。
- 校验（写入侧）：preset 为 uuid 时必须存在于本组织（越组织引用 422）；
- 解析（渲染侧）：`ParseStyleConfig` 的调用方传入 `OrgPresetResolver`（org → map[uuid]jsonb），
  service 层一次查询装配；内置名优先，查不到的 uuid 容错回退 calm（渲染不因删预设而 500，
  管理面在引用中的预设上标记"已被引用"防误删，硬删仍允许——渲染侧兜底在前）；
- 套用预设 = 把预设的 style_config 与 custom_css 深拷贝进站点（**拷贝语义**，非引用语义：
  之后改预设不影响已套站点；"重新套用"是显式动作）。

### 5.3 API 与 Agent 可见性（组织面）

- `GET/POST /api/organization/style-presets`、`DELETE /api/organization/style-presets/{presetId}`；
- "另存为预设"两条等价入口：控制台"存为预设"按钮；**对 Agent 说"把现在这个样式存成预设，
  叫品牌绿"**——新增低风险写工具 `site_style_preset_save`（LowWrite，capability `site.style`，
  仅存数据束，不触碰任何站点）；
- 套用预设：Agent 在候选里给 `style_patch.preset = <uuid>`（suggest 工具上下文注入组织
  预设清单：id + 名称 + 关键 token 摘要），预览后发布；
- 权限：创建/列表对组织成员开放，删除需创建者或组织 admin；套用到站点仍走 site.manage。

## 6. 首图与卡片比例

### 6.1 模型决策：附件角色，不是模型字段

首图必须与内容**同版本不可变**（换图 = 新版本走发布链）。资产域已有
`asset.asset_version_attachments`（纯连接表）与 `asset.attachments`（object_key/media_type/
扫描/过期）。资源模型无 image 字段类型，且字段值是松散 JSON——不可变约束靠不住。
决策：**给版本附件加角色列**。

```sql
ALTER TABLE asset.asset_version_attachments
    ADD COLUMN role text NOT NULL DEFAULT 'body' CHECK (role IN ('body', 'cover'));
CREATE UNIQUE INDEX asset_version_one_cover
    ON asset.asset_version_attachments (asset_version_id) WHERE role = 'cover';
```

- 上传：既有版本附件注册端点增加 `role` 参数；`role='cover'` 校验 media_type 为 image/*、
  扫描 clean、byte_size ≤ 5MB；
- 卡片比例参数（`card_ratio`，一期已存库）就此获得作用对象。

### 6.2 公共媒体路由（新 HTML 面路由）

成员面下载是鉴权的，公开站点图片必须公开可达。新增：

```text
GET /sites/{slug}/media/{attachmentId}
```

- 授权链（全部服务端判定）：附件存在且未删未过期 → 所属版本 = 某绑定资产的
  current_published_version_id → 该资产绑定在本站点 → role ∈ {cover, body}（v1 只放行 cover，
  正文内嵌图二期再议）；
- 命中：经对象存储流式返回，`Cache-Control: public, max-age=31536000, immutable`
  （内容寻址：sha256 在表，object_key 稳定）+ `X-Content-Type-Options: nosniff` +
  Content-Type 锁 image/*（拒绝 text/html 狙击）；
- 不命中/越权：与站点 404 同款防探测语义；
- CSP `img-src 'self'` 不变（同源路由）。

### 6.3 渲染

- Reader 详情/列表行查询联出 cover 的 object_key 与 media_type；
- `CardVM.CoverURL`、`DetailVM.CoverURL`（`/sites/{slug}/media/{id}`）；
- CSS：`.card-cover { aspect-ratio: 按比例类 }`——一期就位的 `ratio--16-9` 等类接上真实规则；
  `card_ratio=text` 时卡片不渲染图；
- 首页 hero 可选用 cover 作背景（`home--hero` 有 cover 时叠加低透明度背景层）。

### 6.4 Agent 面

- 新图源仍来自控制台上传（小白能力圈内：传照片）；上传后**Agent 可提议设为首图**：
  suggest 工具上下文带站点内容的 clean 图片附件清单，候选可含 `cover: {asset_id, attachment_id}`；
  设首图产生版本变更（草稿→提交→确认），落"Agent 产候选、人发布"的既有治理线
  （复用资产建议/发布链，不新造通道）；
- 有 cover 后，`card_ratio` 进入常规建议维度（"卡片换成 16:9 宽幅"）。

## 7. 页面类型：关于页与归档页

### 7.1 关于页（数据先行，`about` 类型一期已预留）

- 路由：`GET /sites/{slug}/about/`；
- 数据：站点绑定中 `content_type='about'` 的**第一条**（按 sort_order），复用详情投影管线
  （§3.3 一期 re-check 全套）——模板 `pages/about.html`（无发布日期/TOC，其余同 detail）；
- 无 about 绑定 → 404；`card_ratio`/样式参数照常生效；
- sitemap 收录（有绑定时）。

### 7.2 归档页

- 路由：`GET /sites/{slug}/archive/`；
- 数据：既有 Posts 分页拉全（上限与 sitemap 同：10 页×50 条），按 published_at 年-月分组，
  纯服务端渲染成年份标题 + 月份条目（含计数与指向 `/posts/` 的月份过滤链接——
  列表页增加 `?month=YYYY-MM` 查询参数，走结构化查询的日期过滤）；
- 无文章时渲染空态（页面恒可用）；sitemap 仅在非空时收录；
- 模板 `pages/archive.html`。

### 7.3 导航

navigation_config 仍为导航唯一事实源（用户自己加"关于/归档"链接）；
站点默认 chrome 不自动注入，避免与用户配置打架。

## 8. 评论区（v1：平铺、成员、先审后显）

### 8.1 范围决策（业界对照）

- **成员评论**：匿名评论是垃圾内容磁铁；v1 要求登录（public_site 面的成员会话 cookie，
  一期 publicVisitorPrincipal 直接复用）。组织范围站点本就成员可见，语义自洽；
- **先审后显为默认**：`comments_mode: off | moderated | open`，默认 moderated——
  小站无专职审核，默认开放等于默认垃圾场（WordPress/Ghost 的教训一致）；
- **平铺不嵌套**：嵌套楼的树形渲染、折叠、排序是三倍复杂度，v1 砍掉；
- **纯文本**：正文只存文本，渲染靠 html/template 转义，无 markdown、无富文本——
  评论是 UGC 中信任最低的一层，解析面越小越好。

### 8.2 数据模型

```sql
CREATE TABLE site.site_comments (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    site_id uuid NOT NULL,
    asset_id uuid NOT NULL,
    display_path text NOT NULL,            -- 冗余快照，仅列表展示用
    author_user_id uuid NOT NULL REFERENCES identity.users(id),
    body text NOT NULL CHECK (char_length(body) BETWEEN 1 AND 2000),
    status text NOT NULL DEFAULT 'pending' CHECK (status IN ('visible', 'pending', 'rejected')),
    moderated_by uuid REFERENCES identity.users(id),
    moderated_at timestamptz,
    created_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (organization_id, id),
    FOREIGN KEY (organization_id, site_id) REFERENCES site.public_sites (organization_id, id),
    FOREIGN KEY (organization_id, asset_id) REFERENCES asset.assets (organization_id, id)
);
CREATE INDEX site_comments_site_asset_idx ON site.site_comments (site_id, asset_id, created_at DESC);
```

键选择：挂 (site_id, asset_id) 而非 display_path——换路径评论不丢。

### 8.3 API

公开面（成员会话 + Origin 门 + 公共面限流桶）：

```text
POST /api/public/sites/{slug}/posts/{displayPath...}/comments   body {body}
```

- 写入前校验：站点 comments_mode≠off、目标为已绑定已发布资产、成员在站点可见档内；
- 一律落 pending（open 模式直接 visible）；双发靠前端禁用 + 每成员每资产 1 条/10s
  服务端节流（auth_rate_limits 桶族加 comment 维度），公共面无幂等键契约（一期约定）维持不变；
- 每资产评论计数进 detail VM 与 ETag 指纹。

管理面（site.manage）：

```text
GET    /api/workspaces/{ws}/sites/{siteId}/comments?status=pending
PATCH  /api/workspaces/{ws}/sites/{siteId}/comments/{commentId}   {status: visible|rejected}
DELETE /api/workspaces/{ws}/sites/{siteId}/comments/{commentId}
```

站点设置：`PATCH sites` 增加 `comments_mode`（存 public_sites 新列 `comments_mode text
DEFAULT 'moderated'`，进 Release 快照）。

### 8.4 事件、缓存与渲染

- 新目录事件 `site.comment_created`（catalog + KnownEvents + delivery.cache 消费者注册）；
  管理侧审核状态变更走 `site.site_changed`（action=comment_moderated）即可，不新增事件；
- detail 模板尾部评论区（visible 列表 + 登录态表单；匿名访客见列表不见表单）；
  站点 comments_mode=off 时整块不渲染；
- 搜索页/列表不出现评论计数以外的东西（v1 连计数也可先不做，列为可选）。

## 10. 安全红线（新增汇总，叠加一期 §10）

1. L2 CSS 只存清理后的规范输出，渲染前二次清理；白名单外一律剥除（position:fixed、
   url()、@import、pointer-events 等为明确攻击面，单测钉死）；
2. L2 的安全由**清理器代码**保证而非模型自觉（与 L1 校验器同构）；Agent 候选在工具层
   先清理后返回，被剥候选带具体原因回传自愈；
3. 公共媒体路由 Content-Type 锁 image/* + nosniff + 防探测 404，object 存储凭据永不进响应；
4. cover 附件必须扫描 clean 才可设角色；
5. 评论纯文本转义渲染、先审后显默认、每成员限流、组织/站点双层归属校验；
6. 自定义预设跨组织引用在写入侧拒绝，渲染侧容错回退（不泄漏存在性）。

## 12. 实施顺序与验收

1. **N1 布局枚举**（半天级）：枚举 + CSS + carousel partial/JS + 单测；验收 = 三形态真实渲染 +
   Agent 说"换成瀑布流"即可切换；
2. **N2 L2 CSS**：custom_css 列 + 清理器 + 双侧校验 + 预览；验收 = 白名单生效矩阵（每条禁止项一个用例）
   + Agent E2E：用户说"卡片悬浮时轻轻上移"→ 候选含 CSS → 清理器放行 → 预览可见 → 发布生效、零部署；
   反向：Agent 产出 position:fixed/url() 的候选被剥并回传修正原因；
3. **N3 首图链**：role 列 + 上传参数 + 媒体路由 + CardVM.Cover + 比例 CSS；验收 = 传图→列表/详情出图、
   比例参数生效、越权取图 404、缓存 immutable；
4. **N4 自定义预设**：表 + 组织 API + preset 值域扩展 + 解析装配；验收 = 另存/套用/删除全链 +
   跨组织引用 422 + 删预设后渲染回退；
5. **N5 页面类型**：about/archive 路由 + 模板 + sitemap + month 过滤；验收 = 两种页面真实渲染与收录；
6. **N6 评论区**：表 + 双面 API + 事件 + 限流 + 模板；验收 = 成员评论→pending→审核 visible→
   详情页出现→缓存失效→组织范围站不泄漏。

## 13. 风险与开放问题

| 风险 | 对策 |
| --- | --- |
| masonry 列序非时间序 | 文档明示取舍；不满意可后续换 grid+JS 方案 |
| carousel JS 的可访问性 | 键盘/aria/reduced-motion 三项进验收 |
| L2 白名单过紧/过松 | 白名单表数据化（style.go 同源枚举法），可调不发版？——不行，清理器是代码：以单测矩阵驱动评审 |
| 模型产 CSS 与基础样式打架（特异性冲突、覆盖过头） | 提示词参数优先层级 + custom_css 级联最后 + 预览闸门 + Release 回退；N2 验收含"悬浮上移"这类典型微调的正反用例 |
| 媒体路由带宽（大图直出） | object 存储直连 + immutable 缓存；超 5MB 拒收；后续可加尺寸派生（v2） |
| 评论垃圾（即便成员制） | 默认 moderated + 限流 + 管理面批量审核；后续接通知 |
| preset 删除时的悬挂引用 | 渲染容错回退 calm + 管理面"被引用"标记 |
| 开放问题 | 评论邮件/通知（复用 notification 管线，二期）；正文内嵌图放行范围（v1 仅 cover）；归档页月份过滤的游标语义 |
