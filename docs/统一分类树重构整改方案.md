# 文件夹与 CMS 分类投影重构整改方案

> 状态：待实施
>
> 前提：不兼容旧接口，不迁移旧数据，允许重建数据库
>
> 目标：后台只维护文件夹；CMS 分类由文件夹树自动生成，不要求用户维护第二套分类

## 1. 最终决策

本次不建设统一的通用 Category 领域，也不让用户分别维护“文件夹树”和“CMS 分类树”。

最终边界如下：

| 概念 | 权威数据 | 职责 |
| --- | --- | --- |
| 正文容器 | `content.containers`、`content.container_versions` | 保存 Chat、Note、Document 等 Block 正文及其版本 |
| 内部文件夹 | `content.folders`、`content.folder_assets` | 工作区内组织资产；后台显示为“文件夹” |
| CMS 分类投影 | Site Revision 配置 + Release Manifest | 从选定文件夹子树自动生成；CMS 显示为“分类” |
| 文档父子关系 | `content.document_parents` | 可选的文档阅读/语义层级，不承担 CMS 分类职责 |

关系为：

```text
content.folders（唯一内容组织源）
        |
        +--> 文档库/内容管理：显示为“文件夹”
        |
        +--> Presentation Projector
                    |
                    +--> CMS 草稿预览：显示为“分类”
                    |
                    +--> CMS Release Manifest：冻结公开分类结构
```

本方案只统一数据来源，不强行统一领域生命周期：

- 文件夹由内容编辑者维护；
- CMS 决定公开哪些文件夹、显示什么名字；
- CMS 不保存第二份资产分类归属；
- CMS 不提供逐节点分类 CRUD；
- UI 文案不同，但不要求用户重复配置节点。

## 2. 用户操作原则

CMS 站点首次创建时只需要一次性选择公开根文件夹：

```text
选择一个或多个公开根文件夹
→ 系统自动包含其子文件夹
→ 自动生成 CMS 分类预览
→ 用户确认并发布
```

后续默认行为：

| 后台操作 | CMS 行为 | 是否需要重新发布站点 |
| --- | --- | --- |
| 新建子文件夹 | 自动出现在 CMS 草稿预览 | 是 |
| 文件夹改名 | 草稿预览显示新名称 | 是 |
| 移动文件夹 | 草稿预览显示新层级 | 是 |
| 归档文件夹 | 草稿预览显示移除差异 | 是 |
| 调整 CMS 公开根范围 | 更新分类投影 | 是 |
| 设置 CMS 别名/隐藏/排序覆盖 | 更新分类投影 | 是 |
| 已发布资产移动到另一个已公开文件夹 | CMS 分类列表立即变化 | 否 |
| 草稿或内部资产移动文件夹 | CMS 不展示该资产 | 否 |

用户不需要在 CMS 中重新创建、移动或删除对应分类。CMS 只提供以下可选覆盖：

- 隐藏某个文件夹；
- 设置公开显示别名；
- 覆盖公开排序。

## 3. 当前代码问题

### 3.1 `content.containers` 混合了正文和目录职责

`db/migrations/0006_content_core.sql` 中的 `content.containers` 原本是正文 Block 容器：

- 通过 `current_version_id` 指向 `content.container_versions`；
- 通过 `content.block_placements` 保存 Block 树；
- 被 Conversation、Note Binding、内容字段和派生关系引用；
- `kind` 表示 `chat/note/document/faq/content_field`。

`db/migrations/0018_yxt_containers.sql` 又向同一张表增加 `parent_id/sort_key` 和资产归属；`db/migrations/0023_yxt_final_contract.sql` 再增加 `kind='custom'`，导致正文容器同时充当文件夹。

正文容器和文件夹的生命周期、权限和约束不同，必须拆开。这是本次确定需要执行的重构，与 CMS 是否使用文件夹投影无关。

### 3.2 文件夹 API 可以误操作正文容器

`internal/container/service.go` 当前存在：

1. `Tree` 查询工作区全部启用 Container，没有限定 `kind='custom'`；
2. `Get/Patch/Delete/Move` 同样不限制类型；
3. `Create` 同时接受 `document/faq/chat/note/custom`；
4. 文件夹删除和正文 Container 使用相同归档逻辑；
5. 树构建没有独立最大深度防御。

因此 Chat、Note、Document 或内容字段 Container 都可能进入目录接口或被目录操作修改。

### 3.3 HTTP 层直接实现目录领域规则

`internal/httpapi/frontend_container_final.go` 直接执行父节点查询、环检测、移动、子节点和资产归属 SQL。规则分散在 HTTP Handler、`internal/container` 和 `internal/asset`，其他入口无法复用完整约束。

### 3.4 `container_id` 在会话接口中含义冲突

创建会话请求中的 `container_id` 表示目标目录，但响应中的 `container_id` 又表示新建的 Chat 正文容器。`internal/content/service.go` 还会把 Chat Container 和 Note Container 的 `parent_id` 指向目录 Container。

一个字段同时表达“存储容器”和“用户文件夹”，必须消除。

### 3.5 现有资产文件夹关系接近可用，但命名错误

`content.container_assets` 已经提供资产与多个目录节点的关联。它不需要升级为资产版本分类；文件夹移动是组织操作，不应强迫创建新的资产版本。

需要做的是：

- 将表改成 `content.folder_assets`；
- 将关联目标改成真正的 `content.folders`；
- 补齐同工作区外键、主文件夹和权限；
- 从 Asset Version 写入流程中移除目录关系更新。

### 3.6 文档父子关系与文件夹不是同一概念

`content.document_parents` 表达文档资产之间的单父级关系。它可以用于“章节包含子文档”等阅读关系，不等于文件夹，也不需要为了 CMS 分类投影被删除。

本次只明确：CMS 主分类树不读取 `document_parents`。后续如产品不再需要文档嵌套，再单独删除。

### 3.7 幂等、错误码和测试不足

`createContainer` 读取 `Idempotency-Key` 后只执行 `_ = key`，没有保存幂等结果。目录冲突统一返回 `container_not_empty_or_cycle`，客户端无法区分同名、循环、非空和深度超限。

当前也没有 `internal/container/*_test.go` 覆盖目录树核心行为。

## 4. 目标领域模型

### 4.1 术语

| 名称 | 含义 |
| --- | --- |
| Content Container | 内部 Block 正文容器，不参与目录组织 |
| Folder | 工作区内部内容组织节点 |
| Folder Membership | Asset 与 Folder 的资产级关系 |
| Category Projection | CMS 对 Folder 树的只读发布投影 |
| Category Override | CMS 对投影节点的隐藏、别名或排序配置 |
| Document Parent | 文档之间独立的阅读/语义关系 |

代码和 API 不使用抽象的 `Category` 表示后台文件夹。只有 Presentation/Delivery 的 ViewModel 使用 `category` 表示公开投影节点。

### 4.2 核心不变量

1. Folder 必须属于一个 Organization 和 Workspace。
2. 父子 Folder 必须属于同一 Organization 和 Workspace。
3. Folder 树不得成环，最大深度为 32。
4. 同一父节点下，启用 Folder 名称不区分大小写唯一。
5. Folder 没有 `kind`、正文版本和 `visibility`。
6. 一个 Asset 可属于 0 到 100 个 Folder。
7. 一个 Asset 最多有一个 Primary Folder。
8. Primary Folder 必须同时存在于 Folder Membership 中。
9. Folder Membership 是资产级组织元数据，不属于 Asset Version。
10. CMS Category Projection 只允许引用 Site 所属 Workspace 的 Folder。
11. CMS Release 冻结 Folder 的名称、层级、公开别名和排序。
12. Delivery 实时读取 Folder Membership，但只输出当前可见的已发布资产。
13. Folder 只软归档；归档前必须没有启用子文件夹和资产关系。
14. Document Parent 不参与 Folder 环检测或 CMS Category Projection。

## 5. 数据库整改

### 5.1 `content.containers` 回归正文存储

保留：

- `id/organization_id/workspace_id`；
- `kind/title/status/visibility`；
- `current_version_id`；
- 创建人和时间字段。

移除：

- `parent_id`；
- `sort_key`；
- `kind='custom'`。

歧义外键改名：

| 当前字段 | 目标字段 |
| --- | --- |
| `content.conversations.container_id` | `content_container_id` |
| `content.note_bindings.note_container_id` | `content_container_id` |
| `content.asset_version_content_fields.container_id` | `content_container_id` |
| `content.derivation_sources.source_container_id` | `source_content_container_id` |
| `content.derivation_sources.source_container_version_id` | `source_content_container_version_id` |

外部 HTTP DTO 不再暴露 Content Container ID。

### 5.2 新建 `content.folders`

```sql
CREATE TABLE content.folders (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    parent_id uuid,
    name text NOT NULL CHECK (length(btrim(name)) BETWEEN 1 AND 200),
    sort_order bigint NOT NULL DEFAULT 0,
    status text NOT NULL DEFAULT 'active'
        CHECK (status IN ('active', 'archived')),
    created_by uuid NOT NULL REFERENCES identity.users(id),
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (organization_id, workspace_id, id),
    FOREIGN KEY (organization_id, workspace_id)
        REFERENCES content.workspaces (organization_id, id) ON DELETE CASCADE,
    FOREIGN KEY (organization_id, workspace_id, parent_id)
        REFERENCES content.folders (organization_id, workspace_id, id)
);

CREATE UNIQUE INDEX folders_active_sibling_name_uq
    ON content.folders (
        organization_id,
        workspace_id,
        parent_id,
        lower(btrim(name))
    ) NULLS NOT DISTINCT
    WHERE status = 'active';

CREATE INDEX folders_tree_idx
    ON content.folders (
        organization_id,
        workspace_id,
        parent_id,
        sort_order,
        id
    )
    WHERE status = 'active';
```

`sort_order` 由 Folder Service 在事务内维护，不再使用客户端字符串 `sort_key`。

### 5.3 新建 `content.folder_assets`

先收紧资产 Workspace 约束：

```sql
ALTER TABLE asset.assets
    ALTER COLUMN workspace_id SET NOT NULL,
    ADD CONSTRAINT assets_workspace_id_id_uq
        UNIQUE (organization_id, workspace_id, id);
```

Folder Membership：

```sql
CREATE TABLE content.folder_assets (
    organization_id uuid NOT NULL REFERENCES organization.organizations(id),
    workspace_id uuid NOT NULL,
    folder_id uuid NOT NULL,
    asset_id uuid NOT NULL,
    is_primary boolean NOT NULL DEFAULT false,
    created_by uuid NOT NULL REFERENCES identity.users(id),
    created_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (folder_id, asset_id),
    FOREIGN KEY (organization_id, workspace_id, folder_id)
        REFERENCES content.folders (organization_id, workspace_id, id),
    FOREIGN KEY (organization_id, workspace_id, asset_id)
        REFERENCES asset.assets (organization_id, workspace_id, id)
        ON DELETE CASCADE
);

CREATE UNIQUE INDEX folder_assets_primary_uq
    ON content.folder_assets (asset_id)
    WHERE is_primary;

CREATE INDEX folder_assets_lookup_idx
    ON content.folder_assets (
        organization_id,
        workspace_id,
        folder_id,
        asset_id
    );
```

Folder Membership 不引用 `asset_version_id`。创建新资产版本、Agent Prepare、模型迁移、Note Sync、Revert 等流程都不复制或修改文件夹关系。

### 5.4 保留并收紧 `content.document_parents`

保留现有单父级文档关系，但使用复合外键确保父子资产属于同一 Workspace：

```text
(organization_id, workspace_id, child_asset_id)
(organization_id, workspace_id, parent_asset_id)
```

Document Hierarchy Service 继续负责文档类型、环和权限校验。它与 Folder Service 分开，不被 CMS Category Projector 调用。

### 5.5 重写迁移历史

仓库迁移按文件名和 checksum 记录，见 `internal/store/store.go`。本次无旧数据，采用干净历史：

1. 修改 `0006_content_core.sql`，让 Content Container 去目录化并消除歧义字段；
2. 修改 `0017_yxt_resource_models.sql`，收紧 Asset Workspace 约束；
3. 将 `0018_yxt_containers.sql` 重命名为 `0018_yxt_folders.sql`；
4. 在 0018 中创建 `folders/folder_assets` 并保留收紧后的 `document_parents`；
5. 从 `0023_yxt_final_contract.sql` 删除 `custom` Container 类型；
6. 同步后续字段引用；
7. 删除开发数据库或 Docker 数据卷，从空库执行全部迁移。

不新增兼容迁移、旧表 View、双写或数据回填。

## 6. Go 领域层整改

### 6.1 用 `internal/folder` 替换 `internal/container`

```text
internal/folder/
  model.go
  repository.go
  service.go
  service_test.go
```

建议类型：

```go
type Folder struct {
    ID               string    `json:"id"`
    WorkspaceID      string    `json:"workspace_id"`
    ParentID         *string   `json:"parent_id,omitempty"`
    Name             string    `json:"name"`
    SortOrder        int64     `json:"sort_order"`
    Status           string    `json:"status"`
    DirectAssetCount int64     `json:"direct_asset_count"`
    Children         []Folder  `json:"children,omitempty"`
    UpdatedAt        time.Time `json:"updated_at"`
}

type MembershipInput struct {
    FolderIDs       []string `json:"folder_ids"`
    PrimaryFolderID *string  `json:"primary_folder_id"`
}
```

Folder Service 负责：

- `Tree/Get/Create/Rename/Move/Archive`；
- 同工作区、环和最大深度；
- 同级重名；
- 兄弟节点重排；
- 非空归档；
- `GetMembership/ReplaceMembership`；
- 幂等、并发、审计和 Outbox。

HTTP Handler 不允许直接查询或更新 Folder 表。

### 6.2 Folder Membership 与 Asset Version 分离

将 `internal/asset/member_relations.go` 拆成：

```text
internal/folder/membership.go
internal/asset/document_hierarchy.go
```

Folder Membership 的完整替换由 Folder Service 处理，不再在 `MemberService.Update` 创建资产版本时顺带删除和重建关系。

资产创建可以在同一事务中设置初始文件夹；后续移动使用独立 Folder Membership API。这样纯移动文件夹不会产生正文完全相同的新 Asset Version。

以下版本生成流程不再需要任何文件夹复制逻辑：

- Agent Prepare；
- 资源模型迁移；
- Note Sync；
- Revert；
- Duplicate 版本；
- 自动化生成新版本。

复制整个 Asset 时可以由产品操作明确选择是否复制 Folder Membership，不能把它和版本复制混在一起。

### 6.3 Conversation 与 Content Container

创建会话请求使用 Folder 字段：

```json
{
  "agent_application_id": "uuid",
  "folder_ids": ["uuid"],
  "primary_folder_id": "uuid",
  "title": "...",
  "source": "chat_interface",
  "visibility": "workspace"
}
```

内部仍创建 Chat Content Container、Note Content Container 和 Note Asset，但：

- Content Container 不再设置目录 `parent_id`；
- Folder Membership 写到 Note Asset；
- Conversation 对外响应保留 `note_asset_id`；
- 删除外部 `container_id/note_container_id`；
- 会话按文件夹筛选时关联 Note Asset 的 Folder Membership。

### 6.4 权限

删除 `container.manage`，增加：

```text
folder.read
folder.manage
```

建议权限：

| 角色 | folder.read | folder.manage |
| --- | --- | --- |
| owner/admin | 是 | 是 |
| editor | 是 | 是 |
| reviewer/member/viewer | 是 | 否 |

Presentation Projector 使用内部只读 Repository，并先校验 Site 与 Folder Workspace 一致。

## 7. HTTP API 整改

### 7.1 Folder API

```text
GET    /api/frontend/workspaces/{workspaceId}/folders/tree
POST   /api/frontend/workspaces/{workspaceId}/folders
GET    /api/frontend/folders/{folderId}
PATCH  /api/frontend/folders/{folderId}
POST   /api/frontend/folders/{folderId}/move
DELETE /api/frontend/folders/{folderId}
PUT    /api/frontend/assets/{assetId}/folders
```

创建：

```json
{
  "parent_id": null,
  "name": "团队规范",
  "position": 0
}
```

移动：

```json
{
  "parent_id": "uuid|null",
  "position": 2
}
```

替换资产文件夹：

```json
{
  "folder_ids": ["uuid-1", "uuid-2"],
  "primary_folder_id": "uuid-1"
}
```

使用 `PUT` 表达完整替换，不再保留容易产生竞态的 `add/remove/replace` 操作枚举。

### 7.2 资产查询

```http
GET /api/frontend/workspaces/{workspaceId}/assets?folder_id={folderId}
GET /api/frontend/workspaces/{workspaceId}/assets?folder_id={folderId}&include_descendants=true
```

`include_descendants` 默认 `false`。递归 Folder 查询在服务端完成，前端不得先读取整棵树后自行拼接 ID。

Asset 响应包含：

```json
{
  "folders": {
    "folder_ids": ["uuid"],
    "primary_folder_id": "uuid"
  }
}
```

Folder Membership 不放入 Asset Version DTO 或历史版本 DTO。

### 7.3 Document Parent API

现有接口暂时保留，但移动到独立 Document Hierarchy Service：

```text
POST   /api/frontend/assets/{assetId}/document-parent
DELETE /api/frontend/assets/{assetId}/document-parent
GET    /api/frontend/assets/{assetId}/document-children
```

接口文档必须明确它不是文件夹关系，也不是 CMS 分类配置。

### 7.4 删除旧 Container API

直接删除，不做兼容别名：

```text
/api/frontend/workspaces/{workspaceId}/containers/tree
/api/frontend/workspaces/{workspaceId}/containers
/api/frontend/containers/{containerId}
/api/frontend/containers/{containerId}/move
/api/frontend/containers/{containerId}/children
/api/frontend/containers/{containerId}/assets
/api/frontend/assets/{assetId}/containers
```

### 7.5 错误、幂等和并发

错误码：

```text
folder_not_found
folder_name_conflict
folder_cycle
folder_depth_exceeded
folder_not_empty
folder_access_denied
validation_failed
revision_conflict
```

写操作要求：

- POST/PATCH/MOVE/DELETE/PUT 都使用 `Idempotency-Key`；
- Rename/Move/Archive 使用 `If-Match`；
- Move 在同一事务内锁定节点、目标父节点和相关兄弟节点；
- 写成功记录 `folder.create/update/move/archive/membership.replace` 审计；
- Outbox 发送对应事件。

## 8. CMS 分类自动投影

### 8.1 Revision 只保存投影规则

Site Revision 增加：

```json
{
  "category_projection": {
    "enabled": true,
    "root_folder_ids": ["folder-uuid"],
    "include_descendants": true,
    "excluded_folder_ids": [],
    "label_overrides": {
      "folder-uuid": "使用指南"
    },
    "sort_overrides": {
      "folder-uuid": 10
    }
  }
}
```

这里没有 CMS Category 节点数组，也没有分类 CRUD：

- 根文件夹是唯一必选配置；
- 后代默认自动包含；
- 排除、别名、排序都是可选覆盖；
- 未覆盖时使用 Folder 的名称和顺序。

### 8.2 草稿预览自动生成

Presentation Projector 根据当前 Folder 树和 Revision 规则生成 CMS 草稿预览。Folder 结构事件只需：

1. 失效 Projection Preview 缓存；
2. 比较实时投影与当前 Release 的 `folder_projection_checksum`；
3. 在 CMS 概览显示“分类结构有待发布变化”；
4. 展示新增、改名、移动、归档的差异。

事件不会逐节点创建 CMS 配置，也不会要求用户执行“同步分类”。进入 CMS 时看到的草稿预览始终来自最新 Folder 树。

### 8.3 发布与并发

Preview 响应返回：

```json
{
  "projection_checksum": "sha256",
  "categories": []
}
```

发布请求携带最近预览的 `projection_checksum`。发布事务中重新读取 Folder 树：

- checksum 相同：继续编译和发布；
- checksum 不同：返回 `409 folder_projection_changed`，前端刷新预览；
- 不提供额外的手工同步步骤。

Compiler 的确定性输入是：

```text
Site Revision Config + Folder Projection Snapshot
```

Release Manifest 保存完整公开结构：

```json
{
  "folder_projection_checksum": "sha256",
  "categories": [
    {
      "id": "folder-uuid",
      "source_folder_id": "folder-uuid",
      "parent_id": null,
      "label": "使用指南",
      "sort_order": 10,
      "canonical_slug": "usage-guide"
    }
  ]
}
```

当前线上 Release 只读取 Manifest 中的分类结构，因此 Folder 改名、移动、新建或归档不会直接改变线上结构，可以正常预览和回退。

### 8.4 Folder Membership 实时生效

Release 不复制资产 ID 或 Folder Membership。Delivery 查询分类内容时：

```sql
JOIN content.folder_assets fa
  ON fa.asset_id = a.id
 AND fa.folder_id = $1::uuid
JOIN asset.asset_versions av
  ON av.id = a.current_published_version_id
```

同时必须校验：

- Folder ID 存在于当前 Release Manifest；
- Asset 属于 Site Workspace；
- Asset 当前存在发布版本且未归档/删除；
- Resource Model 启用 `frontend` outlet；
- Asset 匹配 Site `content_scope`；
- 请求主体满足资产可见性；
- 动态字段经过 Release 白名单。

因此：

- 移动已发布资产会立即改变 CMS 分类列表；
- 移动草稿或内部资产不会造成公开泄漏；
- Membership 事件只需失效相关分类列表缓存，不需要发布站点；
- 如果未来产品要求“资产移动也必须发布”，再单独引入 CMS 内容编排，不提前版本化 Folder Membership。

### 8.5 导航、路径和面包屑

CMS Navigation 仍是 Site Revision 配置，可以指向投影 Category，但不是 Folder 本身。

规则：

- Category 路由以 `source_folder_id` 作为稳定身份；
- Slug 只用于可读地址和 Canonical Redirect；
- Asset 详情 URL 继续以 Asset ID 为稳定身份；
- 多文件夹资产可以在多个 Category 列表出现；
- 详情页默认面包屑使用 Primary Folder；
- Primary Folder 未进入当前 Release 时，使用当前 Release 内排序最前的关联 Folder；
- 均不匹配时进入“其他内容”。

### 8.6 Document Parent 的 CMS 用法

CMS Category 树只来自 Folder Projection。`document_parents` 不再是知识库主目录来源。

如果知识库页面需要展示“子文档”，可以作为独立的 `document_children` 组件读取 Document Parent；该组件不能改变 Category 路由、公开范围或面包屑主路径。

## 12. 验收标准

1. `content.containers` 只承担正文 Block 容器职责。
2. 后台只有一棵人工维护的组织树：`content.folders`。
3. CMS 不存在第二套人工维护的分类树或分类 CRUD。
4. CMS 分类由选定 Folder 子树自动投影。
5. 用户首次只选择公开根 Folder，后续节点自动同步到草稿预览。
6. CMS 只允许隐藏、别名、排序三类可选覆盖。
7. Folder 结构变化需要发布 Release，线上结构可回退。
8. Folder Membership 变化不创建 Asset Version，对已发布资产立即生效。
9. Delivery 始终执行发布状态、Outlet、内容范围和 ACL 校验。
10. `content.folder_assets` 是唯一 Folder Membership 权威数据。
11. `document_parents` 保留为独立阅读/语义关系，不参与 CMS 分类。
12. HTTP Handler 不包含 Folder 领域 SQL。
13. 不保留旧 Container 组织接口、别名、双写或数据迁移代码。
14. 空库迁移、全量测试、API 与 worker 启动验证全部通过。
