# P1-D 自定义域名真实路由 — nginx 配置草案（未激活）

状态：**草案**。写于 2026-09-10，对应开发文档 §7.2/§14 P1-D。
激活前置条件（需运维/域名所有权）：

1. 域名 DNS A/AAAA 记录已指向本机（如 `docs.example.com → 101.35.49.253`）。
2. 该域名的 TLS 证书已就位（建议 certbot：`sudo certbot --nginx -d docs.example.com`，
   证书落在 `/etc/letsencrypt/live/<domain>/`）。
3. 站点在管理台已登记该域名（`site.public_sites.domain`，即站点详情「自定义域名」字段）。

## 原理

 forge API 已支持按 Host 头路由站点（`/sites/{slug}` 与 `Host: <domain>` 等价入口）。
nginx 只需要为每个自定义域名加一个 server 块，把整站流量转给 forge（SSR）与
Next.js（管理台不存在于自定义域名下，公开域名全部交给 forge + 静态）。

## 每个域名一个文件：/etc/nginx/sites-available/custom-site-<domain>.conf

    # 模板：<domain> 换成实际域名；<slug> 换成站点 slug（仅注释用）
    server {
        listen 80;
        server_name docs.example.com;

        # certbot 续期用
        location ^~ /.well-known/acme-challenge/ { root /var/www/certbot; }

        location / {
            return 301 https://$host$request_uri;
        }
    }

    server {
        listen 443 ssl;
        server_name docs.example.com;

        ssl_certificate     /etc/letsencrypt/live/docs.example.com/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/docs.example.com/privkey.pem;
        ssl_protocols TLSv1.2 TLSv1.3;
        client_max_body_size 32m;

        # 公开站点全部由 forge 直出（SSR 页面 / 公开 JSON / 媒体 / 静态脚本）。
        location / {
            proxy_pass http://127.0.0.1:8080;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Forwarded-Proto https;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $remote_addr;
            proxy_read_timeout 300s;
            proxy_buffering off;
        }
    }

## 启用

    sudo ln -s /etc/nginx/sites-available/custom-site-<domain>.conf /etc/nginx/sites-enabled/
    sudo nginx -t && sudo systemctl reload nginx

## 已知缺口（激活前要确认）

- **forge 侧按域名解析站点的入口尚未实现**（2026-09-10 核实）：`PublicReader.loadSite`
  只按 slug 查（`internal/site/public.go:132`，`WHERE slug = $1`），`Host: docs.example.com`
  请求根路径 `/` 不会命中站点。需要：delivery 路由增加「Host → domain → 站点」解析，
  自定义域名下 `/`、`/posts/…`、`/tags/…` 等**无 slug 前缀**路径直接映射到该站点
  （仅对非管理台 Host 生效，避免抢走主站 `/`）。改动集中在
  `internal/httpapi/delivery_routes.go` + `internal/site/public.go`（loadSite 加 domain 分支）。
- 多域名指向同一站点：当前 `domain` 是单值，一对一。
- 证书自动化（certbot 续期 timer）由运维确认。

结论：nginx 侧是纯配置工作；forge 需要先补「域名 → 站点」解析（小改动，未实施——
P1-D 整体仍按开发文档标记为部署层阻塞项）。
